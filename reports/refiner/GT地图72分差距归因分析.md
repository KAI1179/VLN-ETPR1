# GT 认知地图约 72% 与当前结果差距的归因分析

## 1. 要解释的现象

Try5 使用 GT 认知地图时 SR 约 72%；使用当前 LLM 地图和 Online Refiner 时，最佳已测 SR 为 64.76%，仍低约 7 个百分点。该差距不能直接解释为“地图 IoU 不够高”，因为离线 Refiner 已明显改善地图：val-unseen 综合语义 IoU 在 100×100 上由 5.08% 提升到 11.26%，50×50 上由 5.99% 提升到 15.67%。

## 2. 最强证据

1. **地图本身确实被修正，但导航没有同步提升。** Refiner 在所有测试分辨率和 seen/unseen split 上均提升整图 IoU；因此“Refiner 完全不起作用”不是主要解释。
2. **当前导航收益主要表现为更容易接近目标。** 15k 时 NE=3.983、OSR=70.64%，但 SR=64.76%；28k 时 SPL=55.27% 才达到最高。说明到达附近与最终成功停止、路径效率之间存在脱节。
3. **训练后期没有持续提升。** 13k–21k 的 SR 在 64%–64.8% 间波动，28k 的 SR 反而为 64.33%。这不像单纯“训练还不够久”，更像融合接口或决策分布存在系统性问题。

## 3. 最可能的故障位置

### 3.1 地图质量指标与决策所需信息不一致

整图 IoU 是所有格子和通道的平均，而 Try5 只在当前候选节点、ghost 节点和停止判断处使用地图。Refiner 提升的大量格子可能远离决策区域，或者只改善类别占用而没有改善“哪个候选节点值得走”。因此 IoU 提升不能推出 SR 提升。

### 3.2 粗分辨率导致有效信息被涂抹

视觉证据来自 30° 扇区和距离段，映射到 0.5m 网格后覆盖大片区域。离线下采样到 10×10 的 IoU 提升最大，反而说明细网格上的定位仍然粗糙。决策模块读取细粒度空间 token 时，可能把正确类别扩散到错误位置，改变候选排序。

### 3.3 更新后的地图改变了 Try5 的输入分布，但决策模块没有针对它适配

Try5 原本学习的是静态 LLM 地图 token 与拓扑节点的关系。Online Fusion 将部分 token 替换为 Refiner 输出，虽然数值上更接近 GT，却可能改变 token 的稀疏性、幅值和类别共现分布。现有 DAgger 只训练了导航策略，未明确约束融合后节点排序和停止行为，因此会出现“地图更好、动作更不稳”。

### 3.4 终点与路径效率是当前主要损失

新模型的 OSR 和 NE 比 Try5 同阶段更有利，但路径长度和 steps_taken 偏长；28k 的 SPL 最高而 SR 没有同步提高。这表明主要损失可能发生在：已接近目标后没有及时 stop、在正确路线附近继续探索、或 ghost/拓扑候选排序使轨迹绕行。GT 地图的 72% 上界同时改善了这些决策，而当前融合只改善了部分空间语义。

### 3.5 GT→LLM 的 6.6 分并不一定都能由在线视觉修正

GT 地图包含未观测区域信息；Online Fusion 按设计只更新已观测区域。若差距主要来自未见区域的 LLM 错误，当前方案无法触及；若 GT 含有视觉观测中不可恢复的语义，Refiner 也无法补齐。因此“已见区域修正”本身未必足以达到 72%。

## 4. 次要但需要排查的因素

- teacher-forcing 训练和 student rollout 的地图更新分布不同，可能造成门控和 Refiner 的使用偏差。
- 视觉证据是检测结果而非完美语义标签，漏检会把已覆盖区域的先验压低。
- Refiner 输出在拓扑节点融合时可能只作为附加特征，实际决策权重不足；也可能影响所有节点但没有节点级监督，导致有用信息被噪声稀释。
- 当前不同 checkpoint 的评测存在训练随机性，不能仅凭单个 iter 断言收益为负；但整体平台期已经说明问题不是偶然波动。

## 5. 结论

当前最合理的判断是：**主要瓶颈位于“地图 token → 拓扑候选/stop 决策”的接口，而不是 Refiner 的离线纠错能力。** 另外，GT 地图的 72% 是包含未观测区域真值的上界，不能假设只修正已见区域就必然达到该数值。

优先验证两个量：

1. 在相同轨迹上比较 P0、Refined、GT 对候选节点排序和 stop logit 的一致性；
2. 按首次偏航、接近目标后的额外步数、最终 stop 误差分解 SR 差距。

若 Refined 的节点排序已接近 GT 但 SR 仍低，问题在策略/停止头；若排序仍接近 P0，问题在融合接口，继续提高整图 IoU不会直接解决导航差距。
