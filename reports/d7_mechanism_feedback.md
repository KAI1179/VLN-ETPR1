# D7 方案审阅：认知地图是否、以及如何辅助训练

日期：2026-10-09。

本文件是**反馈，不是 D7 执行报告**。本轮仅阅读既有报告、相关代码与方法文献；没有执行 D7 的 checkpoint 扫描、参数计算、评测或训练，没有修改源码、配置或 Git。下面最新的基线/KD 数字来自用户任务书，未在本轮重新核验结果文件。

## 1. 总体判断

**值得研究“训练期地图辅助”，但当前证据还不足以认定增益来自 LLM 地图，更不足以认定机制是语言—视觉对齐。D7 的 T1/T3 值得保留，T2 的初始化基准必须修正，三部分的结论边界都需要收紧。**

应当分开回答三个问题：

| 层次 | 要回答的问题 | 当前证据能到哪里 |
|---|---|---|
| 部署 | 测试时能否去掉 LLM 生成的栅格与方向向量？ | CE 的配对评测支持 SR 变化较小；不是所有指标严格等价，也不是完全无元数据输入 |
| 贡献 | 正确地图内容在训练时是否带来了额外收益？ | 尚需同结构、同实际初始化的有图/零图训练对照，不能用历史无图基线替代 |
| 机制 | 收益是否来自地标与视觉节点匹配得更好？ | 参数变化与困难子集获益只是线索，需要功能性检验 |

我的建议不是放弃当前方向，而是将主张暂定为：**“模型在部署时不依赖生成地图字段；正在检验训练期空间先验的贡献及其实现方式。”** 不应提前把 H1 写成已证实机制。

## 2. 已有数字真正说明了什么

### 2.1 测试去图可行，不等于训练用图有效

D5 同批次、同四卡评测为：

| 口径 | CE own SR | CE deploy SR | deploy − own | 场景 bootstrap 95% CI |
|---|---:|---:|---:|---|
| 全部 1839 个 episode | 64.27 | 64.27 | 0.00 pp | [−0.97, +1.02] pp |
| 原缓存共有的 1833 个 | 64.48 | 64.27 | −0.22 pp | [−1.14, +0.78] pp |

全量持平包含一个补偿：deploy 在原先缺缓存、own 被计失败的六个 episode 中成功了四个。因此机制分析应同时给出**共有缓存集合**，不能只看 1839 个的总分。D5 全量 SPL 还由 54.17 降到 53.46；McNemar 的 SR 检验不能代替 SPL 检验。

准确结论是“没有检测到显著的 SR 差异”，不是“零成本完全等价”。若要宣称实际等价，应事先确定可接受差值，并看置信区间是否全部落入范围。

证据：[D5 配对结果](/home/xukai/code/ETP-R1-snapshot/ETP-R1/reports/d5_training_time_map.md:43)。

### 2.2 OSR 支持改善到达率，尚不能锁定路线选择机制

按本次任务书提供的数字计算：

| 结果类别 | 无地图基线 | KD deploy | 变化 |
|---|---:|---:|---:|
| 最终成功 SR | 63.13% | 66.50% | +3.37 pp |
| 曾到目标范围，但最终失败：OSR−SR | 5.39% | 5.66% | +0.27 pp |
| 从未到目标范围：1−OSR | 31.48% | 27.84% | −3.64 pp |
| 已到达者中的最终失败比例：(OSR−SR)/OSR | 约 7.87% | 约 7.84% | 近似不变 |

这确实使“改善到达目标的能力”比“主要改善停止判断”更有依据。但是：

- OSR 只是是否曾进入目标半径；更长的探索、不同的停止时机也可能提高 OSR，并不自动等于更准确地遵循指令。
- OSR−SR 包含到达后离开、超时等情况，不是纯粹的 STOP 分类错误。
- 两个模型“曾到达”的 episode 集合不同，条件比例接近也不能证明 STOP 能力完全不变。

因此还应结合 PL、步数、nDTW；若已有轨迹记录，再看首次到达目标的步数/路程，而不是仅凭两个成功率给路线机制定性。

代码依据：[OracleSuccess 的累计到达定义](/home/xukai/code/ETP-R1-snapshot/ETP-R1/habitat_extensions/measures.py:203)。

### 2.3 零输入不等于地图模块失效

当前 map encoder 在栅格置零后仍计算投影、卷积、归一化、元数据编码和 Transformer，101 个 token 的 mask 仍全部有效。零输入仍可能产生学习到的 token；整个通路也可能充当额外的上下文处理模块。

所以不能由“零图能跑好”直接推出“地图知识已搬进语言层”。即使有知识内化，也可能发生在 map encoder、融合层或动作头，而不只发生在跨模态编码器。

代码依据：[map encoder 前向与全有效 mask](/home/xukai/code/ETP-R1-snapshot/ETP-R1/vlnce_baselines/models/etp_prior_gt/map_encoder.py:327)。

## 3. 真正决定训练期贡献的对照

最重要的不是再增加一个解释性指标，而是明确以下四格。可复用满足条件的已有实验，不要求重复训练所有模型。

| 训练目标 | 训练时生成字段置零，保留同样起点元数据 | 训练时正确 LLM 地图 |
|---|---|---|
| CE | A：零图 CE | B：有图 CE |
| CE + 同一个 GT 教师 KD | C：零图 KD | D：有图 KD |

四组均保留 Try5 全部模块，部署输入完全相同。需要核对实际初始权重、代码版本、冻结设置、优化器、训练量、教师和采样规则，而不只是 pretrained_path 字符串相同。训练随机种子应成对一致；多 seed 用于估计训练波动。

- **B−A**：CE 条件下，DAgger 输入地图的总贡献。
- **D−C**：KD 条件下，DAgger 输入地图的额外贡献；这是区分 H1 与“收益全来自教师”的关键。
- **C−A、D−B**：教师在两种学生输入下的贡献。
- **(D−C)−(B−A)**：地图与教师是否产生额外的联合收益。

DAgger 会因策略不同而产生不同轨迹，这是训练处理的总效应的一部分，不必强行让四组实际 rollout 完全相同；但后续比较模型内部如何决策时，要用相同状态，避免把所见数据不同当成表征更好。

两个必要限定：

1. **历史 28000 与新零图模型不能天然组成严格 B/A。** 既有 D5 已提醒历史训练代码与 HEAD 不同；要核验差异，必要时使用已准备的同 HEAD 有图对照。[D5 对照说明](/home/xukai/code/ETP-R1-snapshot/ETP-R1/reports/d5_training_time_map.md:64)
2. 四组若都从地图预训练权重开始，只能识别 **DAgger 阶段**的地图贡献。不能因此排除或证明预训练阶段地图的贡献。

若 B−A 或 D−C 明确为正，而论文还要强调“正确的空间语义”，再加入一项**训练期错配地图**对照：打乱 episode 与预测地图/方向的配对，保留输入分布及自身起点元数据。正确图优于零图，可能来自一般正则化；正确图还优于错配图，才更支持语义配对本身有用。测试期 donor 不能代替这个训练期对照。

## 4. 对 D7 T0/T1 的修改意见

### 4.1 T0 不应预设“三个 run 具有共同的完整初值”

既有 R13 审计认定：历史 Try5 DAgger 没有把预训练 map encoder 加载进去，专用加载与 fusion 重映射在 2026-09-24 的 `ec5fde0` 才引入。该报告采用的历史代码 commit 为近似定位，且当时未完成历史 checkpoint 数值复核；此次应保留这个证据边界。

因此需要逐 run 区分：实际继承的导航张量、随机初始化的地图/融合参数、外部 RGB/depth 权重。KD 与零图 run 的加载行为不能从历史 Try5 外推。

证据：[R13 历史加载审计](/home/xukai/code/ETP-R1-snapshot/ETP-R1/reports/R13_try5_map_loading_audit.md:9)。

另应明确：本任务书新给出的基线 63.13 不是本轮重新查得的数据。后续 T0 应定位它的真实结果与训练来源，不再沿用旧 D5“未定位基线”的状态，也不能未经核查就把其预训练来源当成 460000。文件名中的 step 差也不能直接当作接续训练步数，必须看训练计数逻辑与日志。

### 4.2 T1 保留，但修正三条判读

| 观察 | 可以说 | 不能直接说 |
|---|---|---|
| 早期 own 优于 zero，后期接近 | 保存下来的训练阶段中，对生成字段的性能依赖下降 | 已证明地图知识内化；模型也可能放弃噪声地图 |
| 所有已测 ckpt 都接近 | 这些 checkpoint、这些 split 上，没有检测到净 SR 收益 | 从未读图；4000 之前、预训练阶段都未测，逐 episode 效果也可能互相抵消 |
| val_seen 有差、val_unseen 无差 | 输入作用随分布变化，与地图质量解释相容 | 已排除其他场景/指令分布差异，或完全证明策略无问题 |

尤其要注意：**val_seen 是较好的补充，但不是已确认的“高质量地图阳性对照”。** D4 的 region IoU 为 train_90 0.3339、val_seen 0.1515、val_unseen 0.0445；val_seen 28000 own/cross 为 75.19/74.55，p=0.359；18600+LLM 相对 GT cross 的优势也未显著。因此可以考虑在已核验地图质量较好的 train 子集做依赖诊断，但应明确它不证明未见场景泛化。

证据：[D4 地图质量](/home/xukai/code/ETP-R1-snapshot/ETP-R1/reports/d4_llm_map_generalization.md:27)、[D4 val_seen 配对结果](/home/xukai/code/ETP-R1-snapshot/ETP-R1/reports/d4_llm_map_generalization.md:103)。

T1 表格建议保留 own−zero、配对 CI，并补充“仅 own 成功/仅 zero 成功”数量。二者总 SR 相同，不代表输出行为相同。若要判断模型是否响应输入，可在相同决策状态上比较动作分布，但分布响应也不等于响应有益。

执行约束需要提前澄清：

- own/zero 同时改变栅格和生成方向，检验的是“生成地图字段整体”，不是栅格独立贡献。
- 同时报告全量与共有缓存集合：val_unseen 通常为 1839/1833，val_seen 为 778/768，具体以缓存核验为准。
- 缺少 val_seen deploy 缓存时，需明确允许写入新的派生缓存目录；否则与“新文件仅 scripts/eval_d7 和 reports”字面冲突。
- 无地图 ETP-R1 基线可能需要不同 trainer/policy/map-enabled 设置；不能为了满足“只改五类参数”而强行套用 LLM Try5 launcher。
- 自动跳过必须核验完整 episode 数、checkpoint/config 身份；不能只因目录或某个 JSON 存在就认为完成。端口 29670+ 之前 D4 已使用过，后续启动时仍应避免与活跃作业冲突。

评测规模：两种训练 × 五个 ckpt × 两种输入 × 两个 split = **40 次**；按每次 4–5 分钟，串行为 **2 小时 40 分—3 小时 20 分**，约 **10.7–13.3 GPU·小时**（四卡）。零图最终模型两个 split 再加两次；若基线也需补两个 split，再加两次，最多约 44 次、2 小时 56 分—3 小时 40 分。不含 CPU 准备，实际需按 ckpt 与可复用结果调整。

## 5. T2：保留为参数审计，不作为 H1 的验证

### 5.1 460000 不能作为每个模块的 θ₀

对历史上重新初始化的 map encoder/fusion，`θ_final − θ_460000` 不是训练更新量。正确的处理是：

| 参数情况 | 如何报告 |
|---|---|
| 确认继承且键映射/shape 一致 | 可计算相对真实初值的变化 |
| 随机初始化，真实 step-0 权重没有保存 | 标“初值不可恢复”，不伪装成预训练参数漂移 |
| 初值范数为零 | 相对变化无定义；报告绝对变化/RMS，不靠加极小数制造巨大比值 |
| checkpoint 缺键或 shape 不同 | 列出不可比较项及参数量覆盖率，不当成零变化 |
| RGB/depth 来自外部权重 | 对它们的实际初值核验；不能要求对不含这些参数的 460000 得到零变化 |

冻结验证还应区分 parameter 与 buffer；某些训练态统计 buffer 可变化，不能一概认定优化器更新了冻结权重。

### 5.2 参数移动在哪，不等于能力改善在哪

跨模态层变化较大，可能来自 CE/KD 梯度、优化器状态、训练时长、初始化差异，不一定是更好的语言—视觉对齐。反之，少量关键参数变化也可能显著影响行为。

建议 T2 输出“模块、可比参数数、真实初值来源、绝对/RMS 变化、相对变化”，作为排查冻结错误、加载差异和更新分布的诊断。各张量相对变化中位数与模块整体范数是不同统计口径，应同时注明。

最终 28000 与零图训练中间 ckpt 不宜直接比较更新幅度；优先匹配训练步数/更新量，中间结果只作暂存描述。若不存在共同真实初值，两两距离可以描述参数不同，却不能解释谁因地图学得更多。

表征相似性方法如 CKA 比原始参数距离更接近“表示是否变化”，但它仍不自动证明“对齐更好”或因果作用，不建议用另一个相似度指标替代关键对照。[Kornblith 等，ICML 2019](https://proceedings.mlr.press/v97/kornblith19a.html)

## 6. T3：很有价值的行为分析，但不是独立的 grounding 证据

建议执行其统计框架，同时作以下调整：

1. **不要只分析 KD 对基线。** 分别报告 CE deploy vs 基线、KD deploy vs CE deploy；未来再加同 KD 条件的有图训练 vs 零图训练。否则所有改善都可能归于教师，无法回答 LLM 地图做了什么。
2. **“多地标/多岔路收益大”只能称相关特征。** 它们与指令长度、路线长度、场景难度相关，教师也可能尤其擅长这些任务。至少给出长度/场景分层或控制后的比较，不要凭一层显著、另一层不显著就认定两层效应有差异。
3. **先固定特征定义。** 地标是类别去重数还是提及次数？环境类别是否排除？方向词短语怎样避免重复计数？岔路应基于原始 R2R 连通图路径中的不同节点，不能把密集连续轨迹的重复投影点当多个岔路。度 ≥3 只是岔路机会的近似，不等于实际难决策次数。
4. **“翻正/翻负”均值表是描述，不是原因。** 子集本身按结果定义，应配合全体 episode 分层、每层 n、配对差值和场景 bootstrap，而非只展示翻正组地标更多。
5. **失败分类保留，但改名。** 使用“成功 / 曾到目标范围但最终失败 / 从未到达”，不直接称第二类为 STOP 错误。再给基线→KD 的三类转移表，比只列总体比例更清楚。

上述分析能够定位“收益出现在哪类任务、哪类失败上”。它不能单独区分地标 grounding、语言理解、视觉辨别、一般规划能力或探索策略。

## 7. 要明确“如何辅助”，最值得补的一项功能性检验

**在相同决策状态上，比较有图训练与零图训练的模型：是否更准确地把指令中的地标对应到正确视觉节点，并据此选择动作。** 不需要新增导航网络，但将来需要离线前向计算及独立标签；不是当前 CPU 参数统计可以替代的工作。

### 7.1 相同状态，而不是各跑各的轨迹

固定一组具有可辨别地标与候选分岔的决策样本；两个模型都用部署零图输入，输入的指令、视觉观测、拓扑历史、候选节点和位姿相同。仅固定 agent 坐标不够，历史图不同也会改变决策。

主要比较同初始化、同 KD 条件的有图/零图训练模型；GT 教师与历史无图基线可以作为参照，不能替代这对因果对照。

### 7.2 检查“匹配是否更好”和“决策是否使用匹配”

- **匹配能力：** 用独立的可见物体/区域标签，测指令地标与视觉节点匹配或检索正确率。若用冻结表征上的小探针，两边使用相同探针容量、训练数据与预算，并在未见场景检验。不要把带路线信息的认知地图本身当独立匹配真值。
- **决策作用：** 在预先选定、正确动作明确的样本中，替换相关地标短语或对应视觉证据，检查正确候选的概率/排名是否按语义预期变化；同时设无关词、无关节点的匹配扰动作为对照。仅“变化更大”不算更好，必须是**更正确且针对相关证据**的变化。

两项共同出现，且来自匹配训练对照，才比较有力地支持“地图训练改善地标 grounding，并影响导航”。探针准确率提高但动作不用它，只能支持表示更可解码，不能支持收益机制已经建立。

不建议把注意力熵下降或热力图更集中作为主证据：集中也可能集中在错误词上。相关研究对注意力是否具有解释性本就有条件性结论，适合作为可视化辅助，而非因果证明。[Jain 与 Wallace，NAACL 2019](https://aclanthology.org/N19-1357/)、[Wiegreffe 与 Pinter，EMNLP 2019](https://aclanthology.org/D19-1002/)

## 8. 哪些结果应改变甚至否定当前叙事

| 结果 | 应接受的结论 |
|---|---|
| 匹配对照下 B≈A、D≈C，且区间足够窄 | 没有支持 LLM 地图在 DAgger 提供额外收益；应转向解释教师/结构，而不是继续宣称地图辅助。预训练贡献仍需另判 |
| 正确图训练≈错配图训练，均优于零图 | 更像输入分布或一般训练正则化作用，不支持正确空间内容是原因 |
| 有图训练优于零图，但地标功能检验未改善 | 可以主张训练期辅助，不能具体主张弥合语言—视觉对齐差距 |
| 早期依赖下降，但有图训练最终不优于零图 | 更像弃用无益输入；不能包装成有效知识内化 |
| 匹配训练优势、地标功能优势、动作针对性变化共同成立 | 才形成“训练输入 → 表示/匹配能力 → 决策收益”的较完整证据链 |

这些假设不是互斥选项：教师效应、地图辅助与依赖下降可以同时存在。也不应为了凑机制而强行选择 H1。

## 9. 对论文主张的建议与最终意见

LLM 地图若由指令与给定起点信息生成，并未给学生增加独立的真实环境观测；其价值可以来自外部模型知识、空间化表示和训练引导。GT 地图教师则确实使用额外环境信息。建议分别称为**“训练期语言派生空间先验”与“GT 特权教师”**，避免把二者混成同一个信息源。训练期多表示/教师辅助本身已有成熟研究脉络，创新点应落在空间表示为何有效及严格对照结果，而不是仅在“测试去图”。[Lopez-Paz 等，Unifying Distillation and Privileged Information](https://arxiv.org/abs/1511.03643)

另外，保留起点元数据的 KD deploy 66.50 与全部置零 65.47，相差 1.03 pp（用户提供）。这说明“保留什么”不可省略。D5 还发现现有 prompt 的 level-local 起点坐标构造调用了语义楼层/GT 轨迹相关预处理；应另行确认真正部署如何从可用输入得到同一坐标，不能把“等于 prompt 输入”直接当作“只需实时起点位姿”。这不否定地图训练研究，但限制当前“完全不依赖 GT 的部署”表述。[D5 元数据来源提醒](/home/xukai/code/ETP-R1-snapshot/ETP-R1/reports/d5_training_time_map.md:15)
