# 12｜Try5全节点融合与路线门控认知地图更新方案

日期：2026-08-21

## 1. 目标与原则

已知：静态LLM-Grid Try5为 SR 65.42 / SPL 55.25，GT认知地图单向attention约为 SR 72。新方案只解决一件事：

```text
利用路线相关的在线视觉证据修正LLM认知地图，
同时保留正确的未见先验，再交回原Try5完成决策。
```

原则：前端encoder和Try5决策结构不变；不再使用无坐标token重写、ghost-only residual、progress/recovery等OnlineFusion分支。

## 2. 整体结构

```text
当前高层step RGB-D + 实时pose
              ↓
       SpatialVisualHead
              ↓
     空间视觉证据 + 覆盖mask
              ↓
       RouteUpdateGate
       ├─ 路线相关：更新Pt
       └─ 偏航/旧路段：Pt=Pt-1
              ↓
         Map Encoder
              ↓
原Try5单向attention：STOP + visited + ghost全部读取地图
              ↓
       原global encoder/action head
```

## 3. 地图状态

- `P0`：原始LLM-Grid，episode内永远保留；
- `Pt`：当前供Try5读取的地图；
- `Et`：累计视觉语义证据；
- `Ct`：累计Depth有效覆盖。

每个格子区分 `prior / observed-positive / observed-negative / unknown`。没有Depth覆盖的格子不能产生负证据；LLM中的0默认是unknown，不代表物体不存在。

## 4. 空间视觉证据

测试阶段每个高层step可从Simulator取得agent实时 `(x,y,z)` 和heading；visited waypoint坐标也已保存在 `GraphMap.node_pos`。

现有v1缓存只有每个viewpoint的 `(37,)` 类别集合，无法定位。需要生成v2缓存：

```text
12个30°方位段 × 37类 × 5个距离段
距离段：0–2、2–4、4–6、6–8、8–10 m
+ Depth射线覆盖mask
```

`SpatialVisualHead`从现有12-view RGB/Depth表示预测上述证据。结合实时pose、episode起点、初始heading、地图起点格和0.5 m/cell，将证据投影到 `100×100` 网格。预训练结束后冻结该head；DAgger/测试不使用Semantic GT。

## 5. 何时更新地图

不按teacher/student动作来源判断，而由 `RouteUpdateGate` 判断当前观测是否属于尚未完成的路线。

输入：instruction、当前panorama、当前地图context和拓扑历史。训练标签：

- 距当前进度之后的GT path后缀 `≤3 m`：正例；
- 只靠近已完成旧路段，或距后缀 `>3 m`：负例。

因此：

- teacher和仍在正确路线上的student观测可以更新；
- 真正偏航的student观测只写视觉拓扑图，不写认知地图；
- 测试时使用模型预测的门，不需要GT或teacher标记。

## 6. 如何更新地图

若路线门关闭：

```text
Pt = Pt-1
```

若路线门开启，先累积 `Et/Ct`。已观察区域按视觉置信度 `q` 纠错：

```text
Observed = (1-q)·Pt-1 + q·Et
```

未观察区域由轻量卷积 `PosteriorRefiner` 输出残差 `Δt` 和门 `βt`：

```text
Unseen = P0 + βt·Δt
CandidatePt = Ct·Observed + (1-Ct)·Unseen
Pt = g_t·CandidatePt + (1-g_t)·Pt-1
```

训练使用软门 `g_t`，测试可阈值化。无新证据时硬性令未见残差为0。这样具体已见错误由视觉纠正，未见区域默认保持 `P0`，只有路线相关证据才能推动远端修订。

## 7. 与拓扑图的融合

完整复用Try5，而不是只增强ghost：

```text
Query：STOP + visited + ghost拓扑token
Key/Value：更新后的101个地图token
```

attention结果残差加回全部有效拓扑节点，再进入原语言-拓扑global encoder。Try5结构和已有权重均继承，并在两阶段中以较小学习率微调。

## 8. 损失

保留原 `MLM/SAP/action CE`，新增：

1. `L_visual`：方位×类别×距离BCE；仅预训练。
2. `L_route`：路线门class-balanced BCE。
3. `L_seen`：已覆盖区域地图Focal BCE + Dice。
4. `L_fix`：未见区域中 `P0` 与GT冲突的有效语义support。
5. `L_keep`：未见区域中 `P0` 与GT一致的正语义格子保持不变；不监督全零背景。

`shuffled evidence`不作为训练loss，只作为最终消融：换成其他scene证据后若性能/地图几乎不变，说明模型没有真正利用视觉内容。

## 9. 训练Pipeline

### 9.1 预训练

1. 从完整LLM-Grid Try5预训练checkpoint初始化；
2. expert trajectory按prefix展开，每个prefix直接监督地图；
3. 同scene、远离GT path后缀的viewpoint提供路线门负例；
4. 更新 `Pt` 后通过原Map Encoder和Try5完成MLM/SAP；
5. 前端冻结；新模块 `1× LR`，Map Encoder、Try5 attention和原后端 `0.1× LR`。

### 9.2 DAgger

每个高层step，无论动作来自teacher还是student：

```text
实时pose + RGB-D
→ 空间证据
→ 预测路线门
→ 条件更新Pt
→ 原Try5全节点读取Pt
→ 原action head决策
```

SpatialVisualHead冻结；RouteUpdateGate和PosteriorRefiner用 `1× LR`；Map Encoder、Try5和原后端用 `0.1× LR`；前端保持冻结。地图更新使用预测软门，`L_route`只提供监督，保证训练与测试一致。

### 9.3 测试

每个高层step读取实时pose和RGB-D，预测空间证据及路线门，条件更新 `Pt`，再由原Try5决策。不使用GT地图、GT path、Semantic sensor、teacher action或在线LLM。

## 10. 成败标准

- 固定endpoint同时超过 SR 65.42、SPL 55.25；
- SR目标至少约67.6，即收回LLM地图到GT地图差距的三分之一；
- on-route已见区域地图质量提高；
- off-route期间 `Pt` 基本不变；
- 未见正确先验保留率不下降；
- shuffled evidence不能保持同等收益。

先完整实现和训练本方案；成功后再消融。完整预算仍不能超过Try5，则停止该方向。
