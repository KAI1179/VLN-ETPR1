# 09｜双向钢人分析：认知地图在线更新是否值得继续

日期：2026-08-20

## 0. 结论先行

结论分成两层：

1. **停止当前 OnlineFusion 路线。**“不建立 graph-grid 位置对应、让全部地图 token 每步全局改写、再用绝对网格 GT 监督”的方案存在结构性矛盾；30k DAgger 的显著退化已经与该问题相互印证。不建议继续为这套实现增加 loss、head 或训练时长。
2. **更宽泛的研究问题暂不放弃，但只值得再做一次决定性上界实验。**现有证据证明视觉证据能改善地图预测，也证明静态 LLM-Grid 对导航有用；尚未证明的是：**因果地修正地图后，是否真的增加了当前拓扑图之外的 ghost 决策信息。**在回答这一点之前，不值得再训练一套大型融合网络。

最大风险不是优化困难，而是：当前认知网格可能主要是一张“路线语义草图”，并没有稳定的空间位置；若如此，它适合提供静态语义先验，却不适合被视觉节点当作空间地图逐格更新。

## 1. 真正要解决的问题

目标并不是简单地“融合两张地图”，而是解决下面这个决策问题：

> 在陌生连续环境中，LLM-Grid 提供有长时程价值但可能幻觉、错位的指令先验；视觉拓扑图提供局部可靠、可执行但看不远的在线证据。能否只用截至当前时刻的视觉观测修正先验，并让修正结果为当前 ghost/frontier 提供额外的长时程价值，从而稳定超过静态 Try5？

这包含三个因果主张：

1. 新视觉观测能指出认知先验中“什么应改、什么应保留”；
2. 更新后的状态比静态地图更接近当前 episode 的真实且任务相关的环境；
3. 这种改进能改变正确 ghost 的排序，而不只是降低地图或辅助任务 loss。

其中前两个属于地图学习，第三个才是导航价值。`phase/remaining/recovery` 只是可选辅助任务，不是核心 idea；即使它们预测准确，也不能证明双地图更新有效。

## 2. 已有事实：证据到底支持到哪里

### 2.1 仓库内的直接证据

| 事实 | 证据强度 | 能说明什么 | 不能说明什么 |
|---|---|---|---|
| 普通 LLM-Grid 在 R2R `val_unseen` 的 Raster IoU 约为 **0.136**、Cell F1 约为 **0.228**，但 object/region 类别 F1 约为 **0.681/0.679** | 强；完整1839条 episode | 类别大体可猜，精确空间布局是主要短板 | 不能说明这些错误一定妨碍导航 |

| Try5 iter28000 达到 SR/SPL **65.42/55.25** | 强；完整1839条评测 | 静态 LLM-Grid 的读取通路具有导航价值 | 不能证明其价值来自精确空间布局，而非类别/路线先验 |

### 2.2 当前实现的关键事实

当前 OnlineFusion：

- 用新模块替换了 Try5 已训练的静态 map→graph 通路，而不是在其上验证“在线更新”的增量；
- 不计算视觉拓扑节点对应哪个网格位置；
- 一旦出现新观测，100个空间 token 都允许更新，并继续通过 map self-attention 扩散；
- 只给 ghost 写 map-conditioned embedding residual，STOP 另走 logit residual；
- 同一个 progress hidden 同时进入地图更新、地图读取和动作 residual；
- 用完整 `(37,100,100)` GT 约束一个无明确空间绑定的隐状态。

这意味着实验同时改变了“地图是否更新、如何读取地图、动作 head、进度表示和辅助监督”。因此它不是对“在线更新是否有增益”的干净检验，但其大幅退化足以否定**当前组合方案**。

## 3. 支持该 idea 的最强论证

### 3.1 两种地图的信息确实互补

LLM-Grid 在出发前就能根据整条指令提供目标、房间、地标和路线顺序等远程先验；视觉拓扑图只能积累已经走过的节点以及约3 m范围内的 ghost，却提供真实可达性和当前视觉证据。一个负责“看得远但可能错”，另一个负责“局部可信但看不远”，理论上存在互补空间。

这不是纯推测：Try5 说明静态认知地图已经含有可用导航信号；起点 matched evidence 实验又说明与当前环境匹配的视觉观测能改善地图预测，甚至改善未观察区域的选择性。

### 3.2 现有方法普遍支持“显式空间记忆 + 在线证据”

- [Cognitive Mapping and Planning](https://arxiv.org/abs/1702.03920) 用显式俯视信念地图累积观测并规划；
- [Chasing Ghosts](https://papers.neurips.cc/paper_files/paper/2019/file/82161242827b703e6acf9c726942a1e4-Paper.pdf) 把VLN写成带观测模型和运动模型的状态跟踪问题；
- [Cross-Modal Map Learning](https://openaccess.thecvf.com/content/CVPR2022/papers/Georgakis_Cross-Modal_Map_Learning_for_Vision_and_Language_Navigation_CVPR_2022_paper.pdf) 构建受语言条件约束的显式俯视语义地图；
- [BEVBert](https://arxiv.org/abs/2212.04385) 明确区分局部度量地图和全局拓扑地图，用前者聚合观测、后者承担长程规划；
- [GridMM](https://arxiv.org/abs/2307.12907) 把历史观测按位置投影到动态增长的网格记忆；
- [VLFM](https://arxiv.org/abs/2312.03275) 用深度构建可达前沿，再用语言相关价值图选择探索方向；
- [Imagine Before Go](https://openaccess.thecvf.com/content/CVPR2024/papers/Zhang_Imagine_Before_Go_Self-Supervised_Generative_Map_for_Object_Goal_Navigation_CVPR_2024_paper.pdf) 显式区分已观察与未知区域，并随观测增加反复补全未知地图。

这些工作共同支持“先验、观测、空间记忆、frontier价值”这个大方向。项目的潜在独特点是：**用指令生成的想象地图作为先验，再用连续VLN中的已验证拓扑证据修正它，并把修正后的远程信息绑定到可执行 ghost。**没有发现与这一完整设定完全相同的工作。

### 3.3 如果做成，收益位置很明确

最可能受益的不是所有决策，而是以下子集：

- 至少有两个可行 ghost，局部视觉都合理，但只有一个符合后续指令；
- 静态 LLM-Grid 对地标或房间预测正确，但因已见证据需要调整方向或顺序；
- agent 偏航后，需要保留目标语义，同时否定已经证伪的局部路线。

因此，一个真正有效的方案应首先在这类“地图会改变分支选择”的决策上提高 expert-ghost 排序，而不是先期待全部 episode 的平均 SR 自动上升。

## 4. 反对该 idea 的最强论证

### 4.1 对当前方案近乎致命：没有位置对应，就不存在可解释的“地图修正”

模型看到“当前是厨房”并不等于知道应该修改100个 token 中的哪一个。若 LLM-Grid 的朝向、距离和房间布局都可能错，又完全取消 graph-grid 对应，那么一次观测无法区分：

- 当前证据支持原来的哪个格子；
- 某个预测只是位置错了，还是内容错了；
- 哪些未见区域应保持，哪些应连带变化。

全局 attention 可以产生新的隐状态，但不能保证 token 继续保持原来的空间含义。此时再要求它解码绝对网格，是把“无位置的历史记忆”和“有位置的地图”混为一谈。这个问题不是多加一个 loss 就能解决的。

### 4.2 视觉证据不能证伪大部分未见想象

没有看到某个物体通常只意味着视野、距离或遮挡不允许看到它，并不等于它不存在。当前GT又是稀疏、路线相关的认知图，而不是完整场景真值。若没有观测覆盖范围和明确位置，模型无法得到可靠的负证据，容易把“未知”误当“错误”并覆盖仍有用的远程先验。

### 4.3 地图分辨率可能不适合直接区分当前 ghost

原始网格是0.5 m/格，但 Map Encoder 的一个 token 约汇总 **5 m×5 m**；ETP ghost 通常只在约3 m内。多个相邻 ghost 可能读取几乎相同的粗粒度地图内容。认知地图也许适合提供“下一房间/地标”价值，却未必有足够分辨率直接决定近距离分支。

### 4.4 “地图更像GT”不等于“动作更正确”

已有 Oracle-t0 结果已经发出警告：地图预测指标提高，并没有在未匹配预训练条件下超过普通 Try5。2026年的 [WorldMAP](https://arxiv.org/abs/2604.07957) 也给出相近提醒：生成世界的价值可能更适合作为结构化训练监督，而不是直接当作可执行证据。该论文不是本项目的直接反证，但说明“想象质量→动作收益”不能默认成立。

### 4.5 当前负结果不是小问题

OnlineFusion 相对 Try5 最好 checkpoint 低约9.5个SR点、11.3个SPL点；继续训练后还进一步回退。同时写门长期约0.5、地图状态变化很大，而 `L_grid` 基本不改善。这更符合“表示和目标定义错误”，而不是“训练不够久”。

### 4.6 相近工作削弱了宽泛表述的新颖性

局部度量图+全局拓扑图、在线语义地图、frontier价值图、生成未知区域，这些组成部分都已有工作。仅仅提出“双向 attention”“两张地图联合进化”不构成强贡献。只有证明下面的完整因果链，才有清晰研究价值：

```text
视觉证据修正了具体错误先验
        → 未见区域的有效先验被保留
        → 正确 ghost 的相对价值提高
        → unseen 导航稳定改善
```

## 5. 双向钢人后的判断

### 5.1 对当前 OnlineFusion：NO-GO

反方已经暴露了一个结构性问题：**空间 token 没有稳定对应关系，却承担空间地图更新和绝对网格解码。**再结合显著负结果，当前路线不值得继续。建议把它保留为负对照和失败分析，不再对其做增量修补。

### 5.2 对宽泛研究假设：一次验证额度的“有条件GO”

支持方仍有两条实证基础：静态认知先验对导航有用，视觉证据对地图预测有用。因此“可靠证据修正想象先验”还没有被否定。

但继续的条件应非常严格：先证明**理想的、因果的视觉修正本身能改善 ghost 决策**。如果连使用GT位置和GT视觉语义构造的上界更新都不能比静态 Try5 提供更多决策信息，那么学习型 OnlineFusion 更不可能解决问题，应放弃整个“在线更新认知网格来辅助动作”的方向。

## 6. 真正决定结论的变量

按重要性排序：

1. **增量决策信息**：在已经有指令、视觉拓扑图和ghost特征后，修正地图是否仍能提高 expert ghost 的排序？
2. **位置是否可恢复**：使用当前起点、heading、轨迹位姿后，视觉证据能否稳定绑定到认知地图局部？现有四向 target-free 实验失败，说明这不是已解决问题。
3. **冲突决策的占比**：多少决策真的需要地图在多个ghost之间消歧？若占比很低，即使地图更新正确，平均SR也很难明显提升。
4. **更新是否因果**：目标和输入只能使用当前及过去观测，不能把完整未来路径或未来语义泄漏给前缀状态。
5. **地图改进是否被决策器利用**：若地图IoU提高而ghost排序不变，瓶颈在地图表示/读取，而不是更新器容量。
6. **连续环境视觉语义质量**：冻结的 `VisualEvidenceHead` 是否在连续rollout节点上仍准确，目前没有直接指标。

## 7. 最低成本、最有判别力的验证

### 7.1 唯一优先实验：Causal-Oracle Ghost Probe

不训练新的OnlineFusion，不改前端，不先跑完整DAgger。复用现有Try5/数据，收集teacher-forced决策前缀；只在“至少两个有效ghost且expert action是ghost”的状态上比较四组相同容量的小型排序器：

1. `graph only`：只有现有拓扑/ghost表示；
2. `graph + static map`：普通静态LLM-Grid；
3. `graph + causal oracle update`：从静态LLM-Grid开始，只用时刻`t`之前的观测；诊断阶段允许GT pose和GT语义把已见区域写到正确位置，但禁止未来观测；
4. `graph + shuffled update`：使用来自其他episode或错误位置的同量视觉证据，排除“增加参数/语义数量”带来的假提升。

冻结现有encoder，仅训练同一个轻量ghost ranker。主指标不是地图IoU，而是：

- `val_unseen` expert-ghost Top-1 / MRR；
- 静态地图与视觉证据冲突子集上的配对提升；
- 按scene聚类的置信区间。

这比重新跑500k预训练+30k DAgger便宜得多，又直接测试核心因果链中最缺的一环。

### 7.2 预先冻结停止条件

- **Oracle更新不优于静态地图**：放弃“在线更新认知网格来辅助ghost”的整个方向，回到静态Try5；不要继续设计学习型更新器。
- **Oracle更新有效，但错误位置/shuffle同样有效**：收益来自额外语义或模型容量，不是地图修正；该idea不成立。
- **只有GT位置绑定有效，target-free绑定无效**：核心课题是位置对齐，而不是fusion；禁止再次尝试无坐标全局改写。
- **地图指标提高，但ghost排序不提高**：放弃以网格重建loss为核心的路线；地图保真度不是导航代理。
- **Oracle更新在冲突子集和总体决策上都有稳定增益**：才授权下一套模型采用“明确位置绑定、只更新观测覆盖区域、保留未知区域”的在线地图更新，并进入固定预算导航实验。

具体最小效果门槛应在运行前冻结；至少要求配对差值的scene-cluster 95%置信区间下界大于0，并达到预先定义的实际提升幅度，不能只凭单点的微小正数继续。

## 8. 唯一缺失且会改变判断的信息

仓库记录显示 source-matched ordinary/Oracle-t0 两臂已完成500k预训练，并启动固定 `iter28000` 的配对DAgger；但本地文档没有记录两臂最终SR/SPL/nDTW结果，登录节点当前也无法解析主机名，未能只读核对。

唯一需要补充的问题是：

> **source-matched ordinary 与 Oracle-t0 的固定 iter28000 配对评测结果分别是多少？**

若Oracle-t0明确优于ordinary，它会加强“视觉修正后的地图具有导航价值”的支持方；若持平或更差，则宽泛idea只剩上述Causal-Oracle Ghost Probe这一次验证机会，不应再直接投入完整训练。

## 9. 最终建议

1. 立即将当前OnlineFusion判为失败实现，不再追加训练或模块；
2. 先补齐已经在跑的ordinary/Oracle-t0配对结果；
3. 随后只做一次Causal-Oracle Ghost Probe；
4. Probe失败则明确放弃“在线更新认知网格辅助决策”；Probe通过才重新设计带明确空间绑定的最终模型。

这是目前证据下最有利于项目的判断：既不把一次错误实现误当成整个idea的反证，也不因概念听起来合理而继续支付大规模训练成本。
