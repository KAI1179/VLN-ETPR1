# 13｜融合方案六项风险回应与决策

日期：2026-08-26

## 1. 先验证 6.6 SR gap 的来源

**判断：同意先做，而且这是继续大规模训练前优先级最高的验证；但它不是严格的“理论上界”。**

用固定 Try5 权重做在线评测：每个高层 step 累积真实 Depth 覆盖，令

```text
P_t = 已覆盖区域的GT地图 + 未覆盖区域的LLM地图
```

覆盖必须来自该策略实际走出的轨迹，不能预先使用完整 GT path。建议固定 checkpoint、评测集和 endpoint，同时比较四组：

```text
LLM全图 / GT-seen+LLM-unseen / LLM-seen+GT-unseen / GT全图
```

`GT-seen+LLM-unseen` 是“直接纠正已见区域”贡献的低成本强诊断，不是严格理论上界：冻结的 Try5 可能不适应混合地图，而当前 Refiner 还允许根据局部证据推断未见区域。

- 若 SR ≥ 67.6：说明已见错误足以支撑目标，继续本方案。
- 若 SR 明显低于 67.6（如约 66）：不能数学上证明训练后不可达，但足以否定“收益主要来自已见纠错”的归因；应停止当前核心叙事，而不是直接投入完整训练。除非明确把研究问题改成“根据局部证据推断未见区域”。

同时报告 gap 回收率：

```text
(SR_oracle_seen - 65.42) / (72.0 - 65.42)
```

## 2. RouteUpdateGate 标签漏洞

**判断：成立。当前位置到 GT path 后缀的距离只能表示路线相关性，不能表示视觉证据是否有用。**

它会错标两类样本：偏航但看见正确路线内容的观测，以及在路线上但没有有效语义的观测。当前代码中的门实际只看 panorama、文本和地图的全局均值，并未输入 pose 或拓扑历史，因此它不会直接学成位置判别器，而更可能学习带噪声的场景/视角相关性。

建议用共享主体输出两个量：

- `g_route`：投影视野是否与剩余路线相关；
- `g_quality`：该证据是否真的降低覆盖区地图误差；
- 最终写门 `g = g_route · g_quality`。

```text
utility_t = Error(P_{t-1}, GT, visible_t)
          - Error(P_candidate, GT, visible_t)
```

`utility_t > 0` 监督 `g_quality`；距 GT path 后缀的距离只辅助监督 `g_route`。这样门必须同时看证据内容与地图冲突。

另有一个明确代码问题：`route_map_progress` 当前使用整条 path 的 `argmin`，应使用 `suffix_start + argmin(suffix_distances)`，否则进度可能长期不前移。

## 3. 视觉缺失会稀释正确先验

**判断：成立，当前实现的风险比文档描述更明确。** 当前所谓 `q` 实际是每个方位/距离 bin 共用的预测 `coverage`，不是类别可靠度；只要有几何覆盖，未检测类别也会用接近 0 的证据压低原先验。

应拆开几何覆盖与类别证据，并为每个“类别×距离段”学习两种可靠度：

```text
P' = P + q_pos·E·(1-P) - q_neg·(1-E)·P
```

- `q_pos`：检测到该类时增加置信度；
- `q_neg`：未检测到该类时删除先验的置信度；
- 小物体、远距离类别的 `q_neg` 应很低，避免把漏检当成不存在。

因此，Depth 覆盖本身不能作为37类共同的负证据。

## 4. 证据分辨率与 0.5 m 网格不匹配

**判断：问题成立，但当前代码不是“大块涂抹”。** 当前实现把每个 `30°×2 m` bin 只投到距离中点的一个格子，实际问题是把粗证据赋予了错误的单格精度；若改成填满扇区，才会出现约几十格的涂抹。

建议最终采用：

- `0–4 m`：距离段细化到 `0.5 m`，按不确定扇区做软投影，只使用可靠正证据直接更新；
- `4–10 m`：不直接进入 `Observed`，只作为门判断和软约束；
- 仅细化距离仍不能解决 `30°` 角分辨率，因此禁止把一个 bin 当成一个确定的 0.5 m 格子。

这需要新缓存格式；现有 V2 缓存不能完整支持该修改。

## 5. 预训练与 DAgger 的门状态不一致

**判断：部分同意，但真正的问题不是 Refiner 没学过“关闭”，而是关闭时状态仍被污染。**

当前预训练已有同 scene 远端负例，但负例只经过 `RouteUpdateGate`；更严重的是，当前代码即使门关闭，也会先累计 `evidence/coverage`，以后门重新打开时可能把偏航证据带入地图。

必须改为门同时控制三个状态：

```text
P_t = g·P_candidate + (1-g)·P_{t-1}
E_t = g·E_candidate + (1-g)·E_{t-1}
C_t = g·C_candidate + (1-g)·C_{t-1}
```

预训练的远端负例应走完整 updater，并增加 `L_nochange`，监督关闭时 `P/E/C` 均保持不变。Refiner 在门关闭时无需产生有效更新；需要保证的是整个状态转移严格不写入。

## 6. 防止偏航与偏航后恢复的牵制

**判断：不是逻辑矛盾，但必须拆开归因。** 门关闭后地图不更新，仍可通过“当前拓扑节点 Query → 固定地图 Key/Value”帮助恢复；不过预期主要收益确实应来自在正确路线上更早避免错误，而不是偏航后修图。

除 SR/SPL 外，增加四项统计：

1. `never_offroute_rate`：全程未首次偏离的 episode 比例；
2. `first_offroute_step`：首次距剩余 GT path 后缀超过 3 m 的高层 step；
3. `recovery_rate`：首次偏离后重新回到 3 m 内的比例；
4. `offroute_map_drift`：偏航期间 `|P_t-P_{t-1}|`，应接近 0。

若提升主要来自 `never_offroute_rate`，说明地图在预防走错；若 `recovery_rate` 提升，说明固定认知地图也在支持拓扑图纠偏。

## 7. 总体结论

六点中，第 1 点是继续训练前的 go/no-go 验证；第 2、3、5 点要求修改设计；第 4 点需要修正对当前实现的描述并决定是否重做缓存；第 6 点属于评测归因。

当前最值得做的下一步只有一个：先跑四组零训练归因评测，重点看 `oracle-seen-only`。若它明显不足 67.6，应停止“收益主要来自已见纠错”的当前方案叙事，而不是继续训练现有实现。
