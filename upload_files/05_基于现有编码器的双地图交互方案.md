# 基于现有编码器的双地图交互方案

方案日期：2026-08-12

适用对象：ETP-R1 + LLM-Grid

本文是 04 号文件的收敛版本。实现时以本文为准：保留当前有效的编码器与导航主干，只替换 Try5 的单向地图融合模块，并在该位置增加直接、可训练的双向交互。

## 0. 一句话结论

完整方案只做三件事：

1. **视觉拓扑图更新认知地图**：只有本步新增的 visited 视觉节点可以局部更新认知地图 token，并把更新后的状态保存到下一步。
2. **认知地图帮助 ghost 决策**：每个 ghost 从整张更新后的认知地图读取远处语义价值，但认知地图不生成新 ghost，也不修改拓扑边。
3. **两张地图联合预测执行进度**：预测当前处于五段路线中的哪一段、是否偏航、是否应该结束；预测结果同时帮助 ghost 和 STOP 决策。

不采用：

- 事件链；
- 多套地图配准；
- 地图形变；
- 复杂的转移规划模块；
- 在线 LLM；
- 网格与 JSON 之间的来回转换；
- 对现有语言、RGB-D、panorama、拓扑图和认知地图 encoder 的结构改造。

## 1. 对问题 1：预训练和 DAgger 当前更新哪些参数

### 1.1 当前 Try5 预训练

当前 `scripts/submit/llm-grid-try5-pretrain.sh` 调用的配置中，`update_lang_bert=true`；optimizer 又直接收集 `model.named_parameters()`，没有建立“只训练融合模块”的白名单。因此当前预训练近似全量更新：

| 模块 | 当前是否更新 | 说明 |
|---|---:|---|
| 文本 embedding 与 12 层语言 encoder | 是 | `update_lang_bert=true` |
| RGB 特征投影、Depth 特征投影 | 是 | 输入是预先提取的特征，不是原始 CNN |
| panorama encoder | 是 | 属于预训练模型参数 |
| 拓扑图位置、step、task embedding | 是 | 属于 global map encoder |
| graph-language global encoder | 是 | MLM、SAP 都会经过该模块 |
| 当前 Try5 单向融合 | 是 | `graph_map_attention` |
| 当前 Map Encoder | 是 | 从缓存网格生成 101 个 token |
| MLM head | 仅 MLM batch 更新 | 任务相关 |
| SAP/action head | 仅 SAP batch 更新 | 任务相关 |
| RGB CLIP/Depth ResNet 原始 backbone | 不存在于该预训练图中 | 读取离线 RGB/Depth feature 文件 |
| 用于初始化地图类别的 CLIP 文本模型 | 否 | 只生成初始化值，不属于 Map Encoder 子模块 |

证据位置：

- optimizer：`pretrain_src/pretrain_src/optim/misc.py:14-45`；
- `update_lang_bert=true`：`pretrain_src/run_pt/mix_model_config_dep.json:31`；
- 预训练模块：`pretrain_src/pretrain_src/model/pretrain_cmt.py:95-177`；
- 离线 Depth 特征：`pretrain_src/run_pt/mix_pretrain_server.json:32-49`。

结论：**当前预训练并不是只训练 Map Encoder 和 Try5 fusion，而是大部分模型都会更新。**进入 optimizer 不代表每个任务的每个参数在每一步都有非零梯度，但总体上属于全量微调。

### 1.2 当前 LLM-Grid Try5 DAgger

当前配置为：

```text
freeze_base = False
fix_lang_embedding = False
fix_pano_embedding = False
```

所以 DAgger 也接近全量更新 policy：

| 模块 | 当前是否更新 |
|---|---:|

| panorama 的 RGB/Depth 投影与 pano encoder | 是 |
| Map Encoder | 是 |
| graph-language global encoder | 是 |
| Try5 fusion | 是 |
| graph-query-text、后处理与 SAP head | 是 |
| RGB CLIP encoder | 否，固定 |
| Depth ResNet encoder | 否，固定 |
| waypoint predictor | 否，固定且不在 policy optimizer 内 |

证据位置：

- optimizer 与 `requires_grad` 过滤：`vlnce_baselines/ss_trainer_ETP_PriorGT.py:270-314`；
- 默认 `freeze_base=False`：`vlnce_baselines/config/default.py:193-198`；

- 固定 waypoint：`vlnce_baselines/ss_trainer_ETP_PriorGT.py:249-267`。

### 1.3 本方案建议的参数更新方式

本方案**不建议继续让全部参数以同一学习率更新**。编码器结构保持原样；参数分为三组：

| 参数组 | 预训练 | DAgger | 原因 |
|---|---:|---:|---|
| RGB CLIP、Depth ResNet、waypoint predictor | 固定 | 固定 | 当前本来就是固定的 |
| 文本 embedding/language encoder | 固定 | 固定 | 保留已验证的指令表示 |
| panorama RGB/Depth projection 与 pano encoder | 固定 | 固定 | 保留已验证的视觉拓扑输入 |
| 现有 Map Encoder | 见下方说明 | 小学习率 | 结构不改，只学习初始缓存网格的表示 |
| 现有 global graph-language encoder | 小学习率 | 小学习率 | 适配新交互输出 |
| graph-query-text、SAP/action head | 小学习率 | 小学习率 | 保留原决策路径，同时适配新增信号 |
| MLM head | 小学习率 | 不参与 | 保留原 MLM 任务 |
| 新双地图交互模块及辅助 head | 正常学习率 | 正常学习率 | 本次实验重点 |

建议新模块学习率为 `1×`，现有后端决策模块为 `0.1×`。Map Encoder 取决于初始化来源：

- 从 `mlm.sap_habitat_depth/model_step_367500.pt` 起步：若严格检查确认其中没有已训练的 Map Encoder，则 Map Encoder 必须以 `1×` 学习率训练；不能冻结一个新初始化的模块。
- 从已经验证完整的 LLM-Grid Try5 checkpoint 起步：Map Encoder 使用 `0.1×`，或直接固定。

两种情况都不修改 Map Encoder 的结构。

当前 `freeze_base=True` 不能直接使用：它只保留名字包含 `map_encoder/map_predictor` 的参数，连 `graph_map_attention` 也会冻结。需要新增明确的参数白名单或 `trainable_profile`。

## 2. 对问题 2：现有 encoder 是否需要变化

同意：**前面的 encoder 结构完全不动。**

保留以下现有路径：

```text
指令 → 当前 language encoder ─────────────────────────────┐
                                                          │
RGB + Depth → 当前 waypoint / panorama encoder → 拓扑图 ──┤
                                                          │
缓存认知网格 → 当前 Map Encoder → 101 个 map tokens ──────┘
```

保留以下现有模块：

- RGB CLIP encoder；
- Depth ResNet encoder；
- waypoint predictor；
- panorama image/depth embedding 与 pano encoder；
- language encoder；
- 当前 `EmbeddingGridMapEncoder`；
- GraphMap 的构建与 ghost 生成；
- global graph-language encoder；
- graph-query-text 与现有 SAP/action head。

唯一替换的是：

```text
GraphMapCrossAttention（拓扑图单向读取静态认知地图）
                         ↓
MapGraphInteraction（拓扑图写地图 + 更新地图反哺拓扑图）
```

准确位置位于图节点 embedding 已构造完成、进入 global graph-language encoder 之前：

- DAgger：`vlnce_baselines/models/etp_prior_gt/vilmodel_cmt.py:958-982`；
- 预训练：`pretrain_src/pretrain_src/model/vilmodel.py:787-816`；
- 当前 Try5 模块：`vlnce_baselines/models/etp_prior_gt/map_fusion.py:7-41`。

新模块中的“地图 → 拓扑图”分支沿用 Try5 的计算和已有权重，只把静态 `map_tokens` 改为更新后的 `map_state`。因此当前已经带来约 3% 提升的有效信息通路会被保留。

## 3. 对问题 3：为什么曾提出事件链，以及现在为什么删除

事件链原本想解决一个额外问题：LLM 可能预测对了“卧室—走廊—厨房”的顺序，却把绝对位置预测偏了，于是尝试把网格压缩为若干有序语义点再做匹配。

但它不是当前目标的必要条件，反而会增加：

- 网格到事件的抽取规则；
- 事件顺序标签；
- 视觉事件识别；
- 额外的匹配损失；
- 错误来源和调试成本。

当前认知地图缓存已经提供起点位置、方向信息和固定网格坐标；视觉拓扑节点也有实际坐标。因此本方案直接建立**节点坐标到网格 token 的唯一映射**，不再抽取事件链。

---

## 4. 对问题 4：不再涉及 JSON 或在线 LLM

同意，并作为硬约束：

```text
预训练：缓存的 (37,100,100) 网格 → Map Encoder
DAgger：缓存的 (37,100,100) 网格 → Map Encoder
推理：缓存的 (37,100,100) 网格 → Map Encoder
```

这三个阶段都不加载 LLM，也不生成 JSON。

LLM 的作用已经在训练前完成：

```text
指令 → LLM 离线生成 JSON → 离线 rasterize → 缓存网格
```

这不是预训练或 DAgger 计算图的一部分。在线更新后的地图直接解码为 `(37,100,100)` 网格并计算网格损失，不再转回 JSON，不计算文本交叉熵。

## 5. 对问题 5：baseline 是否输入 Depth

**是，而且 Depth 在当前 baseline 中很重要。**

### 5.1 在线 DAgger/推理

配置明确开启 RGB 和 Depth：

- `run_r2r/r2r_vlnce.yaml:4-21`：启用 `RGB_SENSOR, DEPTH_SENSOR`；
- `run_r2r/iter_train.yaml:110-121`：`use_depth_embedding=True`。

Depth 有两条用途：

1. **候选点生成**：12 个方向的 Depth 经固定 Depth ResNet 提取特征，再进入 waypoint predictor。当前 waypoint predictor 中 RGB 分支被注释，实际使用 `vis_x = depth_x`，见 `vlnce_baselines/waypoint_pred/TRM_net.py:59-73`。因此 ghost/frontier 候选生成主要依赖 Depth。
2. **拓扑节点表示**：Depth 特征经过线性投影后与 RGB 特征相加，再经过 panorama encoder，最后写入 visited/ghost 图节点，见 `vlnce_baselines/models/etp/ETP_R1_vilmodel_cmt.py:897-928`。

Depth 不以原始深度图形式直接进入最终 action head，而是先参与 waypoint 和 panorama/graph 表示。

### 5.2 预训练

预训练也使用 Depth，只是使用已经提取好的 128 维 Depth 特征：

- `depth_feat_size=128`：`pretrain_src/run_pt/mix_model_config_dep.json:9`；
- feature 文件：`pretrain_src/img_features/ddppo_resnet50_depth_features.hdf5`。

所以新交互模块可直接使用当前 RGB-D 融合后的视觉节点特征，不需要增加或修改 Depth encoder。

## 6. 对问题 6：删除多套配准及其后续复杂结构

此前的“多套配准”是为地图整体旋转、缩放或局部形变设计的：同时维护几种地图与世界坐标的对应关系，再根据视觉观测选择。这超出了当前最核心的问题，而且会显著增加状态、损失和调试难度。

本方案全部删除，改为一个确定性映射：

```text
节点相对起点位移（米）
        ↓ ÷ 0.5
100×100 原始网格坐标
        ↓ ÷ 10
10×10 map-token 坐标
```

其中节点位置来自当前 `GraphMap`，认知地图起点来自 cache。只需统一坐标轴正负号、单位和边界裁剪。若将来实验证明坐标误差确实是主要瓶颈，再单独研究配准；它不进入当前主方案。

## 7. 基本思想

### 7.1 拓扑图负责更新认知地图

初始认知地图是指令提供的先验；visited 节点是实际看见的证据。每一步只用本步新增的 visited 视觉特征，局部更新对应的地图 token。

基本规则：

- 新 visited：允许写；
- 已经消费过的 visited：不重复写；
- ghost：只读，禁止写；
- STOP：禁止写；
- 没有新观测：地图状态保持不变。

### 7.2 认知地图负责给 ghost 提供长时程信息

ETP-R1 继续负责产生真实可执行的 ghost。认知地图不创造动作，只判断：从每个 ghost 所指方向继续前进，整张地图中是否存在更符合指令的远处物体、区域和方向信息。

### 7.3 两图共同判断当前执行进度

visited 图说明“已经走过哪里、看见什么”，认知地图说明“整条指令预计还包含什么”。二者联合预测：

```text
phase 1～5 / off-route / finished
连续剩余进度 remaining ∈ [0,1]
```

预测进度进入 ghost 价值和 STOP 决策，而不只是一个孤立的辅助 loss。

## 8. 难点与直接解决方案

### 8.1 难点一：拓扑节点如何写到网格 token

问题：图节点是不规则坐标，地图是固定 `10×10` token。

直接方案：根据起点和节点实际坐标计算其 map-token 坐标；仅允许附近 token 接收更新。

```text
d(i,j) = 地图 token i 与新 visited 节点 j 的距离
w(i,j) = exp(-d(i,j)^2 / (2σ^2))
```

`w(i,j)` 是固定空间门控，不让一个局部观测修改整张地图。

### 8.2 难点二：视觉节点没有显式的 37 类地图语义

问题：当前拓扑节点是 768 维 RGB-D 表示，而认知地图有 37 个类别。

直接方案：在现有节点表示后增加一个轻量 `VisualEvidenceHead`：

```text
768-d RGB-D node feature
    → MLP
    ├─ 37 类视觉 evidence
    ├─ 37 类可判断性 visibility
    └─ 1 个整体 confidence
```

该 head 位于 encoder 之后，不改 RGB、Depth 或 panorama encoder。

`visibility` 用来区分：

- 确实看清且未发现某物：可以形成负证据；
- 根本没有覆盖或看不清：仍然是未知，不能判错。

### 8.3 难点三：如何更新地图又不破坏未观察区域

问题：普通全局 attention 可能让一个局部节点改写全部地图。

直接方案：地图 token 作 query，新 visited 作 key/value，再乘空间权重和置信度门控：

```text
ΔZ_t = CrossAttention(Z_{t-1}, new_visited_features)

gate_i = sigmoid(MLP(Z_{t-1,i}, ΔZ_t,i))
         × spatial_weight_i
         × visual_confidence

Z_t,i = LayerNorm(Z_{t-1,i} + gate_i · ΔZ_t,i)
```

- `Z_0` 是现有 Map Encoder 输出；
- 前 100 个空间 token 可更新；
- 第 101 个 metadata token 保持原样；
- `Z_t` 保存为当前 episode 的状态，下一步继续使用；
- 写入分支的最后一层从零初始化，使训练开始时严格退化为静态 Try5。

### 8.4 难点四：如何监督“更新后的认知地图”

问题：需要从 token 恢复网格，但不能转 JSON；现有 GT 又比较稀疏。

直接方案：增加轻量 `GridDecoder`：

```text
Z_t 的 100 个空间 token
    → reshape 为 (768,10,10)
    → 上采样卷积
    → (37,100,100) map logits
```

损失直接在网格上计算：

```text
L_grid = masked focal BCE + Dice
```

监督规则：

- GT 明确标注的正值可以监督；
- 负值只在真实视觉已覆盖、且该类别具备可判断性的位置监督；
- 未观察位置不参与正负分类，并用保持损失约束 `Z_t≈Z_{t-1}`；
- 不把稀疏 GT 中所有 0 都当负样本。

### 8.5 难点五：如何区分支持、想象和错误

问题：单个更新后网格看不出信息来自 LLM 还是视觉。

直接方案：状态中额外保存累计覆盖 `coverage_t` 和视觉证据 `evidence_t`，与初始缓存 `M_0` 对比，直接得到：

| 状态 | 直接判定 |
|---|---|
| 未见想象 | `M0` 有预测，但 coverage 低 |
| 视觉支持 | coverage 高，视觉证据与 `M0` 一致 |
| 认知冲突 | coverage 高、visibility 高，视觉证据与 `M0` 明显相反 |
| 视觉新增 | `M0` 无预测，但视觉持续给出正证据 |

这些状态不需要额外的事件链；它们作为置信度输入 ghost 价值头，同时用于可视化和辅助监督。

### 8.6 难点六：单个 5 m token 如何提供长时程价值

问题：只读取 ghost 所在 token 仍然是局部信息，不能判断远处路线。

直接方案：每个 ghost 对**全部 100 个更新后地图 token**做一次定向 cross-attention：

```text
ghost query = ghost feature + 坐标 + 朝向 + progress embedding

h_g = CrossAttention(ghost query, Z_t, Z_t,
                     relative_position_bias)

Δlogit_g = confidence_gate · MLP(h_g)
```

相对位置 bias 只包含直接可解释的信息：

- 地图 token 相对 ghost 的距离；
- 是否位于 ghost 朝向前方；
- 是否接近下一段预测方向。

这样 ghost 能读取远处语义，不需要额外建立复杂规划器。`Δlogit_g` 从零初始化，并且只加到现有 ghost logit；visited、padding 不变。

### 8.7 难点七：进度标签和偏航

问题：DAgger 中可能偏航或回退，进度并不总是单调。

直接方案：用指令、visited 图和更新后地图做注意力池化：

```text
h_progress = MLP([
  text-conditioned visited pooling,
  text-conditioned map pooling,
  current-node feature
])

phase_logits = Linear(h_progress)   # 5 phase + off-route + finished
remaining    = Sigmoid(Linear(h_progress))
```

训练标签由 expert path/GT trajectory 生成，但只作为 target。推理时 forward 不接收 GT 路径。

- expert prefix：监督 phase 和连续进度，可加软单调约束；
- DAgger 偏航：使用 `off-route`，不强制单调；
- `progress embedding` 输入 ghost head；
- `finished` 通过零初始化残差修正 STOP logit。

## 9. 整体网络结构

```text
【全部保持不变】

Instruction ─→ Language Encoder ────────────────────────────────┐
                                                                │
RGB + Depth ─→ Waypoint/Panorama Encoder ─→ Visual Topological ─┤
                                               Graph            │
                                                                │
Cached Grid (37×100×100) ─→ Existing Map Encoder ─→ Z0 (101×768)│
                                                                │
【只替换原 Try5 单向融合】                                      ↓

          ┌──────────────── MapGraphInteraction ────────────────┐
          │                                                     │
new visited RGB-D node ─→ VisualEvidenceHead                    │
          │                 │                                   │
          │                 └─ local gated write ─→ Zt          │
          │                                           │         │
          │                         ┌─────────────────┼──────┐  │
          │                         ↓                 ↓      ↓  │
          │                    GridDecoder       Progress   Ghost│
          │                    + provenance       Head      Read │
          │                                                   │  │
          └───────────────────────────────────────────────────┘  │
                                                                ↓
【全部保持】          Global Graph-Language Encoder → SAP Head
                                                     + ghost/STOP residual
                                                                ↓
                                                      STOP / ghost action
```

`MapGraphInteraction` 的输出：

```text
updated_gmap_embeds     # 保留 Try5 的 map→graph 基本通路
next_map_state Z_t     # 跨时间步保存
decoded_grid           # 训练监督/诊断
coverage/conflict      # 来源与置信度
progress_output        # phase/remaining
ghost_logit_residual   # 只作用于 ghost
stop_logit_residual    # 只作用于 STOP
aux_losses             # 仅训练时存在
```

## 10. 损失函数

### 10.1 预训练

保留当前 MLM 和 SAP：

```text
L_pretrain = L_MLM
           + L_SAP
           + λ_grid L_grid
           + λ_keep L_keep
           + λ_visual L_visual_evidence
           + λ_progress L_progress
           + λ_ghost L_ghost_rank
```

- `L_grid`：有效区域内的 focal BCE + Dice；
- `L_keep`：本步写入范围外保持上一时刻地图；
- `L_visual_evidence`：37 类 evidence、visibility 与 confidence；
- `L_progress`：7 类 phase CE + remaining SmoothL1；
- `L_ghost_rank`：expert ghost 的分数应高于其他 ghost。

### 10.2 DAgger

```text
L_DAgger = L_action
          + λ_grid L_grid
          + λ_keep L_keep
          + λ_visual L_visual_evidence
          + λ_progress L_progress
          + λ_ghost L_ghost_rank
```

`L_action` 仍是当前 teacher action loss。所有辅助损失按有效 episode、有效像素或有效 ghost 数归一化，避免长 episode 获得更大的隐式权重。

建议初始权重：

```text
λ_grid=0.3
λ_keep=0.05
λ_visual=0.2
λ_progress=0.1
λ_ghost=0.1
```

具体数值根据梯度量级调整，但不引入 JSON loss。

## 11. 训练 pipeline

### 11.1 预训练输入

从当前基础 checkpoint 初始化：

```text
pretrained/r2r_rxr_ce/mlm.sap_habitat_depth/store2/model_step_367500.pt
```

保持当前输入：

- instruction；
- 离线 RGB feature；
- 离线 Depth feature；
- 拓扑路径及图位置特征；
- 已缓存 LLM-Grid；
- MLM/SAP 标签。

新增训练字段：

- visited 节点的时间顺序；
- 节点实际坐标；
- `new_visited_mask`；
- 训练专用网格有效 mask；
- phase/remaining 标签；
- teacher ghost 排序标签。

这里不调用 LLM，不读写 JSON。

### 11.2 预训练前向

对每条训练路径的 prefix：

```text
1. 缓存网格经现有 Map Encoder 得到 Z0
2. 现有 RGB-D/panorama encoder 得到各 visited 节点表示
3. 按访问顺序，每个节点只执行一次 local write：Z_{t-1} → Z_t
4. GridDecoder 从 Z_t 解码更新后网格
5. ProgressHead 预测 phase/remaining
6. GhostRead 为当前候选 ghost 预测长时程残差
7. 进入现有 global encoder、MLM/SAP head
8. 联合计算原任务与新增辅助损失
```

完整交互模块从本次预训练一开始就参与训练；不存在先训练简化结构、之后再增加复杂模块的问题。

### 11.3 预训练参数组

```text
固定：
  language embedding/encoder
  panorama 前端 encoder

1× LR：
  Existing Map Encoder（仅当初始化 checkpoint 不含已训练权重）
  VisualEvidenceHead
  LocalMapWriter
  GridDecoder
  ProgressHead
  GhostLongRangeRead
  provenance/confidence heads

0.1× LR：
  Existing Map Encoder（若从完整 Try5 权重初始化）
  existing global graph-language encoder
  graph-query-text / MLM / SAP heads
```

预训练 optimizer 应显式过滤 `requires_grad`，并打印每组参数名与参数量；不能沿用当前不分组的 `build_optimizer()`。

### 11.4 DAgger 每一步

```text
episode 开始：
  读取缓存网格 → Existing Map Encoder → Z0
  初始化 coverage、evidence 与 consumed-view 集合

每一步：
  1. 按当前 ETP-R1 流程读取 RGB-D
  2. 按当前 waypoint 流程产生 ghost
  3. 按当前 panorama/GraphMap 流程更新视觉拓扑图
  4. 若当前 visited 观测是新证据，局部更新 Z_{t-1} → Z_t
  5. 预测当前 phase/remaining
  6. 所有 ghost 从 Z_t 读取全图长时程价值
  7. 使用现有 global graph-language encoder 与 SAP head
  8. 在原 logits 上加入 ghost/STOP residual
  9. 按现有 DAgger 混合策略执行动作

episode 结束：
  清空该环境的 Z_t、coverage、evidence 和 consumed-view 集合
```

并行环境 pause/reorder 时，`Z_t` 等状态必须与 `GraphMap` 使用同一索引一起调整。

### 11.5 DAgger 参数组

```text
固定：
  RGB CLIP / Depth ResNet / waypoint predictor
  language embedding/encoder
  panorama 前端 encoder

0.1× LR：
  Existing Map Encoder
  Existing global graph-language encoder
  graph-query-text / SAP head

1× LR：
  全部新交互、地图更新、进度和 ghost 模块
```

DAgger 必须从本方案的完整预训练 checkpoint 初始化，并严格检查 Map Encoder 和所有新模块是否真正加载，不能用宽泛 `strict=False` 静默跳过。

### 11.6 验证/推理

验证和推理只允许使用：

- instruction；
- 当前与历史 RGB-D；
- 已执行动作和已构建图；
- 当前 episode 的缓存认知网格；
- 模型自己维护的在线状态。

不允许使用：

- 认知地图 GT；
- GT trajectory；
- 未来观察；
- simulator semantic labels；
- 在线 LLM/JSON。

## 13. 首轮主实验与之后的消融

首轮直接训练并评估上述完整方案：

```text
ETP-R1
Try5 + static LLM-Grid
OnlineFusion + LLM-Grid（完整方案）
```

完整方案先回答一个问题：

> “视觉拓扑图持续修正认知地图，并让修正后的地图直接帮助 ghost 和 STOP，能否稳定超过静态 Try5？”

确认有效后再做消融：

1. 关闭 graph→map update；
2. 关闭 grid loss；
3. 关闭 progress 输入，仅保留辅助 loss；
4. 关闭 ghost long-range residual；
5. 不使用 visibility/confidence；
6. 固定 encoder vs 小学习率更新 encoder；
7. 只读当前地图格 vs 读取整张地图；
8. 持久化地图 vs 每一步从 `Z0` 重新计算。

## 14. 最终方案摘要

本方案不再试图一次解决地图整体形变、复杂规划或 LLM 再生成问题，而是把当前研究目标落实为三个直接的信息流：

```text
new visited RGB-D evidence
        → 局部、持久地更新 cognitive map tokens

updated cognitive map + progress
        → 为现有 ghost 读取整图长时程价值

visited graph + updated cognitive map + instruction
        → 预测 phase/off-route/finished
        → 同时帮助 ghost 与 STOP
```

这样既保留 ETP-R1 和当前 LLM-Grid Try5 已验证的编码与决策结构，又把研究重点集中在后端的双向融合、在线地图更新和长时程 frontier 决策上。
