# 基于现有编码器的双地图交互方案

初稿日期：2026-08-12

修订日期：2026-08-13

适用对象：ETP-R1 + LLM-Grid

本文是 04 号文件的收敛版本。实现时以本文为准：保留当前有效的编码器与导航主干，只替换 Try5 的单向地图融合模块，并在该位置增加直接、可训练的双向交互。

## 0. 一句话结论

完整方案只做三件事：

1. **视觉拓扑图更新认知地图**：全部 visited 节点作为上下文；本步新增的 visited 证据触发对整张认知地图的全局更新，并把更新后的状态保存到下一步。
2. **认知地图帮助 ghost 决策**：每个 ghost 从整张更新后的认知地图读取远处语义价值，但认知地图不生成新 ghost，也不修改拓扑边。
3. **两张地图联合建模执行进度**：预测五段路线进度、偏航状态和剩余路程；共享的进度表示进入 map→ghost 查询及 ghost/STOP 独立残差分支。

不采用：

- 事件链；
- 多套地图配准；
- 地图形变；
- 视觉拓扑节点与认知地图格子的绝对坐标对齐；
- 复杂的转移规划模块；
- 在线 LLM；
- 网格与 JSON 之间的来回转换；
- 对现有语言、RGB-D、panorama、拓扑图和认知地图 encoder 的结构改造。

## 1. 对问题 1：预训练和 DAgger 当前更新哪些参数

### 1.1 当前 Try5 预训练

当前 `scripts/submit/llm-grid-try5-pretrain.sh` 调用的配置中，`update_lang_bert=true`；optimizer 又直接收集 `model.named_parameters()`，没有建立“只训练融合模块”的白名单。因此当前预训练近似全量更新：

| 模块 | 当前是否更新 | 说明 |
|---|---:|---|
| 文本 embedding 与 12 层语言 encoder | 是 | `update_lang_bert=true` |
| RGB 特征投影、Depth 特征投影 | 是 | 输入是预先提取的特征，不是原始 CNN |
| panorama encoder | 是 | 属于预训练模型参数 |
| 拓扑图位置、step、task embedding | 是 | 属于 global map encoder |
| graph-language global encoder | 是 | MLM、SAP 都会经过该模块 |
| 当前 Try5 单向融合 | 是 | `graph_map_attention` |
| 当前 Map Encoder | 是 | 从缓存网格生成 101 个 token |
| MLM head | 仅 MLM batch 更新 | 任务相关 |
| SAP/action head | 仅 SAP batch 更新 | 任务相关 |
| RGB CLIP/Depth ResNet 原始 backbone | 不存在于该预训练图中 | 读取离线 RGB/Depth feature 文件 |
| 用于初始化地图类别的 CLIP 文本模型 | 否 | 只生成初始化值，不属于 Map Encoder 子模块 |

证据位置：

- optimizer：`pretrain_src/pretrain_src/optim/misc.py:14-45`；
- `update_lang_bert=true`：`pretrain_src/run_pt/mix_model_config_dep.json:31`；
- 预训练模块：`pretrain_src/pretrain_src/model/pretrain_cmt.py:95-177`；
- 离线 Depth 特征：`pretrain_src/run_pt/mix_pretrain_server.json:32-49`。

结论：**当前预训练并不是只训练 Map Encoder 和 Try5 fusion，而是大部分模型都会更新。**进入 optimizer 不代表每个任务的每个参数在每一步都有非零梯度，但总体上属于全量微调。

### 1.2 当前 LLM-Grid Try5 DAgger

当前配置为：

```text
freeze_base = False
fix_lang_embedding = False
fix_pano_embedding = False
```

所以 DAgger 也接近全量更新 policy：

| 模块 | 当前是否更新 |
|---|---:|
| 文本 embedding 与语言 encoder | 是 |
| panorama 的 RGB/Depth 投影与 pano encoder | 是 |
| Map Encoder | 是 |
| graph-language global encoder | 是 |
| Try5 fusion | 是 |
| graph-query-text、后处理与 SAP head | 是 |
| RGB CLIP encoder | 否，固定 |
| Depth ResNet encoder | 否，固定 |
| waypoint predictor | 否，固定且不在 policy optimizer 内 |

证据位置：

- optimizer 与 `requires_grad` 过滤：`vlnce_baselines/ss_trainer_ETP_PriorGT.py:270-314`；
- 默认 `freeze_base=False`：`vlnce_baselines/config/default.py:193-198`；
- language/panorama 开关：`run_r2r/iter_train.yaml:104-113`；
- 固定视觉 backbone：`vlnce_baselines/models/encoders/resnet_encoders.py:15-37,250-268`；
- 固定 waypoint：`vlnce_baselines/ss_trainer_ETP_PriorGT.py:249-267`。

### 1.3 本方案建议的参数更新方式

本方案**不建议继续让全部参数以同一学习率更新**。编码器结构保持原样；参数分为三组：

| 参数组 | 预训练 | DAgger | 原因 |
|---|---:|---:|---|
| RGB CLIP、Depth ResNet、waypoint predictor | 固定 | 固定 | 当前本来就是固定的 |
| 文本 embedding/language encoder | 固定 | 固定 | 保留已验证的指令表示 |
| panorama RGB/Depth projection 与 pano encoder | 固定 | 固定 | 保留已验证的视觉拓扑输入 |
| 现有 Map Encoder | `1×` | `0.1×` | 结构不改，但要适配初始缓存网格 |
| 现有 global graph-language encoder | 小学习率 | 小学习率 | 适配新交互输出 |
| graph-query-text、SAP/action head | 小学习率 | 小学习率 | 保留原决策路径，同时适配新增信号 |
| MLM head | 小学习率 | 不参与 | 保留原 MLM 任务 |
| 新双地图交互模块及辅助 head | `1×` | `1×` | DAgger 例外冻结 `VisualEvidenceHead` |

最终实现用显式 `online_fusion` optimizer profile 执行这个契约：新模块用 `1×`，既有后端用 `0.1×`，未命中白名单的前端不进入 optimizer。正式 DAgger launcher 固定使用该 profile，且 `freeze_base=False`。

## 2. 对问题 2：现有 encoder 是否需要变化

同意：**前面的 encoder 结构完全不动。**

保留以下现有路径：

```text
指令 → 当前 language encoder ─────────────────────────────┐
                                                          │
RGB + Depth → 当前 waypoint / panorama encoder → 拓扑图 ──┤
                                                          │
缓存认知网格 → 当前 Map Encoder → 101 个 map tokens ──────┘
```

保留以下现有模块：

- RGB CLIP encoder；
- Depth ResNet encoder；
- waypoint predictor；
- panorama image/depth embedding 与 pano encoder；
- language encoder；
- 当前 `EmbeddingGridMapEncoder`；
- GraphMap 的构建与 ghost 生成；
- global graph-language encoder；
- graph-query-text 与现有 SAP/action head。

唯一替换的是：

```text
GraphMapCrossAttention（拓扑图单向读取静态认知地图）
                         ↓
OnlineMapGraphFusion（拓扑图写地图 + 更新地图反哺 ghost）
```

准确位置位于图节点 embedding 已构造完成、进入 global graph-language encoder 之前：

- DAgger：`vlnce_baselines/models/etp_prior_gt/vilmodel_cmt.py:958-982`；
- 预训练：`pretrain_src/pretrain_src/model/vilmodel.py:787-816`；
- 当前 Try5 模块：`vlnce_baselines/models/etp_prior_gt/map_fusion.py:7-41`。

新模块中的“地图 → 拓扑图”分支只借鉴 Try5 的 attention 计算形式，不继承 Try5 fusion 权重。新交互模块整体重新初始化，并在本方案的预训练中学习。Try5 约 3% 的提升说明“地图供图节点读取”这一信息流有效，但 Try5 本身应保留为简单融合消融，而不是新模型的权重来源。

## 3. 对问题 3：为什么曾提出事件链，以及现在为什么删除

事件链原本想解决一个额外问题：LLM 可能预测对了“卧室—走廊—厨房”的顺序，却把绝对位置预测偏了，于是尝试把网格压缩为若干有序语义点再做匹配。

但它不是当前目标的必要条件，反而会增加：

- 网格到事件的抽取规则；
- 事件顺序标签；
- 视觉事件识别；
- 额外的匹配损失；
- 错误来源和调试成本。

考虑到 LLM 预测网格的绝对位置很可能有误，本方案既不抽取事件链，也不建立节点坐标到地图格子的硬映射。直接让认知地图 token 与全部 visited 图节点做全局 attention，由语义、指令和访问顺序学习如何更新。

## 4. 对问题 4：不再涉及 JSON 或在线 LLM

同意，并作为硬约束：

```text
预训练：缓存的 (37,100,100) 网格 → Map Encoder
DAgger：缓存的 (37,100,100) 网格 → Map Encoder
推理：缓存的 (37,100,100) 网格 → Map Encoder
```

这三个阶段都不加载 LLM，也不生成 JSON。

LLM 的作用已经在训练前完成：

```text
指令 → LLM 离线生成 JSON → 离线 rasterize → 缓存网格
```

这不是预训练或 DAgger 计算图的一部分。在线更新后的地图直接解码为 `(37,100,100)` 网格并计算网格损失，不再转回 JSON，不计算文本交叉熵。

## 5. 对问题 5：baseline 是否输入 Depth

**是，而且 Depth 在当前 baseline 中很重要。**

### 5.1 在线 DAgger/推理

配置明确开启 RGB 和 Depth：

- `run_r2r/r2r_vlnce.yaml:4-21`：启用 `RGB_SENSOR, DEPTH_SENSOR`；
- `run_r2r/iter_train.yaml:110-121`：`use_depth_embedding=True`。

Depth 有两条用途：

1. **候选点生成**：12 个方向的 Depth 经固定 Depth ResNet 提取特征，再进入 waypoint predictor。当前 waypoint predictor 中 RGB 分支被注释，实际使用 `vis_x = depth_x`，见 `vlnce_baselines/waypoint_pred/TRM_net.py:59-73`。因此 ghost/frontier 候选生成主要依赖 Depth。
2. **拓扑节点表示**：Depth 特征经过线性投影后与 RGB 特征相加，再经过 panorama encoder，最后写入 visited/ghost 图节点，见 `vlnce_baselines/models/etp/ETP_R1_vilmodel_cmt.py:897-928`。

Depth 不以原始深度图形式直接进入最终 action head，而是先参与 waypoint 和 panorama/graph 表示。

### 5.2 预训练

预训练也使用 Depth，只是使用已经提取好的 128 维 Depth 特征：

- `depth_feat_size=128`：`pretrain_src/run_pt/mix_model_config_dep.json:9`；
- feature 文件：`pretrain_src/img_features/ddppo_resnet50_depth_features.hdf5`。

所以新交互模块可直接使用当前 RGB-D 融合后的视觉节点特征，不需要增加或修改 Depth encoder。

## 6. 对问题 6：删除空间配准

此前的空间配准试图判断“某个拓扑节点对应认知地图中的哪一格”。但如果 LLM 的绝对位置本身不可靠，这种硬对应反而可能把正确视觉证据写到错误位置。

本方案完全忽略两张地图之间的绝对坐标对应：

```text
认知地图 token：保留自身 10×10 网格索引和内部布局
拓扑图节点：保留现有节点表示、访问顺序和节点类型
两者交互：只使用全局 attention，不使用 graph↔grid 坐标距离
```

因此本方案学习的是“视觉历史如何修订整张路线想象”，而不是声称某个视觉节点对某个绝对网格格子完成了精确校正。

## 7. 基本思想

### 7.1 拓扑图负责更新认知地图

初始认知地图是指令提供的先验；visited 节点是实际看见的证据。每一步用全部 visited 节点理解历史，用本步新增观测触发整张认知地图 token 的更新。

基本规则：

- 全部 visited：作为当前历史上下文；
- 新 visited：触发一次状态更新；
- 已消费 visited：可以被读取，但不能再次单独触发更新；
- ghost：只读地图，禁止向认知地图写证据；
- STOP：禁止向认知地图写证据；
- 没有新观测：地图状态保持不变。

### 7.2 认知地图负责给 ghost 提供长时程信息

ETP-R1 继续负责产生真实可执行的 ghost。认知地图不创造动作，只判断：每个 ghost 的视觉/语言表示与更新后的整张路线想象是否匹配。该读取同样不依赖 ghost 与地图格子的绝对坐标。

### 7.3 两图共同判断当前执行进度

visited 图说明“已经走过哪里、看见什么”，认知地图说明“整条指令预计还包含什么”。二者联合预测：

```text
phase 1～5（只在 on-route 时有效）
route state：on-route / off-route / finished
连续剩余进度 remaining ∈ [0,1]
off-route 状态下每个 ghost 的 recovery 分数
```

不把 phase/route/remaining 的预测值硬编码回动作头；共享的 `progress hidden` 同时条件化 map→ghost 查询、ghost residual 和独立 STOP residual，因此不是孤立的辅助任务。

## 8. 难点与直接解决方案

### 8.1 难点一：不使用坐标时，拓扑图如何更新整张地图

问题：无法可靠判断拓扑节点对应 LLM 网格中的哪一格，但仍希望视觉历史修订整张认知地图。

直接方案：让全部 100 个地图空间 token 查询全部 visited 节点，不加入 graph↔grid 坐标偏置：

```text
H_vis = 全部 visited 节点表示 + 访问步序 embedding + current/new 标记

C_t = CrossAttention(
        query = Z_{t-1} + P_grid,
        key/value = H_vis
      )
```

`P_grid` 只是认知网格内部的 `10×10` 索引 embedding，用于区分不同地图 token；它不表示该 token 与某个真实拓扑节点绝对对齐。所有地图 token 都可以读取所有 visited 信息，而 `new_visited` 标记决定本步是否推进地图状态。

### 8.2 难点二：视觉节点没有显式的 37 类地图语义

问题：当前拓扑节点是 768 维 RGB-D 表示，而认知地图有 37 个类别。

直接方案：在现有节点表示后增加一个轻量 `VisualEvidenceHead`：

```text
768-d 现有 panorama node feature（`gmap_img_fts`）
    → MLP
    → 37 类当前 panorama 语义 evidence
```

该输入位于 step/task/global-position embedding 和语言融合之前，避免辅助 head 利用访问步数、节点类型或位置作为语义捷径。

**该 head 在预训练阶段使用显式辅助监督。**利用 Habitat/MP3D 的 semantic 标注与 Depth，将每个训练 viewpoint 的 12-view panorama 转成 37 类多标签：当前视野中出现该类为 1，未出现为 0；用 class-balanced BCE/Focal loss 训练。预训练完成后冻结 `VisualEvidenceHead`；DAgger 不再启用 Semantic sensors，也不计算该项损失，但固定的 37 类预测仍参与地图更新。

当前 `data/online_fusion/panorama_semantics_v1.hdf5` 已生成，包含 10,567 个 viewpoint，每项为 `(37,) float32`。

需要明确：

- semantic/depth 只用于生成预训练 target；DAgger、验证和推理仍只输入现有 RGB-D 特征；
- “当前 panorama 没看见某类”只表示当前视野中不存在，不能直接解释为未来整张地图中不存在；
- 路径稀疏认知地图 GT 可提供弱正例，但其中的 0 不能拿来监督该视觉 head；
- 如果不愿生成 semantic target，就应将它改名为普通 `VisualProjection` 并仅靠导航 loss 端到端训练；此时不能声称其 37 维输出具有明确类别含义。

### 8.3 难点三：允许更新未来想象，同时避免整图失控

同意未来部分也应允许更新：已经观察到的区域、物体和路线状态，可能改变对后续未见区域的判断。因此不再强制“未观察 token 必须保持不变”。

直接方案：对整张地图做带门控的递归残差更新：

```text
C_t = CrossAttention(Z_{t-1} + P_grid, H_vis, H_vis)

Δ_t = FFN([Z_{t-1}, C_t, Z_{t-1}-C_t, Z_{t-1}⊙C_t])
g_t = sigmoid(MLP([Z_{t-1}, C_t]))       # 每个 token 一个写门

R_t = (1-g_t)·R_{t-1} + g_t·Δ_t
Z_t = Z_0 + R_t
Z_t = Z_t + MapSelfAttention(Z_t, instruction, predicted_progress)
```

- `Z_0` 是不可变的初始缓存地图表示，`R_t` 保存累计修订；
- 前 100 个空间 token 都可更新，第 101 个 metadata token 保持原样；
- 没有新 visited 证据时，强制 `R_t=R_{t-1}`；
- 通过小权重的残差范数、写门预算和 token 多样性约束防止整图被改成同一个向量；
- 不使用空间局部门控，也不要求未来 token 保持原值。

这里的全图变化是模型基于视觉历史产生的**新想象**，不是“未来已经被视觉证实”。

### 8.4 难点四：如何监督“更新后的认知地图”

问题：需要从 token 恢复网格，但不能转 JSON；现有 GT 又比较稀疏。

直接方案：增加轻量 `GridDecoder`：

```text
Z_t 的 100 个空间 token
    → reshape 为 (768,10,10)
    → 上采样卷积
    → (37,100,100) map logits
```

损失直接在网格上计算：

```text
L_grid = masked focal BCE + Dice
```

监督规则：

- 每个 prefix 都可以用完整认知地图 GT 的可信正值监督，让已访问信息学习修订未来想象；
- 负值只在数据定义明确可靠时参与监督；
- 不把稀疏 GT 中所有 0 都当负样本。
- 另加轻量 `L_anchor=||R_t||`、写门预算和 token 多样性损失，约束无依据的整图坍塌，但不禁止未来地图变化。

### 8.5 是否需要区分支持、想象和错误

当前方案去掉“未见想象/视觉支持/认知冲突/视觉新增”四分类 head、状态和监督。

原因是：不做 graph↔grid 坐标对齐后，无法可靠判断某条视觉证据支持或否定的是哪一个具体地图格；强行做四分类会产生伪标签，而且不是导航闭环所必需。

只记录三个无需额外标签的诊断量即可：地图相对 `Z_0` 的变化量、平均写门以及地图预测熵。它们用于检查模型是否过度改图，不进入主要网络目标。

### 8.6 难点六：单个 5 m token 如何提供长时程价值

问题：只读取 ghost 所在 token 仍然是局部信息，不能判断远处路线。

直接方案：每个 ghost 对**全部 100 个更新后地图 token**做一次 cross-attention：

```text
ghost query = Norm(ghost feature + instruction projection + progress projection)

h_g = CrossAttention(ghost query, Z_t, Z_t)

Δlogit_g = MLP([ghost feature, h_g, progress embedding])
```

这里不计算 ghost 与地图 token 的相对位置；attention 的 query 显式融合候选图节点、instruction pool 和 `progress hidden`，再从整张地图读取相关语义。地图条件化的**图 embedding 残差只写 ghost**；visited、padding 不变，STOP 不走该图残差，而由独立 `stop_residual_head` 修正 logit。

### 8.7 难点七：进度标签和偏航

问题：DAgger 中可能偏航或回退，进度并不总是单调。

直接方案：用指令、visited 图和更新后地图做注意力池化：

```text
h_progress = MLP([
  text-conditioned visited pooling,
  text-conditioned map pooling,
  current-node feature
])

phase_logits = Linear(h_progress)       # phase 1～5
route_state  = Linear(h_progress)       # on-route/off-route/finished
remaining    = Sigmoid(Linear(h_progress))
recovery_g   = MLP([h_progress, ghost_g])
```

训练标签由 expert path/GT trajectory 生成，但只作为 target。推理时 forward 不接收 GT 路径。

- `finished`：当前位置到目标距离 `<1.5 m`；
- `on-route`：非 finished，且当前位置到 GT reference path 的最近距离 `≤3 m`；
- `off-route`：该距离 `>3 m`；
- `phase`：仅 on-route 时根据最近且不早于历史进度的 GT path index 映射到五段；
- `recovery_g=1`：当前 off-route，且训练期估计 ghost `g` 的真实位置能让到 GT path 的距离至少下降 `0.25 m`，或直接回到 `≤3 m`；
- `None`：GT path 缺失、距离为无穷、跨楼层对应不可靠或没有有效 ghost。

因此，**off-route 不能整体等同于 None 或 recovery**：

- 对 phase/remaining head，off-route 时 target 设为 `None` 并 mask loss；
- 对 route-state head，它仍有明确的 `off-route` 标签；
- recovery 是候选动作标签，表示“这个 ghost 能把 agent 带回路线”，不是所有偏航状态的统一名称；
- 真正无法构造标签的 `None` 不是一个预测类别，只用于 `ignore_index=-100`。

当前 R2R 的 SPL teacher 选择“更接近目标”的 ghost，它不一定更接近 reference path。因此不能把 teacher action 自动标成 recovery；应根据每个 ghost 到 GT path 的距离单独计算 recovery target。

- expert/on-route prefix：监督 phase 和连续进度，可加软单调约束；
- off-route prefix：只监督 route state 与 recovery ghost，mask phase/remaining；
- `progress embedding` 输入 ghost head；
- `finished` 通过零初始化残差修正 STOP logit。

## 10. 损失函数

OnlineFusion 共定义 6 项辅助损失：`grid/state/visual/progress/recovery/ghost`。`recovery` 是候选动作级任务，不再合并进 `progress`。

### 10.1 预训练

保留当前 MLM 和 SAP：

```text
L_pretrain = L_MLM
           + L_SAP
           + λ_grid L_grid
           + λ_state L_state
           + λ_visual L_visual_evidence
           + λ_progress L_progress
           + λ_recovery L_recovery
           + λ_ghost L_ghost_rank
```

- `L_grid`：可信标签上的 focal BCE + Dice，允许监督整张未来地图；
- `L_state`：无新证据时严格不变 + 小权重残差/写门预算 + token 多样性；
- `L_visual_evidence`：当前 panorama 的 37 类多标签 BCE/Focal；
- `L_progress`：phase CE、route-state CE 和 remaining SmoothL1；
- `L_recovery`：仅对 off-route 且具有可靠位置的 ghost 做类别平衡 BCE；
- `L_ghost_rank`：expert ghost 的分数应高于其他 ghost。

### 10.2 DAgger

```text
L_DAgger = L_action
          + λ_grid L_grid
          + λ_state L_state
          + λ_progress L_progress
          + λ_recovery L_recovery
          + λ_ghost L_ghost_rank
```

`L_action` 仍是当前 teacher action loss。所有辅助损失按有效 episode、有效像素或有效 ghost 数归一化，避免长 episode 获得更大的隐式权重。

建议初始权重：

```text
λ_grid=0.3
λ_state=0.05
λ_visual=0.2（仅预训练；DAgger 为 0）
λ_progress=0.1
λ_recovery=0.1
λ_ghost=0.1
```

具体数值根据梯度量级调整，但不引入 JSON loss。

## 11. 训练 pipeline

### 11.1 预训练输入

从当前基础 checkpoint 初始化：

```text
pretrained/r2r_rxr_ce/mlm.sap_habitat_depth/store2/model_step_367500.pt
```

该基础 checkpoint 只允许缺少明确新增的 Map Encoder/OnlineFusion 子树；其余键和 shape 必须匹配。若 checkpoint 中已出现任一子树，该子树必须完整严格加载，不允许部分继承。

保持当前输入：

- instruction；
- 离线 RGB feature；
- 离线 Depth feature；
- 拓扑路径及图位置特征；
- 已缓存 LLM-Grid；
- MLM/SAP 标签。

新增训练字段：

- visited 节点的时间顺序；
- `new_visited_mask`；
- 训练期离线生成的 viewpoint 37 类语义标签；
- 训练专用网格有效 mask；
- phase、route-state、remaining 标签；
- 每个 ghost 的 recovery 与 teacher 排序标签。

这里不调用 LLM，不读写 JSON。

### 11.2 预训练前向

对每条训练路径的 prefix：

```text
1. 缓存网格经现有 Map Encoder 得到 Z0
2. 现有 RGB-D/panorama encoder 得到各 visited 节点表示
3. VisualEvidenceHead 预测每个 visited panorama 的 37 类语义
4. 全部 visited 节点全局更新整张地图；new evidence 触发 Z_{t-1} → Z_t
5. GridDecoder 从 Z_t 解码更新后网格
6. ProgressHead 预测 phase、route state 和 remaining
7. RecoveryHead 独立预测 off-route 时的逐 ghost 恢复候选
8. 候选图节点加上 instruction/progress 查询更新地图；只为 ghost 写图 embedding 残差
9. 进入现有 global encoder 与 MLM/SAP head，再向 SAP logits 加入独立 ghost/STOP residual
10. 联合计算原任务与 6 项 OnlineFusion 辅助损失
```

完整交互模块从本次预训练一开始就参与训练；不存在先训练简化结构、之后再增加复杂模块的问题。

### 11.3 预训练参数组

```text
固定：
  language embedding/encoder
  panorama 前端 encoder

1× LR：
  Existing Map Encoder
  VisualEvidenceHead
  GlobalMapUpdater
  GridDecoder
  ProgressHead
  RecoveryHead
  GhostLongRangeRead

0.1× LR：
  existing global graph-language encoder
  graph-query-text / MLM / SAP heads
```

预训练 optimizer 应显式过滤 `requires_grad`，并打印每组参数名与参数量；不能沿用当前不分组的 `build_optimizer()`。

### 11.4 DAgger 每一步

```text
episode 开始：
  读取缓存网格 → Existing Map Encoder → Z0
  初始化 map residual 与 consumed-view 集合

每一步：
  1. 按当前 ETP-R1 流程读取 RGB-D
  2. 按当前 waypoint 流程产生 ghost
  3. 按当前 panorama/GraphMap 流程更新视觉拓扑图
  4. 若当前观测是新证据，用全部 visited 节点全局更新 Z_{t-1} → Z_t
  5. 预测 phase、route state 和 remaining，并独立预测 recovery
  6. 所有 ghost 用 instruction/progress 条件化 query 从 Z_t 读取全图长时程价值，仅向 ghost 写图 embedding 残差
  7. 使用现有 global graph-language encoder 与 SAP head
  8. 在原 logits 上分别加 ghost/STOP residual
  9. 按现有 DAgger 混合策略执行动作

episode 结束：
  清空该环境的 Z_t、map residual 和 consumed-view 集合
```

并行环境 pause/reorder 时，`Z_t` 等状态必须与 `GraphMap` 使用同一索引一起调整。

### 11.5 DAgger 参数组

```text
固定：
  RGB CLIP / Depth ResNet / waypoint predictor
  language embedding/encoder
  panorama 前端 encoder
  预训练完成后的 VisualEvidenceHead

0.1× LR：
  Existing Map Encoder
  Existing global graph-language encoder
  graph-query-text / SAP head

1× LR：
  除 VisualEvidenceHead 外的新交互、地图更新、进度、recovery 和 ghost 模块
```

DAgger 必须从本方案的完整预训练 checkpoint 初始化，并启用 `require_complete_pretrained_modules=True`：完整 VLN-BERT、Map Encoder 和 OnlineFusion 子树的 missing/unexpected/shape mismatch 都必须报错。

### 11.6 验证/推理

验证和推理只允许使用：

- instruction；
- 当前与历史 RGB-D；
- 已执行动作和已构建图；
- 当前 episode 的缓存认知网格；
- 模型自己维护的在线状态。

不允许使用：

- 认知地图 GT；
- GT trajectory；
- 未来观察；
- simulator semantic labels；
- 在线 LLM/JSON。

## 13. 首轮主实验与之后的消融

首轮直接训练并评估上述完整方案：

```text
ETP-R1
Try5 + static LLM-Grid
OnlineFusion + LLM-Grid（完整方案）
```

完整方案先回答一个问题：

> “视觉拓扑图持续修正认知地图，并让修正后的地图直接帮助 ghost 和 STOP，能否稳定超过静态 Try5？”

确认有效后再做消融：

1. 关闭 graph→map update；
2. 关闭 grid loss；
3. 关闭 progress 输入，仅保留辅助 loss；
4. 关闭 ghost long-range residual；
5. 预训练 VisualEvidenceHead 显式语义监督 vs 无语义预训练；
6. 固定 encoder vs 小学习率更新 encoder；
7. Try5 静态单向读取 vs 全局双向递归更新；
8. 持久化地图 vs 每一步从 `Z0` 重新计算。

## 14. 最终方案摘要

本方案不再试图一次解决地图整体形变、复杂规划或 LLM 再生成问题，而是把当前研究目标落实为三个直接的信息流：

```text
new visited RGB-D evidence
        → 结合全部 visited 历史，全局、持久地更新 cognitive map tokens

updated cognitive map + instruction + progress hidden
        → 为现有 ghost 读取整图长时程价值

visited graph + updated cognitive map + instruction
        → 预测 phase、on/off-route、finished 和 remaining
        → 独立预测 recovery，仅为 ghost 写图残差
        → 用独立 residual head 修正 ghost 与 STOP logits
```

这样既保留 ETP-R1 和当前 LLM-Grid Try5 已验证的编码与决策结构，又把研究重点集中在后端的双向融合、在线地图更新和长时程 frontier 决策上。
