# 研究 IDEA 重审：状态外置的 Agentic 导航

评审日期 2026-09-24。对象：`03_research_proposal.md`（下称 03）及其依据 `02_p0_paper_notes.md` 第八至十节（下称 02），任务书 04–06 与报告 07–08。整合了九个视角的批评与 41 条经对抗核验的发现（F01–F30 经核验，F31–F41 未核验，单列）。外部文献只看到检索摘要，未读全文，凡引用处均标明。

## 0. 一句话结论

IDEA 值得做，但不能按现在的命题做。"agentic 导航把控制权交给模型、把任务状态留在上下文"这一诊断有跨论文证据（02 §十.1 表）与 MIP 失败审计（02 §八）支撑，E0 的预注册证伪设计和任务 #1/#2 的工程基础是真实资产；但提案把病因写成"上下文只能追加不能修改"（03 §一"诊断"），而它自己引用的证据（15/30 已在上下文中写出正确怀疑、HAM-VLN 13.6% 自愿回溯）指向的是另一件事：缺少一个把怀疑接住并强制变成决策、并对完成/承诺声明做独立验证的控制层。方法规格 v0 中真正独有的只有"承诺登记为带备选的可撤销假设 + 矛盾触发的强制 defend/revise"，而这两个机制按 v0 规格在 MIP 主要失败类型（A/C 类，20/30）上大概率不会触发（satisfy 逐句放行并重置 R1 预算，单帧验证器无法验证"走过/进入"）。最大单一风险：E0 按 06 T3.5 的实现（GT oracle 以 [ORACLE] 文本行追加进上下文、且不含 O-承诺）跑出来后，无论结果是什么都回不到"载体"主张上，1,400 集额度换来一个已知答案。命题、E0 设计与方法规格三处必须在任务 #3 执行前改。

## 1. 总体判断

**站得住的。** (1) 实验床：MIP 冻结协议 + rand100 与 Open-Nav/SmartWay/AgenticNav/C²Nav 共用子集（02 §八"协议"、07 B2），让"固定模型只变 harness"第一次可复现。(2) 三个硬事实：23/30 假成功且信心与终距无关（02 §八失败分析结论 3）；15/30 说出正确怀疑却不行动；20/30 绑定后永不回溯。这些是行为层观察，不依赖任何解释。(3) 诊断方法论：02 §十.1 用"引言声称 vs 自身消融指向"逐篇对照，三种状态是从证据里长出来的。(4) E0 的预注册证伪写法与 §10.3 的冻结配置要求，在 harness 类工作里少见。(5) 工程：08 报告 FGR2R→rand100 命中 100/100、reference_path 同序一一对应、R1/R5/R6 在 1,839 条 GT 上误报 <5%，且否决了 k×length_m 这类 GT 泄漏预算（00 §5）。

**站不住的。** (1) E0 测的是"完美 GT 信息值多少"而非"状态从上下文移到 harness 值多少"，证伪线 <75 几乎不可能触发，且提案认定最大的分量 O-承诺在 06 T3.5 的 all 里缺席（F01、F05）。(2) 提案的动机前提"推理侧干预不起作用"（03 §一问题 2）被目标模型自身击穿：fable-5 max effort 68.3→78（02 §八 Table 3），E1 目标 78 与它相同，E0 阈值 75 低于它，主表没有 max-effort 行（F04）。(3) "状态侧 ≥10 vs 推理侧 ≤6"是跨任务、跨模型、去除消融与新增消融混排的拼表，最大项 ARNA −67 是拆占据栅格，而提案明确不做度量建图（F09）。(4) 矛盾触发在 A/C 类上不响，独立验证器未指定、未校准、无 GPU，承诺账本 commit 完全自愿（F02、F14、F20）。(5) 判定阈值在 2/3/4/5 点间漂移，rand100×3 的 SE 约 1–2 点，主结果与关键消融落在噪声内（F03）。(6) 路线：06 把实验押在 Claude 订阅 + harness=cc，而 cc 按构造保留全转录并自动压缩，"模型只读 600 token 状态"在 cc 下做不出来，03 §五/§10.5 仍按 API/mini 写（F07）；约 7,700–9,000 集的规模与无 key、GPU 全占、一集未跑的现状不匹配（F08）。(7) 新颖性：C²Nav（2609.15142）已在同一 rand100 协议上把"承诺前比较备选 + 子指令段假设 + 可撤销回退"做成标题级主张，GPT-5.5 得 44，低于 MIP 最小接口的 52；GPT-6-Astra 工作流（2609.20116）已在同子集做了代码验证进度与停止；Navi-Agent（2609.20388）已做 RGB-only 无里程计的零样本 VLN-CE；均不在 49 篇清单（F06、F23、F25）。

**决定成败的三件事。** 第一，把命题从"状态载体"改为"矛盾触发的强制决策 + 独立验证是 agentic 导航缺失的控制原语"，三账本降为让矛盾可计算的实现；这一改动由提案自己的 E2 第 2、4 项决定，若不先改，结果出来后标题会被自己的消融否定（F10）。第二，在花任何额度之前，用 MIP 附录 C 30 例或合成错分支轨迹离线回放 R1–R6，得到失败轨迹上的真阳性率；A 类召回 <50% 就必须把触发器从统计阈值改为验证器驱动（F02）。第三，先答"cc 能否每步无状态"，据此决定申请 API key 还是把方法降级为"状态作为工具返回值 + 全转录"并如实改写贡献（F07）。

### 3.1 [阻断] E0 检验不了它要证伪的主张，且最关键分量缺席 [F01, F05, F18]

**问题。** 03 §一末句把 oracle 实验当作对"状态载体"主张的证伪，但 E0 的实现（06 T3.5）是把 GT 进度/偏离/占据图作为 [ORACLE] 文本行"每次 step() 的返回文本末尾追加一行"，briefing 声明"always correct"。这与被批评的"状态留在上下文里"是同一种载体。E0 因此只能回答"完美信息能涨多少"（感知/估计问题）。O-全部涨了，与"模型进度估计差"完全相容；不涨，02 §十.7 已预设解释为"瓶颈在推理"。两个方向都不触及载体。给强模型每步一个正确的"你在第几句 + 是否偏离 + GT 占据图"几乎必然 ≥85，证伪线形同虚设。

分量也不可分离：O-进度由 `common.py` locate()（第 217–228 行）把位置投影到 GT 折线取弧长并单调化，走错分支时 idx 冻结，信息上近似包含 O-偏离；O-空间是完整占据图，测的是建图价值，与 03 §一"AgenticNav 地图 + recall 仅 +3"的论点打架；rand100 有 54/100 集末子句零长度（08 T2.2），O-进度在终点 0.5 m 内播报 stop 子句文本，等价于停止 oracle，B 类失败会被它直接修复但这不是"进度状态"。

O-承诺三处定义不一致且未实现：03 §五 E0 表写"正确实例在图中标记"；03 §10.1 写"commit 时把模型选择的像素/方向用 GT 深度反投影"，前提是存在 commit 工具，而 E0 明确"在最小接口上分别只注入一项 oracle，其余不变"；06 T3.5 的 all 只含 progress/spatial/offtrack，T3.6"只做调研，不实现"，并自认"最小接口下智能体不会显式声明绑定"。而 03 §一把承诺状态定为"最大的失败来源（MIP A+C = 20/30）"。07 A5 显示 MP3D 每 scan 只有 .glb + .navmesh，T3.6(a) 语义标注法的数据基础未验证。

阈值无锚：§一"不能接近 94"、§五"≥85 / <75"、02 §十.7"75 以下"，75–85 区间无定义；75 相对 72 基线仅 +3，落在 §10.3 自己"<5 点只作描述"的范围内。人类 94 是单一测试者，且人类的进度/空间/承诺全在脑内，若它说明什么，是"足够好的内部状态追踪就够"，支持"模型能力"而非"外置载体"（03 §四把"人类 94"列在"LLM 作观测模型而非状态载体"一行，是不充分推论）。

**影响。** E0 是 go/no-go 且承载 C1"不依赖方法成功"的保底贡献。一个不能失败的实验不构成证据；三项 all <75 无法区分"主张错"与"最关键分量没喂"；≥85 又是在无承诺 oracle 下达成，反过来削弱承诺账本的必要性。E0 通过后与 E1 的差距会全部归因于验证器质量，回到感知问题。

**建议。** (1) 保留 GT oracle 作天花板，增加两臂："可达 oracle"= 只注入 harness 无 GT 也能算出的信号（R1/R5/R6 触发 + 验证器子句状态），这是方法的真实上界；"噪声/延迟 oracle"= 动态 idx 以准确率 p∈{1.0,0.9,0.8,0.7}、延迟 k∈{0,3,6} 步注入，画 SR–p 曲线，得到 harness 自身估计必须达到的准确率。(2) 载体对照：同一 oracle 信息分别以"追加到转录"与"替换式状态摘要（无转录）"两种载体给出，差异才是对载体假说的检验。(3) 分离信息源：O-进度拆为静态子句切分与动态 idx 两档；O-空间改为 harness 可算的"已访问锚点 + 未探出口计数/航位推算轨迹图"，完整地图单列为感知上界；增加屏蔽末子句零长度转移（或距终点 >3 m 才播报）的变体；增加随机/恒真的无 GT 对照 oracle。(4) O-承诺在 E0 前二选一：按 T3.6(b) 分支偏离法定义为最小接口可注入的二值信号（拐点视点处航向与 GT 下一段切向夹角 >45° 且前进 ≥1 m 触发），all 定义为四项；或明确 E0 v1 不含承诺，证伪判据改写为分层。无论哪种，03 §五、§10.1、06 T3.5 三处同一份定义。(5) 判据改相对量：O-全部 ≥ max-effort + 5（≥83，CI 不含 78）；E0 三档（≥85 强成立 / 75–85 部分成立按分量解释 / <75 不成立）；人类 94 只用作"接口不阻止高成功率"的存在性证据。章节开头声明"oracle 条件是上界诊断，O-承诺与 O-偏离使用 GT，收益不可外推"。

### 3.2 [阻断] 核心机制在主要失败类型上不会触发；验证器是承重墙却未指定；承诺账本空心 [F02, F14, F20, F27]

**问题。** 03 §9.3 satisfy 行："独立验证查询通过 → satisfied、下一句 active、预算重置"；§9.5 验证器输入只有"(子句文本, 证据图)"，输出 {landmark_visible, room_type, clause_satisfied}。单帧只能证明地标可见，不能证明"走过了水槽"或"进了卧室"，这正是 NavGPT Fig.10 与 MIP ep56 的失败形态。错误分支之所以被选中，正因为它对后续子句也有貌似合理的匹配（A 类错误指代）。于是模型在错误分支上逐句 satisfy、验证器逐句放行、每次放行把 R1 的 used.dist 清零；R1 预算 P99 为 move 10.9 m（中位子句 2.5 m，08 T2.4），在 A 类中位终距 17.3 m 的失败上永远达不到；R2 只约束顺序。逐案：ep56（门口推理"在 3 m 内"又走 7 m）R1/R5/R6 全不响；ep79（首帧两候选选错）需要模型自愿 commit 登记备选，此后错误分支上 satisfy 通过则 R1 重置。

校准与规格脱节：§9.4 R1 仍写 P90，08 采用 P99（P90 误报 31%）；R6 校准按"GT 前进步位置、间隔 10 步"（t25_rules.py:41–56），规格却是"同一子句下已访问锚点 1 m 内"；R1 校准在 FGR2R 人工子句上，运行时子句由 LLM 解析（"make a hard left"被归 move，08 T2.2）；R5 误报 32/36 在"过短"侧，对 B 类过冲无用；参数在 val_unseen 上按"<5% 最紧一档"选，选参集与报告集相同。误报校准对象是 GT 最短路，成功轨迹更长，真实误报更高。T2.6 召回 SKIP，六条规则没有一条在失败轨迹上测过命中率。

验证器：satisfy、R3、R4、defend 全由"一次单独的、无历史的 VLM 调用"判定，"可用开源 8B 级"（§9.5）。单帧回答 clause_satisfied 就是子指令 grounding，VLN 最难的部分；偏松则 satisfy 退化为自报（回到 HAM-VLN），偏严则卡子句、R1 误触发，假阴性直接制造 R3/R4 矛盾 → 强制复核 → 回溯，是震荡主源。贡献 (3) 声称"不能归因于检测器或接地模型"，但 8B VLM 回答 landmark_visible 与 GroundingDINO 的差别不是原则性的。§三 C2"不增加推理预算"与 R3"commit 后连续 M=3 次独立验证"（承诺活跃期每步调验证器）、§9.7 解析调用、复核回合直接冲突；MIP 200 次调用/episode，规格没说验证器是否计入。验证器测试集（FGR2R 子句–视点对）只有正样本，测不出误放行率。08 T2.5"R3/R4 需要视觉验证器，本任务不做"。硬件：07 §0 "8×4090 全被训练作业占用"、C3"无 vllm、无 Qwen 权重"；03 §五"本地 GPU 只在 27B 时需要"与 §9.5/§10.4"验证器本地跑"矛盾。"独立上下文不会被确认偏差污染"是断言无证据。

承诺账本：§9.3 commit 前置只有"clause 为 active；evidence 含当前 obs"，无规则要求在分支点必须 commit；alternatives 可填 none_visible；06 T3.6 自认强模型在最小接口下本就不声明绑定，账本很可能长期为空。§二"把最近一个有存活备选的承诺呈给模型"，无承诺或备选为空时怎么办规格没写。§9.6 置信"唯一用途是 E5 的校准评估，不参与决策"，即矛盾触发前备选对导航零影响，触发后只是给模型看缩略图，与 HarnessVLN 失败注解节点 + backtrack、HAM-VLN 失败笔记功能同类，只是登记时机提前。defend 通过条件是验证器"通过"，A 类是"同类的错误实例"，错误实例上地标当然可见，defend 必过并把预算延长 50%（move → 16.4 m），第二次复核才强制 revise，届时已接近 A 类中位终距。

### 3.8 [重要] 校准指标按现定义即使方法无效也会改善 [F15]

**问题。** 03 §五指标"静默失败率（失败中声称成功的比例，基线 23/30）；置信–终距 Spearman"，E1 判据"从 77% 降到 30% 以下；相关从接近 0 升到 0.5 以上"。MIP 的"声称成功"来自模型自主 STOP 时的推理文本；本方案 request_stop 被 F_stop 门控（§9.3），未通过返回未满足项，模型无法"声称成功"，未通过而耗尽预算的失败会被计为"未声称"，静默失败率在定义上下降。§9.6 conf(c) = (1+verif_agree)/(1+verif_agree+|alternatives|+2·contradictions)，verif_agree 何时递增全文未定义（grep 仅出现在 §9.2 与 §9.6），|alternatives| 由模型自报，contradictions 主要来自 R1/R6：备选越多、承诺越多、走得越远绕得越多，置信越低，而 NE 也随路径长度与杂乱度上升，Spearman 正相关可完全由"已走距离"混杂产生；E5 没设这个平凡基线。基线的"信心与终距无关"是定性观察（02 §八"信心表述几乎相同"），两边测的对象不同；短指令无承诺时 conf 恒为 1；"从接近 0 升到 0.5"未说样本集合与成功 episode 的 NE 截尾。

**建议。** 静默失败率分子改为"模型第一次调用 request_stop 时到目标 >3 m"（不论 harness 是否放行），同时报"预算耗尽且从未 request_stop"比例；所有臂在 request_stop/STOP 处统一要求模型输出 0–100 数值信心作"模型校准"指标，harness conf 单独报；两者都报 Spearman、ECE/Brier 与 conf=1 占比；E5 加"已走总路程"与"已用步数"两个基线预测器，报三者 Spearman 与 AUROC，只有 conf 显著优于两者才写入贡献；对置信与 NE 做偏相关控制子句数与路径长度；明确 Spearman 样本集合（全部 episode，NE 不截尾）；写清 verif_agree 递增条件；"校准"改为"置信–终距 Spearman ≥ 0.5"。

## 4. 创新性判断

**内部先行工作（文档已覆盖）。** 03 §八已诚实收缩两次："把状态放在模型外"不再是贡献（HAM-VLN、HarnessVLN、SpaceVLN）；"零样本视觉导航是信念瓶颈路线尚未触及的地方"不再成立。剩余三条边界中：证据门控 satisfy 与三项验证停止是 HarnessVLN 已有（03 §二"继承 HarnessVLN 的 F_stop"、02 A5 completed 需位姿对齐观测、派发前验证）；"只读状态不读转录"是 BSE/Agent-BRACE/HAM-VLN（上下文 −65%）已有；RGB-only 是设定。真正剩下的是承诺作为带备选的假设、矛盾触发的强制 defend/revise。

## 5. 建议的定位与工作思路

**推荐框架：受控实验论文，"矛盾触发的强制决策与独立验证是 agentic 导航缺失的控制原语"。** 理由：(1) 它是提案自己的证据真正支持的命题（15/30 说出怀疑不行动、23/30 假成功、HAM-VLN 13.6% 自愿回溯），而"状态载体"命题会被自己的 E2-2/E2-4 消融拆开（3.4）。(2) 它把三账本降为让矛盾可计算的实现，避开与 HAM-VLN/HarnessVLN/RegenHarness/C²Nav 在"状态外置"名义层的正面碰撞，并把 C²Nav 44 < 52 从威胁变成要解释的现象（显式承诺 + 自愿回溯不够，需要强制 + 验证）。(3) 它与 03 §七已有定位"这不是一个新的导航系统，是一个关于『LLM 智能体里什么必须在模型之外』的受控实验"一致。(4) 它在订阅额度下可负担：最小判别实验只需三臂（最小接口 / 同文本可忽略提示 / 强制 defend-revise），复用任务 #2 的全部校准、E2-2 与 E5 审计。适合 NeurIPS（含 D&B）或 CoRL 类分析论文；完整方法论文（CVPR/AAAI）等 E1 在全量上拿到有 CI 的 ≥5 点再谈。

**备选一：分析型论文"诊断 + 最小干预"。** E0 三个 oracle + 可达 oracle + 噪声曲线 + O-承诺定义 + SR–上下文预算曲线 + 2–3 个模型的失败审计与校准 + 仅承诺账本/强制修订的最小方法。若 E1 主结果不达 5 点，这是退路，前提是 E0 按第 6 节重做，否则 C1 也缩水。

**备选二：RxR-CE 主表。** 若 E3 的零费用检查（RxR end_reason 分布）与 100 集三次重复显示效应集中在长时程，主表改 RxR-CE，R2R rand100 只作对齐表。这是胜算最高但竞争数字（HAM-VLN 52.7、HarnessVLN 53.9）也最高的路线，需 RxR 侧 oracle 与规则校准前置。

**主结果表必须的样子。** 行：MIP-min / +max-effort / hybrid / +AgenticNav 工具（引用 MIP +3）/ (c1) agent-authored 变体（HAM-VLN 式，同代码开关）/ (c2) harness 验证不强制（HarnessVLN 式，同代码开关）/ ours-min（强制门）/ ours-min 换同文本可忽略提示 / ours-min + GT 子句 / ours 完整版。列：全量 val_unseen（或 ≥500 集预注册分层子集）SR·SPL·OSR·NE·nDTW（配对 bootstrap CI）、A1/A2/B/C/D 失败计数（盲标）、静默失败率（新定义）、置信–终距 Spearman（对照路程基线）、主模型调用 / 验证器调用 / 总 token、末次调用 token、壁钟、复核触发次数与 defend/revise 比例。两个模型（前沿 + 一个可达的开源臂）。同一时间窗、同一 harness、同一 CLI 版本。
