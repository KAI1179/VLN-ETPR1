## 问题与需要人决定的事

1. **子句起点容差**：任务书原规则（0 m）的终点命中率只有 64%，采用 0.5 m 后为 100%。是否接受 0.5 m 作为 `current_clause` 的正式定义？
   备选方案：只对"最后一个零长度子句"放宽，其余子句保持 0 m。
2. **R1 的预算形式**：分位数预算只有 P99 达标，而 P99 很宽松（例如 move 10.9 m），对真实失败的敏感度未知。备选方案有两种：
   预算 = max(类型分位数, k × 本子句 length_m)，或按前进步数计。需要 T2.6 类的失败数据才能比较，这要等 API 可用。
3. **R5 的"过短"误报**集中在短路径：是否改为只检查"过长"一侧，或把下界改为绝对值（例如 < 3 m 才报）？
4. **FGR2R 覆盖缺口**：train 有 10 条第 4 条指令没有子句标注，目前直接跳过（占 0.09%）。是否可以接受？
5. **关键词分类**：move 占 43%，其中包含 "make a hard left" 这类实际是转向的子句。是否把 left/right 加入 turn 规则？这会改变 R1 的类型预算。
