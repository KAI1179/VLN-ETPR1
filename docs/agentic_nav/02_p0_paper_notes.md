## 二、逐篇归纳：路线 A（工具调用 harness）

### A1 AgenticNav — 零样本 VLN-CE 作为工具调用 harness

**Motivation.** 现有零样本 VLN-CE（Open-Nav、SmartWay、EvoNav）都依赖训练好的航点预测器，带来三个瓶颈：动作空间被限制在少量候选点；深度只进预测器不给 VLM；记忆靠堆历史或跨 episode 检索，后者破坏零样本设定。作者把问题定义为「接口问题」：VLM 能推理，但机器人要和空间交互。

**Method.** 四个工具 {query\_depth, recall, move\_to, stop}。move\_to 让 VLM 直接选 RGB 像素，工具做深度反投影 + 几何安全检查（身高范围点是否落在扫掠走廊内），不安全则返回 Reselect。query\_depth 返回像素深度、5×5 邻域统计和「若执行会转多少度、走多远」的动作预览。记忆是一张带节点编号的轨迹地图图片，recall(p, k) 按需取回某节点某视角的 RGB。

**Highlight.**

- 消融最有信息量：去掉 Depth Tool SR 从 55 掉到 42，而直接喂深度图只恢复到 53——说明**结构化点查询比整张深度图更适合 VLM**；去掉整套记忆掉到 41，只留地图不留 recall 是 51。
- backbone 消融：GPT-5.5 55、Gemini-3-Flash 54、Qwen3.6-27B 35 但 OSR 64——弱模型能找到目标区域，弱在停止和路径效率。
- 真机 4 视角 SR 46.7 vs SmartWay 12 视角 23.3；室外院子差距最大（42.9 vs 14.3）。

**局限与可乘之机.** 失败分析：仿真 88.9%、真机 71.4% 的失败来自 VLM 决策本身（含 oracle 成功但没停）。作者只提了「蒸馏进小模型」。没做的事：工具调用序列本身没有任何学习信号；safety check 是硬规则；只有 100 episodes。

### A2 ARNA — LVLM 编排的通用导航栈

**Motivation.** 传统机器人栈是固定工作流 π\_fixed；先前 LVLM 集成靠简化参数化（JSON 场景图、启发式选图）和稀疏动作空间，决策短视且脆弱，还浪费了现代机器人栈已有的能力。目标是让 LVLM 在运行时自己生成任务相关工作流 π\_task。

**Method.** 智能体定义为元组 (S, Γ, L, Π, M, T)：机器人栈 S、工具接口 Γ、LVLM L、工作流空间 Π、记忆 M、任务 T。工具分感知（get\_images、query\_scene\_graph）、推理（最短路、可见性、可达性，以及 LVLM 自己生成的函数如 is\_backpack\_near\_sofa）、导航（goto、follow\_path、explore\_frontiers）。工作流生成用改造的 self-discover：选启发式 → 适配任务 → 写伪代码 → 用工具 + if/while 实现。记忆是文本描述 + 带地标标注的占用栅格，除动作日志外全由 LVLM 自己维护。

**Highlight.**

- HM-EQA 正确率 77%，路径 16.55 m，对比 EuC-GPT-4o 61% / 175.91 m；但 token 消耗 673k，是 EuC 的 16 倍。
- 消融：去掉所有栅格表示（NoRP）正确率从 77 掉到 10，去掉工作流生成只用 CoT 掉到 7——**结构化工作流生成和视觉栅格是两个不可缺的部件**。
- 是唯一在文中明确说「机器人领域 agentic 方法几乎没有，此前只有 Code-as-Policies」的论文。

**局限与可乘之机.** 每个任务 30–60 分钟、1–3 美元；GPT-4o-mini 跑不通；无计划验证与重规划（作者试过在线改写工作流，无收益且更慢）；RxR-CE 30 episodes 只有 12% SR。记忆表示的验证被列为未来工作。

### A3 ReasonNav — 会读路牌、会问路的 VLM 智能体

**Motivation.** 人造环境本身携带导航知识（指示牌、房间号规律、可以问人），现有机器人导航系统用不上这些资源，在大建筑里只能盲目探索。目标是把这些「高阶导航技能」统一进一个 VLM 智能体框架。

**Method.** 双流：低层 SLAM + 开放词汇检测（NanoOWL，三个标签 door / person / directions sign）+ Nav2 规划；高层 VLM 只看两样东西——JSON 地标记忆库（门附房号、人附问路笔记、路牌附各方向房号区间、前沿点）和带编号的俯视图，输出下一个要去的地标索引。每类地标绑定一个行为原语：去前沿并 360° 扫描、靠近门读房号、靠近人用 TTS/STT 问路并让 VLM 写「给未来自己的笔记」（强制用地图全局方位而非左右）、读路牌并按箭头方向分桶。

**Highlight.**

- 去掉路牌/问人技能，真机 SR 从 58.3 掉到 8.3；去掉俯视图掉到 16.6——**输入输出抽象设计比模型本身更决定成败**。
- 自建 Isaac Sim 医院基准（30+ 房间、路牌、11 个 NPC 各有不同知识库），是目前唯一能评测「利用环境知识资源」的仿真环境。
- 无 VLM 的最近/随机地标基线 35.7 / 28.6，去掉 JSON 记忆则 0（反复选已访问地标）。

**局限与可乘之机.** 真机失败首因是检测（海报被当成路牌，33.3% + 26.7%），仿真首因是 Nav2 规划（28.57%）；VLM 只看地标看不到原图，信息利用不充分；只能选前沿不能选近处航点；不处理会走开的行人。样本极小（12 + 14 次）。

### A5 HarnessVLN — 统一指令跟随与 ObjectNav 的 Agent Harness

**Motivation.** 现有 MLLM 导航系统里模型只是流水线中的规划器，证据保留、提案验证、失败处理没有统一机制；三个具体缺口——执行失败后规划与真实状态脱节、认出目标不等于到达、发出动作不等于子目标完成。借用编程智能体的 harness 思想，但要求显式的时空 grounding。

**Method.** Harness 状态 S\_t = (任务, 观测, 位姿, 进度 z\_t, 事件记忆 M\_t, 时空图 G\_t)。八个工具（observe、observe\_panorama、retrieve\_memory、ground\_target、query\_depth、navigate\_to、backtrack、request\_stop），派发前验证参数、证据来源与时效、几何可行性、与当前子目标一致性。事件记忆分工作/进度/反思三层：进度记忆里子目标有 pending/active/completed/blocked 四态且**完成必须有位姿对齐的观测支持**；反思记忆记录不可达、grounding 不一致、碰撞、无进展、回溯失败、停止被拒六类事件。时空图 G\_t 有地点与实体节点、NavigableTo/ObservedFrom/Contains 边、时间戳与失败注解，检索打分 s = 相关性 + λ·近期性 + λ·显著性 − λ·失败惩罚。**停止是请求而非动作**：F\_stop = 语义 ∧ 几何 ∧ 进度三项都过才真正 STOP。

**Highlight.**

- 累积消融（100-ep 子集）：基线 46 → 事件记忆 54 → 时空图 60 → 停止验证 64；OSR–SR 差距从 26 缩到 13。ObjectNav 侧停止验证反而略降 SPL（34.2 → 33.0）——**验证层换来的是完成率不是效率**。
- 同一协议跨四个基准，OVON 59.3 超过训练式 SOTA ABot-N0 的 54.0。
- 模型敏感性：同一 harness 下 GPT-6-astra 63 / Qwen3.8-flash 51 / GPT-5.6-luna 55；MSGNav 换成同一模型只有 37——harness 差异大于模型差异。
- 附录失败案例很诚实：R2R 839 投影目标检查通过但离终点 6.48 m，「接近所选目标 ≠ 指令终点正确」。

**局限与可乘之机.** 作者自述：编排与验证规则全是预定义的，未来要做自演化。RxR 的 SPL 38.0 和 nDTW 54.8 明显落后训练式方法（ABot-N0 60.0）；每步一次全景要 12 次 30° 旋转且计入步数预算。R2R 主表用了全量还是子集未明说。

## 三、逐篇归纳：记忆路线、融合路线与两篇背景

### B1 EvolveNav — 预反思 + 自演化规则记忆的零样本 ObjectNav

**Motivation.** 零样本 ObjectNav 靠基础模型的静态先验，不能从实时反馈学习，同样的错误（被视觉相似物体误导）反复犯；且现有方法是事后纠错，在有限步数预算下每次试错都很贵。要同时解决「在线适应」和「行动前预判」。

**Method.** 两个循环。Episode 内：占用图 + 前沿提取，LLM 在选前沿前做 preflection——对每个候选前沿先预测失败风险，再选。Episode 间：LLM 回看轨迹找关键决策步，蒸馏成自然语言规则存入规则库；每步的 credit 定义为「房间类型/可见物体与目标的语义相似度」相比上一步的增量 C\_i = S\_i − S\_{i−1}，规则的初始支持分是关键步 credit 的加权和；规则检索按 UCB(r) = μ\_r + β√(ln T / N\_r)，新规则 N\_r=0 时 UCB 为 ∞ 保证被验证一次。

**Highlight.**

- HM3D SR 67.3 / SPL 33.9，MP3D 49.0 / 19.1，MP3D 上比最强零样本基线 ASCENT 高 4.5 SR。
- 消融：单独 preflection 在 MP3D +3.5 SR，单独规则记忆 +4.5，合起来 +5.1——两个模块大部分不叠加。
- **backbone 几乎无关**：Qwen2.5-7B / Qwen3-8B / Qwen3.5-9B 结果差在 0.3 以内。作者的解读是决策被规则记忆牢牢约束了。
- 是八篇里唯一把「credit assignment」写成显式公式的工作，尽管用的是语义相似度增量这种代理信号。

**局限与可乘之机.** 作者自述：依赖 2D 检测、对非常规布局敏感。更根本的两点：规则是自然语言，没有验证机制（作者也承认）；跨 episode 记忆意味着它在 AgenticNav 的定义下不是零样本。语义相似度 credit 只对 ObjectNav 有意义，指令跟随任务没有对应物。

### C1 ABot-N0 — 统一 VLA 基础模型 + Agentic Navigation System

**Motivation（第 6 节）.** 真实用户指令异构，一次任务往往要组合 Approaching（Point-Goal 走已知空间）、Reaching（Object/POI-Goal 精确找目标）、Interaction（指令跟随、跟人）；Reaching 类任务性能随时程快速退化而 Point-Goal 稳健，所以要把长程任务拆成「先 Point-Goal 粗到近处，再 Object-Goal 精找」。

**Method.** 四模块：Agentic Planner（云端 VLM，RTX 4090）、Actor（4B VLA + 神经控制器，Orin NX）、短期情景记忆、长期 Topo-Memory。Topo-Memory 四层拓扑：Block（房间/街区）、Road（连通性）、Function（厨房、电梯厅等功能节点）、Object/POI；室内外统一到「One Map」，接高德全局路由；执行结果反写回图，动态更新边权。Planner 形式化为 G = P(I, M\_L, M\_S, O\_t)，分解概率写成 P(G|·)·∏P(W\_j|g\_j,·)。Self-Reflector S(M\_L, M\_S, g\_i) → (r, f)，失败时带反馈 f 重规划。

**Highlight.**

- 基础模型本身：R2R SR 66.4 / SPL 63.9、RxR 69.3 / 60.0，是当前训练式 SOTA；SPL 比 NavFoM 高 8.6。
- 记忆感知规划的具体例子：指令「找烤箱」，记忆里有「厨房在 (x,y)」→ 直接发 Point-Goal(x,y)，到了再切 Object-Goal，避免全局搜索。
- 部署数字：VLA 2 Hz、控制 10 Hz，视觉 token 合并（merge size 4）后边缘推理只掉 3%。
- Fig. 20 的可乐案例是完整的反思 → 重规划闭环。

**局限与可乘之机.** **第 6 节没有任何定量实验**——Planner、Topo-Memory、Self-Reflector 的贡献全靠可视化。Planner 在云端，网络断了只剩本地 VLA。Topo-Memory 的构建流程（Map-To-Memory）没有描述。这是一个「路线 A 的验证层 + 路线 C 的 VLA 执行器」的组合，但组合的收益未被测量。

### L1 NavGPT — 纯 LLM 零样本 VLN 的起点（2023）

**Motivation.** 验证 GPT-4 能否在文本化的具身场景里做序列决策，并把推理过程显式化。

**Method.** 24 张图（8 方向 × 3 仰角，FoV 45°）用 BLIP-2 生成描述，GPT-3.5 摘成每方向一句；Faster-RCNN 检测 3 m 内物体附上方位与深度；历史用 GPT-3.5 摘要压缩；ReAct 式 Thought/Action 循环，动作是选航点 ID。

**Highlight.** R2R val\_unseen SR 34 / SPL 29（DuET 72）；定性展示了子目标分解、常识、地标识别、进度跟踪、异常处理。消融：FoV 45° 优于 30° 和 60°；加物体 +4.86 SR，加深度再 +0.7。

**为什么还值得读.** 它把后来所有 harness 论文要解决的问题一次说全了：视觉→文本的信息损失、历史摘要导致无法判断「上一步是否完成」（Fig. 10 下例：还没进房间就以为进了）。AgenticNav 的 recall 工具、HarnessVLN 的「完成需观测支持」都是对这两个失败模式的直接回应。

### S1 Towards Embodied Agentic AI — 分类框架

**核心贡献.** 两维分类。集成方式：Protocol（LLM 当命令翻译器，单次调用）、Interface/Agentic（ReAct 循环、多次工具调用）、Orchestration（协调多个智能体/技能/机器人）、Embedded（VLA 端到端）。角色：Planner、Orchestration、Task-Specific、Model-Centric、Generalist、Generalist Systemic。NavGPT 和 ARNA 被归为 Task-Specific agents；BUMBLE 也在此列。

**对本项目有用的几点.**

- 它区分 AI Workflow（人写固定流程）/ AI Agent（模型决定动作序列）/ Agentic AI System（多智能体协作）；ARNA 的「运行时生成工作流」正好落在 Workflow 与 Agent 之间。
- 评测一节指出：低自主度系统可以通过监控工具调用顺序和参数来评测，高自主度系统只能看环境影响——这解释了为什么 harness 论文都在补消融而缺过程指标。
- 列出的开放问题：记忆（缺持久、可查询的语义记忆）、连续数据流与离散推理的错配、边缘-云分布、世界模型。
- 表 II 把 ARNA 标成 Embedded 集成、Fig. 3 又标成 Task-Specific，说明这套分类对「运行时生成工作流」这类工作的定位并不稳。

## 三-B、P1 补充归纳（一）：harness 的跨任务证据与「训练式 agentic」

这一组回答两个问题：harness 思想在操作领域的证据是否比导航更硬（是），以及把 agentic 结构训进模型后还算不算 agentic（部分算）。

### A6 Show-Harness — 「正确的接口就能让 VLM 直接玩机器人」

**仅操作，无导航实验**；但它对接口设计的消融是 15 篇里最干净的。

**Method.** 观测 → 插件生成上下文 → VLM 从 13 个语义动作单元里选一个（MV\_FWD/BACK/LEFT/RIGHT/UP/DOWN、ROTATE\_CW/CCW 带轴、GRASP/RELEASE/DONE，双臂加 STILL）→ 具身解释器确定性地转成 6-DoF 设定点增量（粗 4 cm / 细 2 cm，旋转 15°）。九个插件里只有 Action History（最近 5 步 + 反震荡规则）是记忆。可选 FT 模式：Qwen3.5-2B LoRA，H200 不到 2 小时。

**Highlight（Table 2，真机，每格 10 trial）.** 跨任务 ZS 89 / FT 86 vs π0.5 39、Harness VLA 50、RATS 57；跨具身 93 vs 41。关键消融：

- **动作约定文本 > 动作命名**（Fig.10）：语义名 + 物理效果约定 100%；只有语义名 90%；任意符号 + 约定 95%；任意符号无约定 5%。
- 插件 leave-one-out（Fig.9）：去多视角 96→58，去本体感知 →68，去子任务规划 →60，去 Action History →76。
- 模型敏感性（Fig.7）：Gemini-3.1 Pro 到 Gemini-3.6 Flash 约 96→75；thinking effort 只减步数不增成功率；瓶颈在放置精度（Plan correct 95 vs Place correct 70）。

**对导航的含义.** 导航 harness 的每个原语应显式写明物理效果（转角、步距）；「最小记忆」（5 步历史 + 反回环）就值 20 个点，重型地图未必是第一优先级。

### M1 Harness VLA — 冻结 VLA 作为原语，Codex / Claude Code 作为规划器

**Method.** 固定原语库（MOVE\_TO、MOVE\_POSE、ROTATE\_WRIST、SET\_GRIPPER、RELEASE + 学习型 VLA\_ACT；RoboCasa 加 NAVIGATE\_TO / MOVE\_BASE），VLA\_ACT 带停止谓词与块预算。三层记忆：Task-Specific Memory（JSONL 过程轨迹 + JSON 策略摘要，坐标只作结构先验、部署时必须重定位）、Global success rules、Failure models（如「夹爪闭合但物体未随动 → 空抓，重定位后重试」）。执行循环是文件式 REPL：读 state.json + RGB-D → 写 command.json → 等 done.flag → 读 log.json。规划器是 Codex 或 Claude Code。

**Highlight.** LIBERO-Pro 82.4 vs π\_RLinf 50.0（后者标准 LIBERO 95.3，说明 VLA 在分布外崩得多快）；few-shot 带记忆 vs zero-shot：空间扰动 87.0 vs 31.0，任务扰动 87.0 vs 79.0——**Task-Specific Memory 主要救空间扰动**。VLA\_ACT 只占 LIBERO 中 15.8% 的调用，72–84% 的任务由解析原语收尾。

**局限.** 规划器与 VLA 之间开环；作者拟用 GRPO 做联合微调但未做。

**可直接迁移到导航的.** 双文件记忆格式与「重用结构、禁止回放坐标」规则；failure model 文本格式（导航对应：误判到达、重复徘徊、错误地标绑定）；re-staging（把机器人移到策略熟悉的观测区再调用学习策略）。

### A7 AgentVLN — 训练式的「VLM-as-Brain」，R2R-CE 全量 SR 67.2

**先纠正之前的归类**：这篇不是零样本，是在自建 AgentVLN-Instruct 上微调 Qwen2.5-VL-3B（冻结视觉编码器，32×A100），且评测用 RGB-D + 里程计，对手多为 RGB-only。

**Method.** POSMDP 形式化：动作空间不是原子动作而是技能函数集 F\_percep ∪ F\_plan，VLM 每个决策周期选技能，技能闭环执行 τ 步后交回。**跨空间表示映射**：RGB-D 建增量占据图 → 规划层算可行 3D 路径点 → 透视投影回当前图像成为像素对齐的绿点提示，VLM 只在像素空间选点。**QD-PCoT**：局部定位阶段 VLM 生成自然语言查询（「前方椅子距我几米？」）触发感知技能，返回文本追加进上下文，多轮后输出目标像素。CDFG：无可行路径投影时直接输出 {Forward, Left, Right}。

**Highlight（Table 1，R2R-CE val-unseen）.** AgentVLN-3B NE 3.88 / OSR 73.5 / SR 67.2 / SPL 64.7；InternVLA-N1-8.3B 58.2 / 54.0；DualVLN-7.1B 64.3 / 58.5；EfficientVLN-4B 64.2 / 55.9。RxR-CE SR 69.5 / SPL 61.3。消融（Table 3）：基线 38.6 → +VLM-as-Brain 59.7 → +CDFG 65.6 → +QD-PCoT 67.2。**把 3D 几何投影成像素提示这一步贡献 +21.1 SR，是全文最大的单项增益。**

**是否 agentic.** 部分：有闭环多步技能调用与多轮查询，但查询类型与阶段切换全由数据集模板监督，论文没给每 episode 平均调用次数、查询多样性或失败回滚示例。

**局限.** 全文没有任何延迟 / FPS 数字，「边缘部署」只是定性；真机只有两条定性示例；深度与里程计输入使其与 RGB-only 方法的比较不对等。

### 多智能体：D1 DiscussNav / D2 REMAC

**结论先行：两篇都没有证据表明「角色拆分」本身优于「单智能体多次工具调用」。**

- DiscussNav（R2R 离散 val\_unseen SR 43 / SPL 40 vs NavGPT 34 / 29）：8 个「专家」里 InstructBLIP / RAM 就是工具，GPT-4 专家与主智能体是同一模型换 prompt；消融拆掉的是信息源，不是角色。决策测试（+5.5 SR）本质是 self-consistency。每步 ≥ 24 次 VLM 调用 + 5 路 GPT-4 采样，无任何成本报告。真机 Turtlebot 20 条指令 SR 25%。
- REMAC（厨房操作，摘要称含导航但实际没有独立导航评测）：真正的多机器人（RE → REMAC）**不提升成功率**（DefrostInBowl 50 → 40），收益全来自单智能体的 pre/post-condition check；反思能力强依赖推理模型（GPT-4o 12.5% vs Grok3 82.5%）。

可迁移的三个机制都能在单智能体里实现：分离的验证器、按地标类型定向提问减幻觉、跨 episode 反思记忆。**建议把多角色作为消融对照而非默认设计。**

### 背景：E1 BUMBLE / Q1 VLFM / N1 VLN-CE

- **BUMBLE**：GPT-4o 每步两次查询（选技能 → 估参数），Set-of-Mark + CoT；长期记忆是**人工标注的错误案例**、离线收集、评测时不更新；导航靠人工采集的地标图像拓扑图。Tiago 三栋楼 70 trial SR 47.1%；38 次失败中 28 次是 VLM 推理错误。
- **VLFM**：BLIP-2 ITM 对「Seems like there is a \<target> ahead」打分 → 投影成价值图（置信度 cos² 加权）→ 选价值最高的前沿 → PointNav 策略到达。HM3D 52.5 / 30.4。成为底座的原因：零样本、模块可替换、中间表示显式、单卡实时；局限（单目标、不支持语言指令）恰是 agentic 方法的切入点。
- **VLN-CE**：动作 forward 0.25 m / turn 15° / stop，单前向 RGBD 90° FOV，无位姿；val\_unseen 1,839 episodes（来自发布数据而非正文）；成功阈值 3 m；SPL = Σ S·ℓ/max(p,ℓ)，nDTW = exp(−DTW/(|R|·d\_th))。注意很多零样本方法把转向改成 30°、预算改成 260 或 500 步，比较时要核对。

## 四、横向提炼：共识、分歧与可复用的设计模式

### 共识（多篇独立得出的结论）

1. **接口设计的收益大于换模型。** A1 消融（深度工具 +13 SR vs 深度图 +11）、A3 消融（去技能 −50 SR）、A5 模型敏感性表（同 harness 跨模型差 12，同模型跨框架差 18）、A2 的 NoRP 消融（−67）四篇各自独立指向同一结论。
2. **VLM 不能直接输出数值几何。** A1 让它选像素、A3 让它选地标索引、A5 让它提语义操作再由 harness 落地、C1 让它出子任务原语——没有一篇让 VLM 直接输出坐标。ARNA 的 goto(x,y,z) 是例外，但坐标来自场景图查询而非 VLM 估计。
3. **停止判断是主要失败源。** A1 失败分析里「oracle 成功但没停」被单列；A5 的停止验证单独贡献 +4 SR 并把 OSR–SR 差距从 26 缩到 13；L1 早在 2023 就指出「看到目标就立刻停」。
4. **上下文必须有选择地加载。** A1 的 recall、A5 的 top-K 检索、A3 的 JSON 地标库、B1 的 top-K 规则，都是「压缩表示常驻 + 细节按需取回」。
5. **真机失败首因不在 VLM。** A3 是检测器（60%）、A1 真机 API 超时占 21.4%、A5 附录里是投影距离与基准距离不一致。

### 分歧（值得作为研究问题的地方）

| 议题 | 一方 | 另一方 |
| --- | --- | --- |
| 什么算零样本 | A1：只允许 episode 内记忆，跨 episode 检索「削弱零样本设定」 | B1：跨 episode 规则库是核心贡献，且不算训练 |
| 验证放在哪 | A1：只有几何安全检查，决策全交给 VLM | A5：派发前四项验证 + 停止三项验证，VLM 只能「请求」 |
| 工作流谁定 | A2：LVLM 运行时生成 π\_task | A5、C1：编排流程预定义，A5 作者明说这是局限 |
| 记忆谁维护 | A2：LVLM 自己写文本记忆 | A5、C1：harness/系统按规则写图，VLM 只读 |
| 反思时机 | B1：行动前 preflection | C1：子任务结束后 Self-Reflector；A5：失败事件写入反思记忆供检索 |
| 云端还是本地 | A1、A2、A3：远程 API | A5 真机 Qwen3.8-27B 本地；C1 Planner 云端 + VLA 本地 |

### 可复用的设计模式（做实验时可直接拿来当基线组件）

- **动作预览**（A1 query\_depth 返回「若执行会转多少走多远」）：让 VLM 在不动的情况下比较候选，成本极低。
- **停止即请求**（A5）：F\_stop = 语义 ∧ 几何 ∧ 进度，任何一项不满足就退回观察/回溯。
- **子目标四态 + 完成需证据**（A5 progress memory）：防止规划器「宣布完成」。
- **失败注解带衰减**（A5 时空图）：子目标变了或新证据推翻后惩罚自动降低，避免永久封死某条路。
- **给未来自己的笔记用全局方位**（A3）：把相对方向转成地图坐标系，记忆才能跨时刻复用。
- **粗到细分解**（C1）：长程 Point-Goal 稳、短程 Object-Goal 准，用记忆里的位置把搜索问题变成到达问题。
- **规则 UCB 检索**（B1）：新规则强制验证一次，旧规则按历史成功率加权。

### P1 带来的修正与新证据

1. **「接口 > 模型」从共识变成跨任务定律。** Show-Harness Fig.10（动作约定 100 vs 无约定 5）、AgentVLN 消融（像素提示 +21.1）、SpaceVLN 消融（层次记忆 −14.4）与 P0 的四篇证据同向。
2. **「何时调用慢系统」是一个独立变量。** VLingNav 2.1% 触发率已够、每步 CoT 反而更差；MetaNav 每 3 步打分一次、每 episode 反思 1.9 次；DualVLN 2 Hz / 30 Hz 异步。P0 的 harness 论文都是每步调 VLM，这很可能是浪费。
3. **空间记忆 > 反思机制（按消融幅度）。** 四篇记忆路线论文里空间记忆贡献 12–14 点，反思 4–5 点；且 VLingNav 证明纯文本记忆单独几乎无效。反思的收益集中在长任务后段。
4. **多智能体路线降级。** REMAC 多机器人不提升 SR；DiscussNav 的专家就是工具。路线 D 在研究切入点里只作对照。
5. **内化路线目前没有人把工具调用训进导航模型。** ME-VLM 有 environment-loop RL 但导航仍是纯端到端；AgentVLN 的查询是模板监督。「RL 学何时查询什么」仍是空白。
6. **零样本 R2R-CE 全量榜单现在可以排了**：HarnessVLN 60.8 > SpaceVLN 53.3 > GTA 48.8 > Open-Nav 23.0；AgenticNav 55 是子集不入榜。训练式：AgentVLN 67.2（RGB-D）> ABot-N0 66.4 > DualVLN 64.3 > InternVLA-N1 58.2 > VLN-R1 30.2。零样本与训练式最优相差约 6 点。

### 新增的可复用设计模式

- **动作约定文本**（Show-Harness）：每个原语附一句物理效果描述，比命名本身重要。
- **可学习的思考开关**（VLingNav）：用一个 token 决定是否调用慢系统。
- **停滞触发反思**（MetaNav）：未知体素减少量低于阈值连续 N 步 + 冷却期，比固定频率省 20% 调用。
- **预算式粗到细候选筛选**（EvoMemNav）：先按房间桶 Top-K 压缩候选，再让 VLM 选——单项消融 +11.6。
- **双文件记忆 + 结构先验重定位**（Harness VLA）：轨迹只作结构参考，坐标必须重新 grounding。
- **投影式 3D 提示**（AgentVLN）：把规划器算出的可行路径点投回图像，VLM 只在像素空间选。

### 术语与协议陷阱（写作与实验前必须记住）

- EvoNav（Dai et al., CVPR 2026）≠ EvolveNav（B1）≠ EvoMemNav（B2）。
- A1 的 55 是 R2R-CE val\_unseen 100-episode 子集，A5 的 60.8 推断为全量；A5 把两者放在同一张表。
- A5 全景观测每步要 12 次 30° 旋转，计入 1,000 步预算；比较步数效率时要注意。
- A3 真机只有 12 次、仿真 14 次；A1 真机 30 次。所有真机结论都是小样本。

## 五、研究切入点

八篇论文共同留下的空白可以归为六个方向。每个方向标注它反驳或延伸的是哪篇、最小可行实验是什么、需要什么资源、风险在哪。排序按「文献缺口大小 × 可用现有代码快速验证」。

### 1. 让 harness 可学习：工具调用序列的 RL 后训练

- **缺口**：A1、A5 的工具调用完全靠 prompt，A5 作者明说编排规则预定义是局限；A1 只提「蒸馏」。目前没有一篇在导航 harness 上做过 RL。
- **最小实验**：在 AgenticNav 开源代码上，用 Qwen3.6-27B（A1 报告 SR 35 / OSR 64，有 29 点提升空间）做 GRPO，奖励 = 成功 + SPL + 工具调用次数惩罚；对照 A1 的 GPT-5.5 数字。
- **需要**：Habitat + R2R-CE、一张 80G 卡即可跑 27B LoRA、AgenticNav 代码（作者称开源，需确认）。
- **风险**：100-episode 协议方差大；训练后是否仍算「零样本」会被审稿人质疑，需要同时报告 val\_unseen 全量。

### 2. 停止判断的专门建模

- **缺口**：三篇独立指出停止是主要失败源，但只有 A5 用硬规则处理，且 ObjectNav 侧反而掉 SPL。没有人把「是否到达」当成独立的可学习判别问题。
- **最小实验**：从 A5 的 OSR–SR 差距（R2R 全量 72.7 vs 60.8，即 12 点）入手，训练一个轻量停止判别器（输入：当前观测 + 子指令 + 投影距离），插到任意 harness 的 request\_stop 前。
- **需要**：R2R-CE 轨迹上按到达距离打标签即可，数据现成。
- **风险**：A5 附录 R2R 839 案例说明「接近所选目标 ≠ 指令终点」，判别器要看指令而不只看距离，否则复现 A5 的问题。

### 3. 细粒度 credit assignment 用于规则/记忆的自演化

- **缺口**：B1 是唯一写出 credit 公式的，但用的是语义相似度增量，只适用于 ObjectNav；A5 的反思记忆记录失败事件却没有归因。指令跟随任务下「哪一步决策该为失败负责」没有任何方法。
- **最小实验**：在 R2R-CE 上用轨迹与 GT 路径的 nDTW 局部增量、或子指令 grounding 进度，替换 B1 的语义相似度 credit；评估规则质量而非只看 SR。
- **需要**：B1 的规则库框架 + 一个指令跟随的进度信号。
- **风险**：跨 episode 记忆的零样本争议（见分歧表第一行）；要么接受 B1 的定义，要么把规则限制在同一场景内。

### 4. 记忆表示的可验证性

- **缺口**：A2 把「记忆验证」列为未来工作；B1 承认规则无验证；A5 只对失败注解做衰减。没有人测过「记忆里有多少条目是错的、错的条目造成多少失败」。
- **最小实验**：在 A5 或 A2 框架里注入受控噪声（错误的实体位置、过期的可达性），量化 SR 随记忆错误率的退化曲线；再比较「VLM 自己写记忆」（A2）与「harness 按规则写」（A5）的抗噪性。
- **需要**：一个开源 harness；A5 有项目页，代码状态待确认。
- **风险**：偏分析型工作，需要配一个改进方法才好发。

### 5. 利用环境知识资源的技能扩展

- **缺口**：A3 证明读路牌/问路在大建筑里把 SR 从 8.3 提到 58.3，但只有 12 + 14 次实验，且技能集固定为三类；只有 A3 自建的医院环境能评测这类能力。
- **最小实验**：在 A3 的 Isaac Sim 医院基准（作者称将开源）上扩展技能类型（电梯、目录屏、地图板），或让 VLM 自己决定何时触发技能而不是绑定地标类别。
- **需要**：Isaac Sim；真机验证需要有路牌的大型建筑。
- **风险**：依赖 A3 开源；检测器仍是瓶颈（A3 真机 60% 失败来自检测）。

### 6. 融合路线的定量化：agentic 层到底带来多少

- **缺口**：C1 的 Agentic Navigation System 没有定量消融，「VLA + 外挂 harness」的收益从未被测量；A5 在 OVON 上超过 C1 的 VLA（59.3 vs 54.0），但 R2R 上落后（60.8 vs 66.4）。
- **最小实验**：以开源 VLA（InternVLA-N1 或 NavFoM）为执行器，外套 A5 式验证层，在 R2R-CE / OVON 上做「VLA 单独 / VLA + 验证 / VLA + 验证 + 记忆」三档对比。
- **需要**：一个开源 VLA 权重 + A5 的 harness 逻辑（可自行实现，规则在论文里写得足够清楚）。
- **风险**：工程量大；如果 VLA 本身已经很强，agentic 层收益可能只体现在长程任务，需要 RxR 或自建长程 benchmark。

### 与已有工作线可能的接口

- 方向 3 与「内省进化 / 细粒度 credit assignment」这条线直接相关：B1 的公式是现成的对照。
- 方向 6 与「双层技能系统（history-agnostic 原子技能 + history-aware 路由）」同构：路由器就是 harness 的规划器，原子技能就是 VLA 原语。
- 方向 3、4 与测试时适应（TTA）共享「无梯度在线改进」的设定，B1 的规则演化可以看作离散版 TTA。

### P1 读完后的修订（覆盖上面六个方向的排序）

| 方向 | 修订 | 新依据 |
| --- | --- | --- |
| 1 harness 可学习 | **上调，并细化为「RL 学何时查询 / 查询什么」** | VLingNav 证明「何时思考」可学且收益大；AgentVLN 的 QD-PCoT 是模板监督，论文自己没给查询统计；ME-VLM 有 env-loop RL 但未用于导航工具；Harness VLA 拟用 GRPO 但未做。四篇都站在门口没进去。 |

| 4 记忆可验证性 | 维持 | Harness VLA 的「禁止回放坐标」是一个工程化的验证规则，可作基线。 |
| 5 环境知识资源 | 维持 | 无新证据。 |

**新增方向 7：自适应调用频率的 harness**

- **缺口**：所有零样本 harness（A1/A2/A3/A5/B3）每步或每阶段固定调 VLM；VLingNav 证明 2.1% 触发率就够，MetaNav 的停滞触发省 20%。没有人在 harness 里让「是否调用规划器」成为一个学习或自适应的决策。
- **最小实验**：在 SpaceVLN 或 HarnessVLN 的双时间尺度结构上，用一个轻量判别器（输入：当前观测与上次规划时观测的差异、子目标进度、最近 k 步的探索增益）决定是否唤醒 VLM；报告 SR 与 VLM 调用次数的 Pareto 前沿。
- **需要**：R2R-CE + 一个开源零样本 harness；判别器可用 MetaNav 的停滞规则做无学习基线。
- **风险**：如果主要收益只是成本而非 SR，论文要写成效率工作；但 VLingNav 的每步 CoT 反而更差这一点暗示 SR 也可能洨。

**新增方向 8：agentic VLN 的过程指标与协议标准化**

- **缺口**：15 篇里没有一篇报告完整的「每 episode 工具调用次数 / 查询有效率 / 失败恢复率 / 延迟」；S1 综述明确指出低自主度系统应该用过程指标评。协议上：100-ep 子集 vs 全量、RGB vs RGB-D、260 vs 500 vs 1000 步、30° vs 15° 转向、全景是否计步，各篇不一致。
- **最小工作**：在同一 backbone（如 Qwen3.6-27B，AgenticNav 已用）下复现 AgenticNav、SpaceVLN、HarnessVLN 三个 harness 到全量 val\_unseen，统一报告上述过程指标。
- **价值**：本身可发（benchmark/analysis 类），且是方向 1、2、7 的必要基础设施。
- **风险**：依赖三个代码库的开源状态；API 成本（SpaceVLN 自报 $0.01/ep，但 ARNA 是 $1–3/任务）。

### 修订后的建议顺序

先做方向 8 的最小版（只复现一个 harness 到全量并加过程指标），它同时是方向 2 和 7 的实验平台；然后在这个平台上并行跑方向 2（停止判别器）和方向 7（调用频率），两者都是插入式模块、不改主体。方向 1（RL 学查询）是最大的空白但依赖前三者的基础设施，放第二阶段。

### 建议的第一步

（以下为 P0 阶段的原建议，已被上文修订覆盖，保留供对照。）方向 2（停止判别）成本最低、数据现成、结论对任何 harness 都有用，适合作为进入该领域的第一个实验；方向 1 是最大的空白但依赖 A1 代码是否真的开源。建议先确认 A1、A5、A3 三个代码库的实际状态，再定主线。

### 遗漏的关键论文：MIP（arXiv 2607.26148）

**Embodied Agents Take Control: Minimal-Interface Zero-Shot Agents Rival Industrial-Scale Policies in VLN**（2026.07，审稿中）。Show-Harness 引用它作为 \[105\]，我之前漏掉了。仅从仓库 README 获得的信息（**论文原文待读，编号 A8**）：

- 接口只有两个工具：`observe()` 返回相机画面，`step()` 执行离散动作。没有深度工具、没有地图、没有 recall。
- 智能体是现成的编码智能体（Claude Code / Codex / mini-SWE-agent），而非专门写的导航 prompt。
- R2R-CE `rand100` 子集：Claude Code + fable-5 SR 68.3 / SPL 58.02；mini-SWE-agent + fable-5 SR 72 / SPL 59.08；最大 effort 下 SR 78。RxR-CE SR 26，VLNVerse SR 84，HM-EQA 76%。

**这个结果如果成立，会改变前面的好几个判断：**

1. AgenticNav 在 100-episode 子集上的 55 / 48.41 被一个**接口更简单**的系统用 68–78 超过（需确认 rand100 与 AgenticNav 子集是否同一协议，以及 backbone 是否可比）。「接口设计 > 模型」这条定律需要重新表述：可能是**智能体循环的质量**（编码智能体自带的规划、重试、上下文管理）而非工具数量在起作用。
2. 它与 Harness VLA 用 Codex / Claude Code 做规划器是同一思路：**把编码智能体整个当作 harness**，而不是自己写 harness。
3. 它开源、MIT、接口极小——是目前最适合做「接口消融」的平台：从两个工具开始，逐个加 depth / map / recall / stop-verify，看每个工具到底值多少。这正好是方向 8 的最小版。

**待确认**（读原文后补）：rand100 的抽样方式与步数预算；每 episode token / 时间 / 费用；是否报告了全量 val\_unseen；失败分析；与训练式基线的对比表。

## 七、研究计划草案

前提：计算资源为 8×24 GB 节点，可跑 Habitat + 27B 量级 LoRA；已有 R2R / RxR 离散与连续环境的实验基础。计划分三阶段，每阶段的产出都能独立成文。

### 阶段 0（约 2 周）：平台与基线

1. 跑通 MIP（Claude Code SDK 或 Codex CLI 后端），复现 rand100 结果；确认 token / 费用 / 延迟。
2. 在 MIP 上加过程指标采集：每 episode 工具调用次数、observe/step 比例、停止时距目标距离分布、OSR–SR 差距。
3. 将 MIP 接口扩展为可配置工具集 {observe, step} + 可选 {query\_depth, map\_image, recall, request\_stop}，工具实现参照 AgenticNav / HarnessVLN 论文（规则写得足够清楚）。
4. 产出：一个统一平台 + 全量 val\_unseen 上的接口消融表（方向 8 的最小版）。风险：API 费用，1,839 episodes × 多个配置；先用 rand100 筛配置，只把关键配置跑全量。

### 阶段 1（约 6 周）：两个插入式模块，并行

**1a 停止判别器（方向 2）**

- 假设：OSR–SR 差距（HarnessVLN 全量 12 点，AgenticNav 子集 OSR 64 vs SR 35 在弱模型上）主要来自停止判断而非到达能力，一个轻量判别器能收回大部分。
- 数据：R2R-CE / RxR-CE 训练集 GT 轨迹上，每步标「距终点 ≤ 3 m 且最后一句子指令已完成」为正；负样本重点取 HarnessVLN R2R 839 那类「靠近了中间地标但不是终点」的难例。
- 输入：当前观测 + 完整指令 + 子指令进度估计 + 最近 k 步。基线：HarnessVLN 的三项硬规则、EvoMemNav 的多视图 STOP/RESELECT。
- 与现有工作线的接口：子指令 grounding 信号可直接复用 TTA 线里的子指令对齐模块；RxR-CE 的 Landmark-RxR 对齐数据可作训练标签。

**1b 自适应调用频率（方向 7）**

- 假设：导航中只有少数步需要 VLM 重新规划（VLingNav 2.1%，MetaNav 每 episode 1.9 次反思）；其余步由上一次规划的子目标 + 局部控制器执行即可。
- 方法：三档对比——每步调用（现状）/ MetaNav 式停滞规则 / 学习型门控（输入：观测变化量、子目标进度、探索增益；标签：用 GT 轨迹回放判断「若不重规划是否仍在正确子目标上」）。
- 报告 SR × 调用次数 Pareto 前沿。
- 与现有工作线的接口：历史窗口截断实验（HAMT 上 3–6 步饱和）直接支持「局部决策不需要长历史」这一前提；双层技能系统的路由器就是这个门控的训练式版本。

### 阶段 2（约 8 周）：RL 学查询（方向 1）

- 在阶段 0 的平台上，用开源 VLM（Qwen3.6-27B，AgenticNav 报告 SR 35 / OSR 64）替换闭源智能体，对工具调用序列做 GRPO。
- 奖励：终点成功 + SPL + 工具调用次数惩罚 + 阶段 1a 停止判别器的中间奖励。VLN-R1 的指数衰减奖励形状可作参考（Hard 23.8 → 指数 30.2）。
- 重点学的是「何时 query\_depth / recall / request\_stop」，而不是动作本身——这是 AgentVLN QD-PCoT 用模板监督、ME-VLM 未在导航上做的部分。
- 与内省进化线的接口：细粒度 credit assignment 在这里有天然的落点——工具调用序列比原子动作序列短得多（MetaNav 1.9 次反思 / episode），把失败归因到某次工具调用比归因到某步动作可行得多；CanTest 的能力级归因 (C\*, t\*) 可以直接对应到工具类型。
- 风险：每步一次 27B 前向 × GRPO G=8 × 长 episode，采样成本高；先用 rand100 验证再扩。「训练后还算不算零样本」的质疑需提前用「仅训练工具使用、不接触评测场景」回应。

### 不做的事（及理由）

- 不自建多智能体框架（REMAC / DiscussNav 无角色收益证据）。
- 不从零写 harness（MIP / HarnessVLN 已有，且 MIP 证明编码智能体本身就是不错的 harness）。
- 不先做跨 episode 规则记忆（零样本定义争议 + 消融收益小）。
- 不追求真机，除非阶段 1 结果需要部署证据（所有真机实验都是 ≤ 30 次的小样本）。

## 八、A8 MIP 精读：对前面所有判断的冲击

**Embodied Agents Take Control**（Zhou, Zhao, Zhou, Li, Lin, Liu, Wu；阿德莱德 + CSIRO；arXiv 2607.26148 v3，2026-09-18）。下面所有数字来自原文。

### 协议：与 AgenticNav 严格同一子集

rand100 = R2R-CE val\_unseen 固定子集的 episode 0–99，由 Open-Nav 引入、SmartWay 与 AgenticNav 共用（附录 A.1）。之前担心的「是否可比」解决了：**可比**。接口：`observe()` 返回 512×512 RGB（HFOV 90°），`step(actions)` 执行 ≤ 50 个原语（forward 0.25 m / turn 15° / STOP），只返回执行数与剩余预算，**无位姿、无碰撞、无深度、无地图、无跨 episode 记忆**。预算 500 步 / 200 次 LLM 调用 / 2400 s。一个人类测试者在同一接口上 SR 94 / SPL 80.80——这是这个接口的天花板。

### 主结果（Table 1–2）

| 配置 | SR | SPL | 备注 |
| --- | --- | --- | --- |
| mini-swe-agent + fable-5 | 72 | 59.08 | 开源 harness，几百行 ReAct，**无上下文管理** |
| Claude SDK + opus-5 | 70.7 ± 3.5 | 55.21 | 三次重复 |
| Claude SDK + fable-5 | 68.3 ± 1.5 | 58.02 | 三次重复 |
| Claude SDK + fable-5，max effort | 78 | 65.27 |  |
| **hybrid（原语 + 可选航点工具）** | **76.7 ± 0.6** | **63.63** | 步数 87 → 48，时间 210 → 112 s，调用 39 → 20 |
| mini-swe-agent + gpt-5.5 | 52 | 44.24 | **与 AgenticNav 同模型** |
| AgenticNav（GPT-5.5） | 55 | 48.41 | 地图 + recall + 深度 + 安全检查 |
| mini-swe-agent + qwen3.6-plus | 45 | 33.27 | 最强开源模型 |
| mini-swe-agent + qwen3.5-4b / 9b | 5 / 7 | — | 小模型完全不行 |

**同模型对照是最重要的一行**：AgenticNav 的全套工具在 GPT-5.5 上只比两个工具多 3 SR / 4 SPL（作者自己说 serving path 未控制，不能归因到具体模块）。

### 三轴定位（§4.3，Fig.3）

- **模型**：同 harness 同接口，换模型跨度 5 → 72 SR。
- **Harness**：同模型，mini-swe-agent vs 厂商 harness 差 1.7–7.3 SR。
- **接口**（Table 4）：强制换成航点接口（12 视角 RGB-D 全景 + 训练过的航点预测器），对 qwen3.5-4b +38、gpt-5.5 +22、sonnet-5 +8.7、fable-5 +0.7、opus-5 +1.3；在 VLNVerse 上对强模型反而 −4 到 −6，碰撞率升 4–6 倍。
- **推理 effort**（Table 3）：fable-5 +9.7，其余 −5 到 +6，无一致方向；时间翻倍。

作者的提法：问题不是加多少脚手架，而是脚手架是**强加的还是放在智能体控制之下的**。hybrid 中智能体自发形成「航点走长距离、原语精调终点」的粗到细策略，prompt 并未规定。

### 失败分析（§4.6 + 附录 C，30 个失败 episode 逐个审计）

| 类别 | n | 中位终距 (m) | 声称成功 |
| --- | --- | --- | --- |
| A 错误指代 / 错误分支 | 12 | 17.3 | 10/12 |
| B 停止决策 | 7 | 4.9 | 7/7 |
| C 失控搜索 | 8 | 18.6 | 4/8 |
| D 几何 / 仿真器陷阱 | 3 | 5.5 | 2/3 |

三个结论直接冲击我们的计划：

1. **失败是路线级的，不是停止级的**：30 次失败只有 5 次曾进入过 3 m 成功区；20/30 是「贪心搜索不回溯」——在分支处绑定局部最佳匹配后永不撤销。
2. **自我诊断但不自我纠正**：至少 15 个 episode 里模型的推理逐字说出了正确的怀疑（「应该 3 跳 10 米但我已经走了 15+」），然后照样承诺错误终点。语言化的路线模型从不覆盖已承诺的轨迹。
3. **失败是静默的**：26/30 自主 STOP，23/30 声称成功，终距 3.1–34.1 m 下的信心表述几乎相同——模型自己的成功声明没有任何评估价值。

另外一个便宜的接口漏洞：`step()` 报告的是请求数而非实际位移，阻塞只能靠比较连续帧发现（ep14 对着像素相同的两帧发了四次前进）。真机上同样：命令 90° 实际只转了 11°，后续整段路线航向错误。

### 长时程与部署（§4.5）

RxR-CE 同配置 SR 26（原语）/ 39（航点），上下文 22.4k → 49.2k token，时间 187 → 527 s。全部 4,700 个 episode 中位时间 206 s，18.6% 超 10 分钟；R2R-CE 最后一次调用上下文中位 33k、最大 169k。作者自己点名的下一步：**在有界上下文内选择性保留与合并状态的具身 harness，以及教会模型使用这些状态的训练**。

### 分类法（附录 F）：可直接用于定义章节

两个正交轴：**控制权（policy / workflow / agentic）× 能力来源（trained / zero-shot）**。判定标准是「动态控制流而非动态内容」：双系统（ABot-N1、InternVLA-N1/DualVLN）因为慢快交接固定，被归为 **workflow**；MapGPT / SmartWay / DiscussNav 是 zero-shot workflow；NavGPT、AgenticNav、planner × Qwen-RobotNav、MIP 是 agentic。这比我们之前的四要素定义更干净，且把「脚手架多少」降为描述性维度。附录 E 还定义了 Autonomous Embodied Agent 的五条系统级要求（连续多任务、持久状态、闭环恢复、资源有界、安全适应）。

### 对研究计划的修订（覆盖第七节）

| 原判断 / 方向 | MIP 之后 |
| --- | --- |
| 「接口 > 模型」 | **修正为：模型决定上限，接口对弱模型是补偿、对强模型必须可选**。Show-Harness / AgentVLN / SpaceVLN 的消融仍成立，但都是在固定模型内比较接口；跨模型看，模型跨度 67 点 vs 接口 0.7–38 点。 |

| （新）方向 9 **从怀疑到回溯** | **升为第一优先**。缺口最硬：20/30 失败是不回溯，15 个里模型已经说出正确怀疑。机制方向：把承诺点（分支、指代绑定）显式化为可回溯的假设栈；当模型输出的进度估计与指令结构矛盾时强制触发 backtrack 到上一个承诺点。这与内省进化线的「第一偏离步 t\*」完全同构——MIP 附录 C 就是 30 个手工标注的 (t\*, 原因) 样本。 |

| （新）接口小修：返回实际位移 | 低成本高收益。`step()` 返回实际位移 / 碰撞标志，直接消除类别 D 并削弱 C。可作为阶段 0 的第一个消融。 |

### 需要回头核对的一件事

已核对 HarnessVLN §4.2–4.4 与 Table 4：消融只写「fixed 100-episode subsets」，**未说明是否为 rand100**，因此 64 vs 52 的同模型对比不能成立。而且 HarnessVLN 的「基线智能体」（46 SR）已经拥有 RGB-D（640×480，79°）、GroundingDINO + SAM、FMM 规划器和 NavDP，不是最小接口；它的消融增量（+8 记忆、+6 图、+4 停止）量的是「在一个已经很重的感知栈上再加记忆与验证」的收益。另外两个细节：HarnessVLN Table 2 把 AgenticNav（rand100）与自己（推断全量）并列并声称「同 GPT-5.5 下 +5.8 SR」，这个比较本身不成立；且其 R2R SPL 43.5 低于 AgenticNav 48.41，说明重 harness 换来的是完成率而非路径效率。

**结论**：目前没有任何一组同模型、同子集、同传感器的对照能说明「重 harness 比最小接口好多少」。唯一严格可比的是 AgenticNav vs MIP（+3 SR）。这本身就是一个值得做的实验：在 MIP 平台上、固定 gpt-5.5 或 qwen3.6-plus，逐个加入 HarnessVLN 的三个组件（事件记忆、时空图、停止验证）与一个 backtrack 工具，在 rand100 上报告 SR/SPL/调用数。这就是修订后的阶段 0。

## 九、整体判断、领域主线与最有潜力的方向

基于 24 篇论文的完整阅读。先给结论：**agentic navigation 的瓶颈已经从「感知与接口」转移到「自我修正与状态管理」**，而现有工作几乎全部还在前者上发力。

### 1. 整体判断（五条，每条带证据）

**① 能力在模型里，不在脚手架里。** 同接口同 harness 换模型跨度 5 → 72 SR；harness 差异 2–7；AgenticNav 全套工具在同模型上只多 3 SR（MIP）。三年前 NavGPT 用 GPT-4 只有 34，现在同样的 ReAct 循环用 fable-5 是 72——这中间的进步几乎全是模型带来的。含义：任何在前沿模型上“加工具”的工作，预期收益上限就是几个点。

**② 脚手架的价值是条件性的：对弱模型是补偿，对强模型必须可选。** 航点接口对 4B 模型 +38、对 fable-5 +0.7，强制使用在 VLNVerse 上反而 −4 到 −6；作为可选工具则 76.7、步数减半（MIP Table 4–5）。Show-Harness 的动作约定消融（100 vs 5）、AgentVLN 的像素提示（+21）、SpaceVLN 的层次记忆（−14）都是在固定模型内成立的。含义：接口研究的正确提法不是“哪个接口好”，而是“在多大的模型能力下、以何种授权方式提供”。

**③ 当前失败的主体是“承诺后不修正”，而非感知、接口或停止。** MIP 30 个失败中 20 个是分支处贪心绑定后永不回溯，15 个模型已逐字说出正确怀疑；只有 5 个曾进入成功区；23 个在 17 m 开外声称成功。AgenticNav 的失败 88.9% 归于“VLM 决策”，BUMBLE 38 次失败 28 次是 VLM 推理。人类在同一最小接口上 94 SR——与 72 之间的 22 点不是感知差距。

**④ 长时程是真正的崩溃点，而现有记忆工作没有对准它。** 同配置 R2R-CE 70 → RxR-CE 26，上下文 22k → 49k，时间 187 → 527 s（MIP）。四篇记忆路线论文都在短任务上评测，其中空间记忆值 12–14 点、反思值 4–5 点；纯文本记忆单独几乎无效（VLingNav 18.8 vs 45.2）。同时 HAMT 上历史窗口 3–6 步就饱和——说明大部分原始历史无用，有用的是稀疏的空间锚点和承诺点。

**⑤ “内化”路线还没有真正内化任何 agentic 能力。** DualVLN / VLN-R1 / ME-VLM 导航部分均无工具调用、无回溯；AgentVLN 的查询是模板监督；VLingNav 只内化了“何时思考”（2.1% 触发率就够）。开源模型在最小接口上最高 45（qwen3.6-plus），与前沿 72 差 27 点。MIP 作者自己把“脚手架生成可验证轨迹 → RL / 蒸馏 → 模型反过来简化脚手架”列为未测假设。

### 2. 领域主线（五条，按“现在该在哪里发力”排序）

| 主线 | 核心问题 | 现状 | 空白 |
| --- | --- | --- | --- |

### 3. 最有潜力的方向（排序：缺口大小 × 证据确定性 × 可验证性）

**★★★ 方向 I：承诺感知的回溯（Commitment-Aware Backtracking）**

- **为什么现在**：它对应当前最大的失败份额（20/30），且模型已经“知道”自己错了（15/30）——缺的不是能力，是从怀疑到行动的机制。这是全部 24 篇里证据最硬、机制最清楚、无人专门做过的缺口。
- **机制设想**：把每次“指代绑定 / 分支选择”显式为带位姿锚点的承诺记录（假设栈）；智能体每步输出结构化进度估计（已走距离 / 已完成子句 / 预期剩余）；当估计与指令结构矛盾（走过头、地标缺失、房间类型不符）时，harness 强制弹出上一个承诺并回到其锚点，屏蔽已否定的分支。这是 HarnessVLN “失败注解”的前向版本：不是记录失败后衡减，而是在承诺时就登记可回退点。
- **最小验证**：MIP 平台、rand100、固定模型，四档：最小接口 / +backtrack 工具（被动）/ +承诺栈（主动触发）/ +承诺栈 + 到达验证。目标：类别 A+C 的 20 个失败收回一半，即 SR 从 70 向 80 走。标签来自 MIP 附录 C 的 30 个手工审计 episode。
- **与现有工作线的关系**：“第一偏离步 t\* + 负责子指令 s\* + 原因 c\*”的诊断探针就是这个机制的离线版；在线版需要在没有 GT 的情况下从模型自己的进度估计中检测矛盾。CanTest 的能力级归因可以直接用来对承诺类型分类。
- **上限与风险**：上限是人类的 94。风险：强模型可能已经在内部做了部分回溯，机制收益可能像 HarnessVLN 的 +4 那样不大；回溯有成本，SPL 可能下降，需同时报步数。

**★★★ 方向 II：脚手架到权重的自举（Scaffold-to-Weights Bootstrapping）**

- **为什么现在**：开源模型在最小接口上 45、前沿 72，27 点差距决定了能否本地部署；VLingNav 证明“何时思考”可学，VLN-R1 证明 GRPO 能让 2B 追平 7B SFT，ME-VLM 证明 env-loop RL 对工具调用有效；但三者都没有在导航工具调用上做。MIP 明确把“脚手架生成可验证轨迹 → 训练 → 模型简化脚手架”列为未测假设。
- **机制设想**：用 hybrid 接口的前沿智能体（或带地图 / 深度工具的强 harness）在训练场景里生成带完整工具调用痕迹的成功轨迹；对 Qwen3.6-27B 级模型先 SFT 后 GRPO，奖励 = 成功 + SPL − 调用次数惩罚，重点学三件事：何时 observe、何时调航点 / 深度工具、何时回溯。然后在**最小接口**上评测，看模型是否把工具提供的能力内化了。
- **最小验证**：R2R-CE 训练场景、rand100 评测；基线是 qwen3.6-plus 45（最小）/ 53（航点）。目标：27B 开源模型在最小接口上过 60。
- **与现有工作线的关系**：ETP-R1 / VQ 技能编码线的 RL 基础设施可直接复用；双层技能系统的“路由器”就是这里的工具选择策略；credit assignment 在工具调用序列（每 episode 20–40 次）上比在原子动作序列（87–500 步）上可行得多。
- **上限与风险**：如果成功，是这个领域今年最重要的结果之一（前沿 agentic 导航不再依赖闭源 API）。风险：采样成本（每步 27B 前向 × G=8 × 长 episode）；“还算不算零样本”的定义争议（MIP 附录 F 的双轴分类可以化解：它是 trained + agentic，与 ABot-N0 的 trained + workflow 对照）。

**★★ 方向 III：长时程的有界状态 harness**

- **为什么**：RxR-CE 26 是整个范式最大的未解决数字；现有记忆工作都在短任务上评测；MIP 自己点名“选择性保留与合并”为下一步。
- **机制设想**：不重发历史帧，只保留三类东西——稀疏空间锚点（拓扑节点 + 一帧缩略图）、承诺栈（方向 I）、子指令进度表；历史帧按需 recall。报告 SR 随上下文预算（4k / 8k / 16k / 无限）的曲线。
- **最小验证**：RxR-CE 100 episodes，MIP 平台，固定模型。基线 26 / 49k token。
- **风险**：可能主要收益是成本而非 SR；但 R2R 上“每步 CoT 反而更差”的 VLingNav 结果暗示上下文污染真实存在。与方向 I 共享承诺栈，可以合并成一篇。

**★★ 方向 IV：可验证的自我声明（Grounded Self-Verification）**

- **为什么**：23/30 失败声称成功且信心与终距无关；模型自己的成功声明没有任何评估价值。对任何需要“连续多任务不 reset”的部署，这比 SR 本身更致命。
- **机制设想**：到达声明必须附带可检验证据（指令终点描述 ↔ 当前观测的显式对齐；子句完成表；与指令隐含距离的一致性）；一个独立的验证器（可以是同模型单独上下文，或训练的小判别器）给出校准过的置信度。
- **价值**：单独只救 7/30，但作为方向 I 的触发器与方向 V 基准的必需组件。

**★ 方向 V：持续自主基准（reset-free multi-goal）**

- MIP 附录 E 给出了 AutoEA 五条要求但没有实现；ReasonNav 的医院环境是唯一接近的。一个在同一场景内连续下达 5–10 个目标、不 reset、记录状态复用与错误累积的基准，会把主线 A/B 的价值第一次量出来。影响大但工程重，适合作为第二年的工作或合作项目。

**★ 方向 VI：接口反馈与约定（快速小文章）**

- `step()` 返回实际位移 / 碰撞，消除类别 D 并削弱 C；动作约定文本的系统消融。一周可做完，适合作为阶段 0 的预热实验，不建议单独成文。

### 4. 建议的主线与论文序列

主线命名：**自校正的 agentic 导航（Self-Correcting Agentic Navigation）**——从“模型能诊断但不修正”这一实证观察出发，先用机制补上修正环，再把修正能力训进开源模型，最后在长时程上验证。

| 顺序 | 论文 | 方向 | 平台 / 模型 | 预期主结果 |
| --- | --- | --- | --- | --- |
| 1 | 承诺感知回溯 + 到达验证（零样本） | I + IV | MIP / 前沿模型 + qwen3.6-plus | rand100 SR 70 → 78+，静默失败率 77% → <30% |
| 2 | 工具使用与回溯的 RL 后训练 | II | MIP / Qwen3.6-27B | 开源模型最小接口 45 → 60+ |
| 3 | 有界状态下的长时程 agentic 导航 | III | RxR-CE | SR 26 → 40+，上下文 49k → <16k |

论文 1 与内省进化线共享标注与归因方法，论文 2 与 ETP-R1 / VQ 线共享 RL 基础设施，论文 3 与历史窗口截断的发现直接衔接。三篇可以共用一个代码库（MIP 扩展）。

### 5. 明确不做的

- 不在前沿闭源模型上继续“加工具”——收益上限几个点，且不可复现（serving path 漂移，±3.5 方差）。
- 不做多角色多智能体——无角色收益证据。
- 不做重型 3D 重建记忆——稀疏锚点已够，成本不匹配。
- 不先做跨 episode 规则库——收益小、定义争议大。
- 不把停止判别器当独立论文——只救 7/30。

## 十、核心问题：从 24 篇论文自身的证据中挖掘

本节取代第九节第 3–4 小节。方法：对每篇论文只记两件事——它在引言里声称要解决什么，它自己的消融和失败分析实际指向什么。两者的偏差就是要找的东西。

### 1. 声称的问题 vs 证据指向的瓶颈

### 2. 三条跨论文的规律

**规律一：动机和发现系统性地错位。** 上表左列几乎全是感知、接口、工作流、推理；右列几乎全是“去掉某种对自身状态的显式表示后崩盘”或“决策在已知信息下仍然错”。没有一篇的引言把“智能体不知道自己在指令的哪一步、在空间的哪个位置、已经承诺了什么”当作问题提出，但几乎每一篇的最大消融都落在这里。

**规律二：对“状态表示”的干预收益大，对“推理”的干预收益小。** 把所有消融按干预对象分两组：

| 干预对象 | 例子 | 幅度 |
| --- | --- | --- |
| 空间状态（我在哪、去过哪、哪里可达） | ARNA 栅格、SpaceVLN 层次记忆、MetaNav 空间记忆、ReasonNav 俯视图/已访问表、AgentVLN 像素投影、EvoMemNav 粗筛、HarnessVLN 时空图 | −67、−14.4、−12.8、−41.7/→ 0、+21.1、+11.6、+6 |
| 进度状态（指令执行到哪、哪句已被证据满足） | DiscussNav 完成度估计、HarnessVLN 进度/事件记忆与停止验证、SpaceVLN 带进度字段的 Spatial-CoT | −10.3、+8/+4、−8.5 |
| 推理本身（反思、预反思、多专家、推理预算、每步 CoT、查询式推理） | MetaNav、EvolveNav、EvoMemNav RDCMA、DiscussNav 决策测试、MIP effort、VLingNav 每步 CoT、AgentVLN QD-PCoT | −5.1、+3.5/+5.1、+4、+5.5、−5…+10、**负**、+1.6 |

推理侧干预没有一个超过 6 点（MIP fable-5 的 +9.7 是例外，但同表其他七个模型均在 −5 到 +6）。状态侧干预普遍在 10 点以上。EvolveNav 还给了一个反向证据：当决策被外部规则约束后，换 backbone 结果差在 0.3 以内——一旦状态被结构化，推理能力的差异就被抹平了。

**规律三：同一个失败模式跨越了三年和约 40 个 SR 点的模型进步。** NavGPT 2023 的 Fig.10：模型在进入房间前已认为自己进了。MIP 2026 的 ep56：站在正确的门口，推理写着“完全在 3 米限制内”，然后重新解析指令又走了 7 米。GPT-4 到 fable-5，SR 从 34 到 72，这个失败一模一样。MIP 的 15/30“说出正确怀疑却不行动”和 23/30“信心与终距无关”是同一件事的两个侧面：推理结论产生了，但没有一个地方接住它并让它影响下一步。

### 3. 核心问题的表述

**Agentic navigation 把控制权交给了模型，却把状态留在了上下文里。** 具体是三种状态：

1. **进度状态**：我在指令的哪一句，哪些句已经被观测证据满足。（NavGPT、DiscussNav、HarnessVLN、SpaceVLN、MIP 类别 B 都在这里失败。）
2. **空间状态**：我在哪、去过哪、哪些分支未探索。（ARNA、SpaceVLN、MetaNav、ReasonNav、MIP 类别 C 和真机“持久空间状态”。）
3. **承诺状态**：我把指令中的指代绑定到了哪个实例、选了哪个分支、有多确定。（MIP 类别 A 12/30，AgenticNav “错分支/错实例”，BUMBLE。）

上下文作为状态载体有四个结构性缺陷，每个都在文献里有对应的症状：它只能追加不能修改（绑定写下就成了事实 → 20/30 不回溯）；它无界增长（→ 49k token、RxR 26）；它无法对照环境验证（→ 成功声明与终距无关）；它不可检查（→ 失败只能事后人工审计，无法在线归因）。空间记忆是各家唯一普遍外化了的状态，所以它的消融幅度最大；反思只是往上下文里再写一段文字，所以它的幅度最小。

### 4. 为什么这是 agentic 范式特有的问题

用 MIP 附录 F 的分类：策略式系统（NaVid、StreamVLN）的状态在训练出来的隐状态/KV cache 里；工作流式系统（MapGPT、SmartWay、双系统）的状态在固定管线的地图和规划器里。Agentic 系统把控制流交给模型时，默认也把状态交给了模型的上下文。前 LLM 时代的离散 VLN 已经把这一层做过一遍：进度监视器（Self-Monitoring, 2019）、带回溯的搜索（FAST, 2019）、多假设重排（Speaker-Follower）、子指令对齐。MIP 的 51 篇参考文献里没有任何一篇。HarnessVLN 的进度记忆（子目标四态、完成需位姿对齐的观测）是离重建这一层最近的，也正是它收益最大的部分；但它存的是事实而非带不确定性的假设，所以承诺错误仍然无法修正。

还有一个结构性原因让这个问题被系统性地低估：**基准是 episodic 的**。每个 episode 从干净状态开始、一个目标、结束即重置（MIP 附录 E、S1 评测一节）。R2R-CE 平均 55 步、一句指令、一次停止，状态错误没有机会累积。一旦任务变长（RxR）或连续（GOAT 的多子任务，EvoMemNav 的收益在子任务 3–5 才出现），状态问题立刻成为主导。领域在一个对核心问题不敏感的基准上优化，所以才会把注意力放在接口和推理上。

### 5. 可能的反对解读及其证据

- **“瓶颈是模型，等模型变强就行”**。反证：同一模型加推理预算基本无效；opus-5 与 fable-5 接近；人类在同一接口上 94；且同一失败模式从 GPT-4 持续到 fable-5。模型变强提升的是隐式状态追踪的能力，但隐式状态无法修改、验证和有界化。
- **“瓶颈是感知/grounding”**。部分成立：AgentVLN 的 +21 和 ReasonNav 真机 60% 检测失败支持这一点。但 MIP 的 30 个失败里几何/感知类只有 3 个，ep79 的真目标在第一帧就可见；AgentVLN 的像素投影本质上也是把“哪里可达”这个状态外化到图像上。
- **“瓶颈是接口”**。只对弱模型成立（航点 +38 对 4B，+0.7 对 fable-5）。

### 6. 由此导出的研究问题（一个问题，五个子问题）

**当 LLM 是决策者但不应该是状态载体时，任务状态应该如何表示、更新、验证和有界化？**

| 子问题 | 文献现状 | 空白 |
| --- | --- | --- |
| 表示：三种状态各值多少，哪种先做 | HarnessVLN 累积消融是唯一尝试，但在重感知栈上且未隔离承诺状态 | 没有人用 oracle 逐个隔离过 |
| 更新：承诺如何被修改 | HarnessVLN 失败注解衰减（事后）；FAST 的回溯（前 LLM 时代） | 没有任何 agentic 系统把绑定当作可修改的假设 |
| 验证：状态如何对照环境而非对照模型自己的叙述 | HarnessVLN F\_stop 三项；REMAC 前/后置条件 | 只验证停止，不验证中途承诺 |
| 有界：时程增长时保留什么 | VLingNav 遗忘曲线采样；HAMT 上历史 3–6 步饱和 | 无人报告 SR 随上下文预算的曲线 |
| 写入者：模型写、规则写、还是学出来 | ARNA 模型自写（无验证）；HarnessVLN 规则写（作者自认局限） | 没有学习型的状态更新 |

### 7. 直接检验核心问题的实验

在建任何系统之前，先回答“这三种状态各值多少”。MIP 平台、rand100、固定模型，分别只喳给智能体一项 oracle 信息：

- O-进度：当前应执行的子指令编号（来自 GT 对齐）
- O-空间：带自身轨迹的俯视图，不含目标
- O-承诺：指令命名的物体在图像中的正确实例标记
- O-偏离：“你已偏离”的二值信号，不说去哪
- 以及全部叠加

基线是 fable-5 的 70 和 qwen3.6-plus 的 45，天花板是人类的 94。如果叠加后接近 94，核心问题成立且每个分量的价值被量出来；如果叠加后仍在 75 以下，那么瓶颈确实在推理，agent 侧的研究空间很小——这个否定结果同样重要。成本约 500–600 个 episode 的 API 调用，无需训练。这个实验的结果决定后面做什么，所以它应该是第一个实验。
