## 一、整体 IDEA

**一句话：agentic 导航智能体在分支处把指代和路线绑定成事实，之后即使自己说出了怀疑也不会撤销；本方法把这类绑定登记为带备选的可撤销承诺，由 harness 从指令结构算出矛盾，矛盾时拒绝继续执行，强制模型在"用新证据辩护"与"撤销回退"之间二选一，辩护须经独立验证。**

### 问题

MIP（2607.26148）在 R2R-CE rand100 上对 30 个失败 episode 逐个审计：12 个错误指代或错误分支、7 个停止决策、8 个失控搜索、3 个几何陷阱；其中 20 个在分支处绑定局部最佳匹配后永不回溯，至少 15 个的推理已逐字说出正确的怀疑却照样走下去，23 个在 3–34 m 外声称成功且信心与终距无关（02 §八）。AgenticNav 把 88.9% 的仿真失败归为 VLM 决策（错分支、错实例、oracle 成功未停）；GPT-6-Astra 工作流论文（2609.20116，摘要级）在同一子集上观察到"judgments do not always lead to progress or appropriate stopping"。这类失败是**承诺后不修正**，不是感知或停止判断：30 例里只有 5 例曾进入 3 m 成功区。

现有零样本 harness 对它的处理有三种，都不够：HarnessVLN 记录失败注解并提供 backtrack 工具，回溯由模型自选；HAM-VLN 让模型自己写进度与失败笔记，回溯"建议性而非禁止性"，1,288 次决策中 175 次自愿回溯，R2R-CE 100 集 SR 61.0 且 OSR–SR 差距仍有 17.7；C²Nav（2609.15142，摘要级）让 VLM 在承诺前比较控制器构造的备选并提供可撤销的 walk-back，但在同一 rand100 协议、同一 gpt-5.5 上只有 44，低于 MIP 两个工具的最小接口 52。三者的共同点：**承诺是否撤销由模型自己决定，没有任何一方从指令结构里算出"你现在的承诺已经与指令矛盾"并强制模型处理**。

### 机制

三个部件，均在 harness 侧，不训练、不加传感器（RGB + 相对里程计，见 §9.1）：

1. **可撤销承诺**。指令解析为子句后，凡活跃子句含地标或房间，harness 在放行下一次 `step()` 前要求模型 `commit(子句, 选择, 备选, 证据)`；备选由 harness 从当前观测中保留缩略图，模型不能以"无备选"跳过（同类实例 ≥2 时强制登记）。承诺登记时记录可回退的位姿锚。
2. **结构矛盾**。harness 从子句类型与指令结构得到可检查约束：子句预算（R1，从解析出的地标/房间条件化，GT 只用于离线校准）、顺序（R2）、承诺后地标持续不可见（R3）、进入类子句后房间不符（R4）、停止时路程异常（R5，只保留过长侧）、同子句内回环（R6）。任一触发即置 contradicted。
3. **强制修订**。contradicted 时 harness 拒绝 `step()`，把最近一个有存活备选的承诺连同备选缩略图呈给模型，只接受 `defend(证据)` 或 `revise(备选 | 回锚)`。defend 由一次独立、无历史的验证调用裁决，问的是区分性问题（当前证据与备选相比是否同一实例且更符合子句）；同一承诺第二次矛盾不再允许 defend。`satisfy(子句, 证据)` 对 pass/enter/turn 类子句要求跨帧证据对（首见地标帧、当前帧、两者间位移），验证"走过/进入"而不是"可见"；`request_stop` 通过当且仅当全部子句 satisfied、末句证据与当前位姿对齐、无 contradicted。

进度账本、锚点图、`recall` 都是让上述三件事可计算的实现，不作为贡献。模型继续持有自己的推理转录（编码智能体 harness 的默认行为），状态摘要只作为工具返回值出现。

### 主张（可证伪，主模型 gpt-5.5，rand100，MIP 协议）

- SR 显著高于同模型的最小接口（52）、AgenticNav（55）与 C²Nav（44），目标 ≥ 60；增益集中在 A/C 类失败，而非均匀分布。
- 相对"同一代码、同样的承诺与验证、但矛盾只记录不阻断、defend 不限次"的对照（HarnessVLN 式）与"模型自写状态、自愿回溯"的对照（HAM-VLN 式），强制修订是最大单项。
- 静默失败率（首次 request_stop 时终距 > 3 m 的比例）下降，harness 置信与终距的相关显著高于"已走路程"这一平凡预测器。
- 在 fable-5 上不为负（可选臂）。

若 gpt-5.5 上本方法 < 57（最小接口 + 5），方法不成立；届时只剩 §五 E0/E5 的分析结果。

### 为什么是现在

MIP 给出了冻结协议、逐 episode 失败审计与开源平台；rand100 上已有三篇同模型（gpt-5.5）的 harness 结果可直接对照；任务 #2 已证明子句级进度可从 FGR2R 自动构造、矛盾规则可在 GT 上校准误报率。缺的只是把"怀疑"接成"必须做决定的节点"这一件事。

## 二、方案概述

### 角色分工

LLM 做三件事：解析指令为子句序列（每 episode 一次）、解释当前观测（观测模型）、选择下一步动作（决策者）。Harness 做三件事：持有三种状态、校验每次状态转移是否有证据、在状态出现矛盾时强制模型复核。模型不能用自由文本修改状态，只能通过受限操作。

### 三种状态

| 状态 | 内容 | 写入条件 | 模型每步读到的 |
| --- | --- | --- | --- |
| 进度账本 | 子句序列，每句状态 ∈ {pending, active, satisfied, contradicted}，附证据指针（观测 id + 位姿） | satisfied 必须附证据指针；contradicted 由 harness 依结构约束判定（见下） | 当前子句、已满足子句的一行摘要、剩余子句数 |
| 空间锚点 | 决策点的稀疏拓扑：位姿、缩略图、已探/未探出口、关联子句 | 每次分支选择或承诺时建锚；实际位移从 `step()` 返回值写入（而非命令值） | 当前锚、最近 k 个锚、每锚未探出口数 |
| 承诺账本 | (子句, 所选实例/分支, 已见备选, 证据, 置信) | 每次指代绑定或分支选择时写入；备选由 harness 从当时观测中保留缩略图 | 活跃承诺及其存活备选 |

三个账本加起来几百 token，作为每次工具返回值附带的状态摘要；模型保留自己的推理转录（编码智能体 harness 默认行为），历史观测按锚点 recall。

### 每步协议

输入：当前 RGB + 三状态摘要 + 工具集。工具：`observe`、`step`（与 MIP 同，但返回实际位移）、`recall(anchor)`、`commit(clause, choice, alternatives, evidence)`、`satisfy(clause, evidence)`、`revise(commitment → alternative | back_to_anchor)`、`request_stop`。模型在自由推理后必须以这些操作之一结束本步；推理文本不进入下一步输入。

### 关键机制：矛盾触发的强制复核

Harness 从指令结构里得到每个子句的可检查约束：预期在 N 步或 D 米内出现的地标、房间类型、剩余子句数与已走距离的比例。当当前子句的约束被违反（例：“走到走廊尽头”已走 15 m 而走廊未结束；“右转进卧室”后观测到厨房），该子句置为 contradicted，harness 拒绝下一个 `step`，把最近一个有存活备选的承诺连同备选缩略图呈给模型，只允许两种输出：用新证据 `defend`，或 `revise`。这把 MIP 中“推理里说出了怀疑”变成一个必须做决定的节点，而不是一句会被下一步忘掉的话。

停止同理：`request_stop` 通过当且仅当全部子句 satisfied、末句证据与当前位姿对齐、无 contradicted（继承 HarnessVLN 的 F\_stop 三项）。成功声明的置信定义为活跃承诺置信之积，用于校准评估。

### 最小版与完整版

最小版只有进度账本 + 承诺账本 + 强制复核，空间状态仅保留承诺时的位姿供回退；完整版加锚点图与 recall。先做最小版，它足以检验主张的核心（可修改 + 可验证）。

### 与现有系统的差异

|  | MIP 最小接口 | AgenticNav | HarnessVLN | SpaceVLN | 本方案 |
| --- | --- | --- | --- | --- | --- |
| 状态载体 | 全部转录 | 转录 + 轨迹地图 | 事件记忆 + 时空图，存事实 | 拓扑路点序列化为文本 | 三账本，承诺存为假设 |
| 承诺可修改 | 否 | 否 | 失败后注解衰减 | 否 | 是，带备选 + 强制复核 |
| 完成需证据 | 否 | 否 | 是 | 部分 | 是 |
| 模型读什么 | 全转录（中位 33k） | 全转录 + recall | 检索 top-K | 序列化记忆 | 全转录 + 状态摘要作为工具返回值（v1 起不主张只读状态） |
| 传感器 | RGB | RGB-D | RGB-D + 检测器 + FMM | RGB-D + 检测器 | RGB（与 MIP 同） |
| 回溯 | 无 | 无 | 工具，模型自选 | 无 | 矛盾触发，harness 强制 |

v1 补充两行（摘要级）：C²Nav（2609.15142）承诺前由 VLM 比较控制器构造的备选、route sketch 持有相邻子指令段假设、可撤销 walk-back；承诺后无矛盾检测与强制修订；gpt-5.5 rand100 SR 44。RegenHarness（2609.27612）证据门控、版本化记忆区分观测事实与已接受进度、commit gate 控制可信状态更新；真机四足，无冻结基准、无消融。

与 HarnessVLN 的差别集中在两点：承诺是带备选的假设而非事实；复核由 harness 算出的矛盾触发并强制，而非由模型自愿（v1 删除"只读状态"这一差别）。且本方案在 RGB-only 的最小传感器上运行，收益不能归因于深度或检测器。

## 三、核心贡献

**C1 方法：矛盾门控的承诺。** 把指代与分支绑定登记为带备选的可撤销假设，由 harness 从指令结构计算矛盾，矛盾时拒绝执行并强制模型 defend 或 revise，defend 须经独立验证，完成与停止须经证据门控。与 HarnessVLN 的差别在"触发者与裁决者"：矛盾由规则算出而非模型自愿，defend 由独立调用裁决而非自报；与 HAM-VLN 的差别在"谁写状态"：承诺与进度转移由 harness 门控而非模型自书；与 C²Nav 的差别在"承诺之后"：C²Nav 在承诺前比较，承诺后无矛盾检测与强制修订。

**C2 实证：同模型同子集的主表。** gpt-5.5 + MIP 协议 + rand100，与 MIP 最小接口（52）、AgenticNav（55）、C²Nav（44）、GPT-6-Astra 工作流（52，50 集）同表；再加两个自家实现的对照（HAM-VLN 式自写、HarnessVLN 式验证不强制），同一份代码只差开关。报告 SR/SPL/NE/OSR、四类失败计数、静默失败率、调用数与 token。主结果在全量 val_unseen 上复核。

**C3 分析：状态与验证各值多少。** (a) oracle 分量（进度 / 空间 / 承诺 / 偏离，GT 版与"harness 可达"版）给出上界；(b) 加法阶梯消融（自写 → 验证 → 假设化承诺 → 强制修订）隔离每个部件；(c) 校准：置信–终距相关对照路程基线；(d) 失败审计：干预前后四类分布变化，首个 contradicted 承诺与首个偏离步的对齐率。

不声称的：不声称新的记忆表示或工具集；不声称 SOTA（训练式方法全量 66–70）；不声称"状态外置"原则（HAM-VLN、HarnessVLN、SpaceVLN、RegenHarness、LongHorizon-Harness 都已做）；不声称有界上下文。

## 五、实验计划与判据

平台与协议与 v0 相同：MIP、habitat-sim 0.3.3、rand100、512×512 RGB 90°、500 步 / 200 次调用、3 m 成功阈值。主模型 gpt-5.5（codex CLI 座位）；第二模型 gpt-6-astra 预留，本阶段不启用；fable-5（Claude 订阅，cc 座位）作可选强模型臂。统计口径统一：rand100 上只报描述统计与配对 bootstrap CI，分辨率 5 点；结论性判据放在全量 val_unseen（或按 scene 与子句数分层的 ≥500 集预注册子集）上的配对比较（McNemar / 配对 bootstrap）；同一 family 的多重比较用 Holm。所有配置冻结后再跑，预测写在跑之前。

指标：SR / SPL / NE / OSR / nDTW；A1（感知误识）/ A2（有备选而选错）/ B / C / D 失败计数（LLM 初标 + 人工抽检 20%）；静默失败率 = 首次 request_stop 时终距 > 3 m 的比例，另报"耗尽预算且从未 request_stop"比例；置信–终距 Spearman 及其对"已走路程""已用步数"两个基线预测器的优势；矛盾触发次数、defend/revise 比例与各自成功率、回溯次数与步数；主模型调用、验证器调用、总 token、壁钟。

### E-P 先导（第一个付费实验，决定是否继续）

gpt-5.5，rand100 前 20 集，三臂各一次：最小接口 / HarnessVLN 式（验证不强制）/ 本方法。目的不是出数字，是确认机制会响：报告每集矛盾触发次数、defend/revise 次数、验证器调用数、回溯步数，以及三臂的 SR 与失败类别。**判据：本方法在 20 集上触发率 < 30% 或 SR 低于最小接口，则回到 §九修触发器，不进入 E1。**

### E1 主表

臂：(a) 最小接口，引用 MIP 52 并同窗自跑一次；(a') 最小接口 + max effort；(b) AgenticNav 55 与 C²Nav 44、GPT-6-Astra 工作流 52 引用；(c1) 自写状态臂：同代码，commit/satisfy 由模型自报、矛盾只记录、回溯自愿（HAM-VLN 式）；(c2) 验证臂：satisfy 经验证器门控、停止验证、矛盾只记录不阻断、defend 不限次（HarnessVLN 式）；(d) 本方法；(d+) 本方法 + GT 子句切分（oracle_progress_rand100.json 已有，隔离解析误差）。(c1)(c2)(d) 共享全部基础设施，验证器在 (c1) 照常调用只写日志以等成本。

判据：(d) ≥ 60 且 (d) − (a) 的配对 CI 不含 0；(d) − (c2) ≥ 5（强制修订的价值）；(c2) − (c1) 报告但不作主张；增益集中在 A2 + C（减少 ≥ 30%，新增失败 ≤ 减少量一半）；SPL 不低于 (a) 3 点以上。全量 val_unseen 只跑 (a) 与 (d)。

### E2 加法阶梯与机制消融（rand100，先 1 次筛出 ≥5 点的再重复）

从 (c1) 出发逐级加：+验证门控 → +假设化承诺（备选与回退锚）→ +强制修订。再在 (d) 上单项替换：强制修订换成同内容的可忽略提示（2×2：决策强制 vs 建议式 × harness 代回溯 vs 模型自行回溯，条件分析只在"至少触发一次矛盾"的子集上做，触发率 < 20% 判不可解释）；验证器 = 主模型独立上下文 vs 小模型；里程计三档（模型可见 / harness 无里程计 / 加噪）；规则阈值 ×2 与 ÷2；去掉备选与置信（承诺存为事实）。

### E0 oracle 分析（降为分析节，不作 go/no-go）

在 (a) 上分别注入：O-进度（静态切分 / 动态 idx 两档，动态档只在未偏离时更新，屏蔽末子句零长度转移）、O-空间（harness 可算的锚点/出口计数图；完整占据图单列为感知上界）、O-承诺（分支偏离二值信号，见 06 T3.6(b)）、O-偏离、O-全部，以及"可达 oracle"（只注入 R1/R5/R6 触发与验证器子句状态）和噪声/延迟版（p ∈ {1.0, 0.9, 0.8}，k ∈ {0, 3}）。用途：给出三种状态的上界与方法的真实上界，并回答 harness 自身估计必须达到的准确率。判据只作描述。

### E3 长时程（副实验）

零费用先做：从 MIP 公开运行注册表统计 RxR-CE 的 end_reason 与末次 token。再跑 RxR-CE 100 集英文：(a) vs (d)，前置用 Landmark-RxR 构造 RxR 侧 O-进度并在 RxR train GT 上重校准 R1/R5。报 SR/SPL/nDTW、预算耗尽率、回溯步数占比。不主张有界上下文。

### E4 第二模型

gpt-6-astra 在 E1 全部结束后启用：(a)(c2)(d) 三臂。fable-5（cc 座位）可选，只为检验"强模型上不为负"。E-P 与 E1 期间不跑。

### E5 校准与审计

按上文指标定义；t* 用 O-偏离首步作自动代理，30 例上与人工核对一致率；首个 contradicted 承诺与 t* 的对齐率（±5 步）。

### 预算与顺序

E-P 60 集 → 20 集基线失败轨迹上的规则 ROC（零费用）→ E1 rand100（约 600 集，含 (a)(d) 各 3 次）→ E2（约 600 集）→ 全量 (a)(d)（3,678 集）→ E0（约 800 集）→ E3（200 集 + 前置）→ E4。费用以 codex 订阅额度计，T3.3 实测每日吞吐后再定各阶段日程。

## 七、定位与衔接

### 与最近两篇的关系

MIP 问的是“模型能不能掌控循环”，答案是能；它自己的讨论章把下一步定为“harness 需要选择性的持久状态和有界上下文，模型需要从已承诺的错误中恢复”。本工作问的是“循环里必须持有什么是模型持有不了的”，是它的直接后续，并且用它的平台、协议和失败分类。

HarnessVLN 证明了进度记忆是最大增益项，但它把这当作“一个统一 harness 的组件之一”，没有把“状态载体”当作问题本身；它的基线已带 RGB-D、检测器和规划器，所以无法回答状态本身值多少。本工作在它的基础上变两件事：事实改为假设，自愿回溯改为矛盾触发。

### 与前 LLM 时代 VLN 的关系

进度账本是 Self-Monitoring 进度监视器的符号版；矛盾触发回溯是 FAST 的回溯但触发条件来自指令结构而非学习的进度分数；承诺账本的备选是 Speaker-Follower 多假设的稀疏版。不同之处是这些机制当年是训练出来的、在离散图上、靠全景特征；现在是零样本、连续环境、单目 RGB，由 LLM 提供观测信号。这个对照本身可以是论文相关工作的主线。

### 与现有工作线的衔接

- 子指令与轨迹段对齐（R2R-CE / RxR-CE，Landmark-RxR）：直接是 E0 的 O-进度真值和进度账本解析质量的评测集。
- 历史窗口 3–6 步饱和的发现：是“模型只读状态不读转录”的经验前提，可直接引用。
- 首个偏离步 t\* 的诊断探针：E5 里“首个 contradicted 承诺”与 t\* 的对齐率就是它的在线版验证；两条线共享标注。
- TTA 线的子指令 grounding 信号：可作为 `satisfy()` 的证据打分器，替代纯 LLM 判断。
- 双层技能系统的路由器：如果后续要把复核策略训出来，它就是路由器的学习目标。

### 一句话定位

这不是一个新的导航系统，是一个关于“LLM 智能体里什么必须在模型之外”的受控实验，导航是它的测试床。

## 八、新颖性核查（2026-09-23，基于摘要，全文待读）

### HAM-VLN（2607.29600，2026-07-31，中科院自动化所）：重叠最大的先行工作，贡献边界据此重划

**它做了什么。** 零样本双过程：System 2 = Gemini-3.1-Pro 每航点调用一次，在同一次调用里既输出动作又写入记忆（房间类型、物体、**指令进度**、失败笔记）；System 1 = Qwen3.6-35B 把方向落到像素框，深度反投影，快速行进控制器。持久状态是深度接地的“地点–物体”世界图（Grounding DINO + SAM）+ 有序进度记录 L\_t（第一个 pending 项 = 当前子目标）。四个记忆视图：工作（K=1 帧）、情景、语义、反思（附在被放弃地点上的失败笔记）；每步按子目标检索一个图切片进上下文。回溯是 System 2 自己选择的动作，放弃的分支被标为失败证据，“建议性而非禁止性”。传感器：RGB-D + 里程计 + 内参。

**数字。** R2R-CE 100 条子集（沿用 LaViRA 的子集，**是否等于 rand100 未知**）：SR 61.0 ± 1.7 / SPL 48.1 / OSR 78.7 / NE 3.92；RxR-CE 52.7 / 35.7 / nDTW 54.3；HM3D-v2 ObjectNav 79.7 / 43.2。消融：去世界图（K=1） 51.7，换成全原始历史 53.3；去情景或语义记忆 53.3；去反思记忆 55.7（SPL 36.9）；全去 50.7。上下文 17.9k token / 决策，244.9k / episode（全历史 746.1k）。100 个 episode 里 1,288 次决策中 175 次回溯（13.6%）。

**与本方案的重叠**：显式进度记录在模型之外、稀疏空间图、可回溯、失败笔记、有界上下文、零样本、同一组基准。我之前写的“零样本视觉导航是信念瓶颈路线尚未触及的地方”**不再成立**，第一节该句要改。

**它没有的、也就是本方案必须站住的地方**：

## 九、方法规格 v0（伪代码级）

补上第二节留空的三个机制：矛盾怎么判、证据怎么验、置信从哪来。原则：所有判定由 harness 用可计算规则或独立上下文的小查询完成，不接受主智能体的自报。

### 9.1 一个前置决定：harness 使用相对里程计

MIP 的最小接口对模型隐藏位姿，但它自己的失败分析把“缺少运动信号”列为第二大原因。本方案的 harness 用**实际执行的原语做航位推算**（仿真器里取真实位移，真机上是腿式里程计 / IMU）维护锚点和距离累计；模型仍然看不到绝对位姿。这是与 MIP 的一个明确差异，写成设定而非贡献，实验里三档消融（模型可见 / harness 无里程计 / 加噪，E2）。

### 9.2 数据结构

```
Clause      {id, text, type∈{move,turn,pass,enter,stop_at}, landmark, room, 
             status∈{pending,active,satisfied,contradicted}, evidence:[obs_id], 
             budget:{max_dist, max_steps}, used:{dist, steps}}
Anchor      {id, pose(dead-reckoned), obs_id, clause_id, exits:[{heading, explored}], step}
Commitment  {id, clause_id, anchor_id, choice:{kind∈{referent,branch}, desc, heading|bbox},
             alternatives:[{desc, heading|bbox, obs_id}] | none_visible,
             evidence:[obs_id], verif_agree:int, contradictions:int, 
             status∈{active,defended,revised,retired}}
StateSummary (每步渲染给模型，目标 ≤ 600 token)
  指令全文；每子句一行（编号、状态、已用 dist/预算）；活跃承诺及备选数；
  当前锚与最近 k=3 个锚的未探出口数；上一步实际位移/旋转/是否受阻；剩余动作预算
```

StateSummary 作为每次工具返回值附带；模型输入由编码智能体 harness 管理（含其自身转录）。v1 不再要求"只读状态"。

### 9.3 工具的前置 / 后置条件

| 工具 | 前置 | 后置 |
| --- | --- | --- |
| `observe()` | — | 归档 (obs\_id, 图, 航位位姿) |
| `step(actions)` | 无未处理的复核请求；活跃子句含 landmark/room 且无 active 承诺时拒绝并要求先 commit | 返回 {executed, realized\_dist, realized\_rot, blocked}；更新活跃子句 used；更新锚点出口已探标记；运行矛盾规则 |
| \`commit(clause, choice, alternatives | none\_visible, evidence)\` | clause 为 active；evidence 含当前 obs |
| `satisfy(clause, evidence)` | clause 为 active；之前子句均 satisfied（否则触发 R2）；pass/enter/turn 类子句 evidence 为跨帧对（首见地标 obs、当前 obs、两者间航位位移）；stop_at/move 类为当前 obs | 独立验证查询通过 → satisfied、下一句 active；R1 的 used.dist 不因 satisfy 重置，改为自上次经验证器确认的地标位置起累计；不通过 → rejected(reason)，计入该子句 reject 次数 |
| `recall(anchor)` | anchor 存在 | 返回该锚图像（不进入持久上下文） |
| `revise(commitment, to_alternative(j) \| back_to_anchor)` | commitment 为 active/defended | harness 按航位推算反向执行到锚点位姿（或反放原语带）；该承诺之后的子句重置为 pending；清除 contradicted；若选 to\_alternative 则自动建新 Commitment |
| `defend(commitment, evidence)` | 仅在 harness 已发起复核时可用 | 验证为区分性问题（备选缩略图 + 当前证据，是否同一实例且更符合子句）；通过 → defended，contradictions+1，预算延长到 max(剩余, 一个子句中位数)；同一承诺第二次复核不允许 defend，只能 revise；无承诺或备选为空时退化为 back_to_anchor 到该子句 active 时的位姿 |
| `request_stop()` | — | F\_stop = 全部 satisfied ∧ 末句证据在当前位姿 1 m 内 ∧ 无 contradicted；否则返回具体未满足项 |

### 9.4 矛盾规则 v0（harness 端，无 LLM，每条单独可开关）

| 规则 | 触发条件 | 参数来源 |
| --- | --- | --- |
| R1 预算超支 | 活跃子句 used.dist > budget.max\_dist 或 used.steps > max\_steps | 按子句类型取 P99（任务 #2 校准：P90 误报 31%，P99 2.45%，见 rules_v0.json）；v1 目标改为按解析出的地标/房间条件化的预算，GT 只做离线评测 |
| R2 顺序违反 | 对子句 j 调 satisfy 而存在 i\<j 为 pending | — |
| R3 地标缺失 | 子句有 landmark，commit 后连续 M=3 次独立验证“不可见” | M 在校准集上定 |
| R4 房间不符 | enter 类子句 satisfied 后连续 2 次验证房间类型不符 | — |
| R5 停止距离异常 | request\_stop 时总路程 > 2× "同子句数指令的训练集路程中位数"（v1 只保留过长侧，任务 #2 显示过短侧误报 32/36） | R2R-CE 训练集统计 |
| R6 回环 | 同一子句内，当前位姿进入 ≥ 10 个前进步之前经过的位置 1.0 m 内（与任务 #2 校准口径统一，转向不计步） | 任务 #2：(1.0 m, 10 步) 误报 2.28% |

**规则校准（必做，在任何智能体实验之前）**：把 GT 轨迹回放进 harness，任何规则触发都是误报。在 R2R-CE 训练集上调参使每条规则误报率 < 5%，在 val\_unseen GT 上报告。这一步不需要 LLM（R3/R4 需要验证查询，可用开源 VLM 做）。

### 9.4b 触发结构 v1.1（2026-09-25，任务 #3 T3.7(a) 之后）

任务 #3 在 20 条真实 gpt-5.5 轨迹上回放 v0 规则：R6 在 8 个成功 episode 上全部误触发，R1/R5 各 5/8；GT 最短路上校准的 <5% 误报不迁移到智能体轨迹（成功的智能体本来就绕路、回头、反复观察）。因此矛盾触发改为两级：

1. **疑似**（harness 规则，零成本）：R1 预算、R5 过长、R6 回环、以及"分支偏离"（承诺后朝向持续偏离子句地标方向 ≥ d，用无 GT 的验证器版本）只把承诺标为 suspect，并在下一次工具返回值里附一行提示，不拒绝执行。
2. **确认**（独立验证调用）：suspect 状态下每 k=3 个前进步做一次独立验证查询（子句地标是否可见 / 朝向是否指向地标 / 房间类型是否符合）；连续 M=2 次否定才置 contradicted，此时才拒绝 `step()` 并强制 defend/revise。

R6 从触发规则降为过程指标；R1 预算只在 defend 裁决时作为证据之一。E-P 先导的判据相应改为：验证器确认的触发在失败集召回 ≥ 50% 且成功集误触发 ≤ 20%（20 集）。代价：验证器成为必需部件，承诺活跃且 suspect 期间每 3 步一次 gpt-5.5 独立调用，全部计入验证器预算列。

### 9.5 独立验证查询

一次单独的、无历史的 VLM 调用：输入 (子句文本, 证据图或跨帧证据对) → 结构化输出 {landmark\_visible, room\_type, clause\_satisfied}。它不知道主智能体的推理与意图；"独立上下文不受确认偏差污染"是待 E2 检验的假设而非前提。v1 默认验证器 = 主模型的独立无历史调用（codex 座位下即另起一次 gpt-5.5 调用），小模型只作成本消融；所有验证器调用计入单独预算列。验证器评测集：正样本 FGR2R val\_unseen 子句–视点对，负样本取同子句起点帧、相邻子句帧、其他 episode 同类地标帧、偏离 > 3 m 的帧，报 precision/recall 及推出的 R3/R4 误报率；单帧 < 80% 则改用跨帧对。

### 9.6 置信

不让模型填。conf(c) = (1 + verif\_agree) / (1 + verif\_agree + |alternatives| + 2·contradictions)。成功声明置信 = 活跃承诺 conf 之积。它的唯一用途是 E5 的校准评估，不参与决策。

### 9.7 指令解析

Episode 开始时一次 LLM 调用，输出符合 Clause schema 的 JSON；失败则重试一次，再失败退化为整句作单一 clause。解析一次即冻结，不提供 merge/split（v0 §六提到的子句编辑操作删除，以免绕过 R1/R2）；退化 episode 单独计数。解析质量用 FGR2R val\_unseen 的人工校验切分评估（子句数一致率、边界 F1）。rand100 的 100 条全部有人工切分可对照。

### 9.8 回溯执行

back\_to\_anchor 由 harness 把从锚点到当前的实际原语带反向重放（前进不可逆时用转身 + 前进），步数计入 500 步预算。预算代价就是回溯的代价，不做任何豁免。

### 9.9 与最小接口的差异清单（供 E2 逐项消融）

1. 状态替代转录
2. 承诺带备选
3. 矛盾规则 + 强制复核
4. 证据门控的 satisfy
5. 独立验证器
6. 实际位移反馈
7. 停止验证

每一项都能单独关掉。

- 模型名在 `exp_workspace/bareES/configs/models/models.yaml`；mini harness 支持 `api_base`；DashScope 只支持国际站 `DASHSCOPE_INTL_API_KEY`。
- 阻塞项：服务器无任何 provider key，codex 订阅过期；8×4090 全被训练占用，无 vllm、无本地 Qwen VL 权重。

### 10.2 规则校准集

R2R-CE 训练集 GT 轨迹回放（不需智能体）：统计每类子句的子路径长度分布（给 R1 预算）、总路程对子句数的分布（给 R5）；然后在 val\_unseen GT 上报告每条规则的误报率。R3/R4 需要验证器在 GT 帧上跑，同时得到验证器本身的准确率。这一步产出一张表，直接进论文附录。

### 10.3 统计

MIP 三次重复的 sd 为 1.2–3.5。规则：rand100 上只报告 ≥ 3 次重复的格，差异 < 5 点只作描述；主结论建立在全量 val\_unseen（1,839）上，报 bootstrap 95% CI；失败类别分布变化用 χ²。所有配置在跑之前写入冻结的配置文件，E0 的预测值写入提案作为预注册。

### 10.4 成本估算方法

先跑 20 个 episode 实测。可以预期的方向：MIP 的 mini-swe-agent 每次重发全部历史，最后一次调用中位 33k token、每 episode 约 39 次调用，输入 token 在百万量级；本方案每次只发状态 + 一张图，预计低一个数量级。验证器用开源小模型本地跑。总 episode 数以 E0–E2 约 3,000、E3–E4 约 1,000、全量两配置约 3,700 计。

### 10.5 工程路线

Fork MIP；在其工具桥上加 harness 层（不改仿真器侧）；保留其运行注册表与逐 episode 归档。主智能体后端优先 mini-swe-agent（开源、可接 LiteLLM 任意模型），其次 Claude SDK。开源模型本地部署时用 8×24 GB 节点。
