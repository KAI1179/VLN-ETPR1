# Brief 02: graph generation and registration experiments

Code remains on `exp/cogmap-v2-graph-gt`. No GPU training, GPU evaluation,
Slurm submission, or remote file modification was performed for this brief.
Generated data and dry-run configurations live in the real `data_v2/` directory.

## M1 training data

`data_v2/llm_graph/{train,val_seen,val_unseen}.jsonl` contains 10,786 / 778 /
1,839 R2R rows. Each row has the existing SFT contract's `input_text`,
`target_text`, `example_id`, and `dataset` keys. Input is the instruction plus
known start position/direction; completion is semantic graph text. RxR is not
included because the existing graph CLI supports R2R only.

The Llama-3.1-8B tokenizer gives raw-target mean/P95/P99/max lengths of
310.93 / 501 / 596 / 808. Rendered completions include one EOS token.
`--max-new-tokens 640` drops 43/10,786 targets (0.398665%), retaining 10,743.
Prompt/total budgets are 1,152/1,792; no additional examples exceed them.
Full statistics and JSONL source hashes are in `data_v2/llm_graph/summary.json`.

The CPU dry run uses tokenizer files copied from an existing Llama-3.1 adapter
export; `data_v2/tokenizers/llama-3.1-8b/provenance.json` records their hashes.
The base 8B weights are absent from this checkout. Set `MODEL_NAME_OR_PATH` to
the installed **Llama-3.1-8B-Instruct base weights**, rather than an adapter-only
directory, when submitting training. The login-node path could not be checked
because its SSH hostname did not resolve.

```bash
python -m prior.cogmap_v2.llm_data --tokenizer data_v2/tokenizers/llama-3.1-8b
bash scripts/submit/llm-graph-train.sh --dry-run
# On the training host, after setting MODEL_NAME_OR_PATH:
sbatch --export=ALL scripts/submit/llm-graph-train.sh
```

The launcher preserves the existing eight-GPU LoRA/FSDP training loop: batch 1
per GPU, accumulation 1, gradient checkpointing, 10 epochs, seed 42, and LoRA
rank/alpha/dropout 32/64/0.05. It supplies a graph-specific manifest builder and
system prompt to that loop. Its explicit R2R corpus does not weaken the
existing LLM-Grid requirement to load both R2R and RxR. The shorter graph budget
changes the long-sequence cache-clear threshold from 3,072 to 1,024 tokens.

Evaluation and future reward calls:

```python
from scripts.cogmap_v2.eval_graph_text import graph_reward

reward = graph_reward(pred_text, gt_graph, instruction)  # [0, 1]
```

```bash
python scripts/cogmap_v2/eval_graph_text.py \
  --split val_unseen --predictions data_v2/llm_graph/predictions.jsonl
```

Prediction rows contain `episode_id` and `text`; scene is optional for
disambiguation outside the prompt. Invalid or missing predictions stay in the
denominator. All 1,839 GT texts round-trip exactly and receive maximum reward.

## G1 template and registration behavior

The located source is `data/logs/checkpoints/dagger_coordfusion_gt_legacy/`,
iteration 19,200. The local evaluation at
`data/logs/checkpoints/gt_coordfusion_legacy_iter19200_val_unseen_teleport_w4/eval_results/stats_ckpt_19200_val_unseen.json`
records SR **86.7863%**, SPL **77.8802%**. Its saved `config.yaml` and
`eval_args.txt` are authoritative: 30,000 iterations, seed 100, four GPU ranks
with four environments each, LR 1e-5, sampling 0.75, decay 2,000, warmup 500,
checkpoint interval **800**, teleport/tryout, y elevation, and start positions
in meters. It initializes from the no-Gaussian PriorGT `model_step_440000.pt`
and **loads pretrained map modules**. The older launcher currently hard-codes
False/400; G1 corrects these to the saved True/800 recipe.

The registration head predicts up to 16 route-order classes and sigmoid progress
from fused topological-node features. Side nodes are not classes. Auxiliary loss
is mean route CE plus mean progress MSE, weighted by `IL.reg_weight=0.1` and
added to the original DAgger CE and optional KD losses. STOP, padding,
nonfinite positions and projected distance over 2 m are ignored. All labels
come from route-polyline projection in level coordinates, using predecessor
occurrence hints. NPZ schema 2 includes the necessary `level_origin`; all
13,403 label files have been regenerated. Six train episodes have 17 route
nodes and explicitly skip auxiliary supervision, with warnings; validation
fits within 16.

Feedback pools the head's predicted probabilities and progress into one token
of map-token width. A second pass through the same fusion attention, starting
from the original graph queries, consumes the appended token. Its coordinates
are neutral, like the metadata token. No ground-truth label is fed to the
action path; the known input graph's route cardinality supplies only the class
padding mask. Both head and feedback flags default off.

Head initialization occurs after the production Hugging Face base loader,
inside a preserved RNG context. This avoids missing-head parameter
initialization changing subsequent map-encoder weights or dropout RNG. Tests
check the actual pretrained loader and navigation outputs for control parity.

## Submit and evaluate

Transfer the generated `data_v2/cognitive_maps/` namespaces and
`data_v2/cogmap_v2/registration/` to the training checkout using the usual data
sync workflow. LLM training additionally needs `data_v2/llm_graph/` and the
tokenizer files for its CPU dry run. These artifacts are Git-ignored.

G1 resolves the pretraining checkpoint from the template's translated
`eval_args.txt` or the standard repository-relative pretraining locations.
Set `PRETRAINED_CKPT` if the training host stores that same checkpoint elsewhere.

```bash
sbatch scripts/submit/g1-ln01.sh corridor_noreg
sbatch scripts/submit/g1-ln01.sh corridor_reg
sbatch scripts/submit/g1-ln01.sh corridor_reg_fb
sbatch scripts/submit/g1-ln01.sh box_noreg
sbatch scripts/submit/g1-ln01.sh box_reg
sbatch scripts/submit/g1-ln01.sh box_reg_fb
```

All six were CPU dry-run with `bash scripts/distill/run_dagger_g1.sh ARM --dry-run`.
The resolved configurations, logs and `eval_args.txt` files are under
`data_v2/runs/checkpoints/dagger_g1_<arm>/`; the comparison to the saved
template is recorded in `data_v2/cogmap_v2/g1_dry_runs.json`. Namespace, optional
head/feedback, cache root and output paths are the intended differences.
Distinct default rendezvous ports avoid collisions between arms. No SR is yet
measured for G1, and the graph-corridor control is not assumed to reproduce
86.79 without an actual evaluation.

The existing evaluation command interface is preserved:

```bash
bash scripts/distill/eval_iters.sh dagger_g1_corridor_noreg 19200
```

G1 run names select the V2 output root automatically. `eval_args.txt` restores
the correct map source, registration flags and teleport recipe. Output routing
uses `run.py --output-root data_v2/runs`, leaving historical runs' default path
behavior intact. The optional GPU probe of the existing checkpoint on whole-box
maps was not run.
