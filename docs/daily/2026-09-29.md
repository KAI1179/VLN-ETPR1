## R11′ 的 GRPO 续训脚本（patch 0023）

核查 `GRPO_trainer_ETP_PriorGT.py` / `GRPO_trainer_ETP_LLM.py`、`run_r2r/main_server.bash` 与 08-07～08-10 的 GRPO 记录后写成 `scripts/distill/run_grpo_from_dagger.sh`。关键判定：

- **加载什么**：策略全部权重（骨干、导航头、fusion、含 DAgger 训过的 tokenizer 的 map_encoder）来自 DAgger ckpt `ckpt.iter<DAGGER_ITER>.pth`，`GRPO.require_complete_checkpoint True` 保证缺一个键就报错。`MODEL.pretrained_path` 仍指 460000（构造时无条件 `torch.load` 取骨干形状），但 `load_pretrained_map_modules False`：它的 tokenizer 是死的，且分支现默认 True，历史 `llm_grid_try5_grpo` 模式在本分支会在构造时直接抛错。KL 参考策略是训练器从已加载的 DAgger 权重复制的（strict），锚点即 DAgger ckpt；优化器全新。
- **训什么、学习率**：GRPO 训练器只有一个 `GRPO.lr`，没有分模块学习率（两组仅权重衰减不同）。默认 `PROFILE=nav4`（global_encoder、graph_query_text、graph_attentioned_txt_embeds_transform、global_sap_head，234 张量），map_encoder 与 graph_map_attention 冻结，栅格通路保持 DAgger 结果不动；map_encoder 若收到梯度训练器会报错。`nav4-fusion` 历史上输给 nav4（65.42 对 66.50，已退役），仅作第二臂备用。
- **超参**：沿用 66.50 配方——LR 2e-5、无预热、余弦衰减到 0.25×、500 iter、G=8、update_epochs 1、β 0.04、ε 0.2、梯度裁剪 2.0、dropout 0.10 开、AMP 关、waypoint_aug 开、`train_10`、seed 100、4 进程 × 4 环境、`back_algo teleport`。ckpt 每 `log_every`（50）iter 存一个（GRPO 忽略 `CHECKPOINT_INTERVAL`），每个约 2.75 GB。
- **防错**：`DAGGER_ITER` 与 `CUDA_VISIBLE_DEVICES` 必须显式给出；`RUN_NAME` 不得等于 DAgger 目录（否则 requeue 会从 DAgger 目录"续跑"）；启动前用 CPU 读一次 DAgger ckpt，核对 iteration、fusion 键存在、无非有限值、tokenizer 非全零（`ALLOW_DEAD_TOKENIZER=1` 可跳过）；空闲端口 rendezvous；同目录已有 ckpt 时走 `GRPO.is_requeue True`（注意训练器此时把 KL 参考换成续跑的 ckpt）。
- 本地用 stub ckpt（含一个死 tokenizer）验证了列表、缺参、死 tokenizer 拒绝、覆盖、续跑、同名拒绝、profile 校验与完整参数串。评测沿用 `eval_iters.sh <RUN_NAME> 100 200 300 400 500`（`eval_run.sh` 已传 `load_pretrained_map_modules False`）。

## GRPO 接 R7 17k 前的代码核对（按 git 上的 exp/refiner 逐行）

远端 exp/refiner 为 `cf9f5c3`（0022），训练代码与 `084aeb3` 相同；0021–0023 只增改脚本。逐项核对结果：

- 分发：`run.py` 对 `--run-type grpo` 调 `trainer.train()`，ckpt/tensorboard/日志都进 `data/logs/checkpoints/<exp_name>/`；`--dry-run` 只写 `config.yaml`。
- 构造：`GRPO_trainer_ETP_PriorGT._initialize_policy` 先 `from_config`（`dropout_rate=GRPO.dropout_rate`），再加载 waypoint predictor（`data/wp_pred/check_cwp_bestdist_hfov90`，冻结），选 profile 并冻结其余参数（`setup_training_parts` 有重叠/不匹配/空集三重校验），再 DDP 包 `policy.net`，再建 AdamW（单一 `GRPO.lr`，两组只差 weight decay）与 LambdaLR（线性预热 + 余弦到 `min_lr_ratio`），**最后**才加载 ckpt。
- 加载：`GRPO.is_requeue False` 时取 `GRPO.ckpt_to_load`；R7 由 4 进程训练，键为 `net.module.*`，GRPO 4 进程时走直接 `load_state_dict(strict=False)` 分支，随后 `_validate_checkpoint_compatibility` 在 `require_complete_checkpoint True` 下对任何 missing/unexpected 键抛错；优化器不从 ckpt 恢复（打印 "optimizer is initialized"）。
- 参考策略：`grpo_beta 0.04 ≥ 1e-6` → 构造第二个策略，从已加载的 `self.policy.state_dict()` 去掉 `net.module.` 前缀后 strict 复制，eval 且 requires_grad=False；锚点即 R7 17k。
- map 通路：`policy.py` 在 `load_pretrained_map_modules False` 时只构造 `EmbeddingGridMapEncoder`（构造函数显式调用 `reinit_spatial_tokenizer`，0017），不读 460000 的 map 张量，也不触发死 tokenizer 检查；`vlnbert_init.py` 仍 `torch.load(pretrained_path)` 取骨干权重，fusion 重映射仅在 load 标志为 True 时进行，否则打印 "fusion starts from random"。两者随后都被 R7 ckpt 完整覆盖（`require_complete_checkpoint` 保证）。
- 地图输入：GRPO 的 `_prepare_map_inputs` 与 SS 训练器逐字段一致（grid、trajectory metadata、start direction、start position），只少了消融/缩放分支（默认 none/1.0）；LLM 子类的缓存 id 与 SS 的 `_cognitive_map_cache_id` 同为 `{DATASET}_{split}_{episode_id}`，均 `random_rotation_augmentation=False`（SS 训练时两处调用也是 False）。R7 训练时看到的地图与 GRPO 期间一致。
- 损失：PPO 式裁剪比（存储采样概率作 old prob，`update_epochs 1`），k3 KL 对参考策略乘 `grpo_beta`，G 个样本梯度累积后 `clip_grad_norm_(max_grad_norm)`，非有限梯度抛错，冻结的 map_encoder 若有梯度抛错，每 iter `scheduler.step()` 一次。
- 可训练模块名 `global_encoder / graph_query_text / graph_attentioned_txt_embeds_transform / global_sap_head / graph_map_attention` 均在 `vilmodel_cmt.py` 854–866 行定义；`map_encoder` 挂在策略网络顶层（键 `net.module.map_encoder.*`），启动器预检按后缀匹配，两种挂法都能找到。
- 数据：`SPLIT train` + `SUFFIX _10` → `train/train_10.json.gz`，与历史 GRPO 相同；`enable_all_dropouts True` 时采样与更新阶段整个 vln_bert 处于 train 模式（66.50 配方）。

结论：启动器传参与训练器实际读取的键一一对应，R7 17k 接 GRPO 的加载路径、冻结集合、学习率与历史 66.50 配方一致，无遗漏。

## R11′ 低于 R7 的细致分析

逐 iter 对齐：7k 63.02/63.08，13k 65.31/65.09，15k 65.20/64.82，17k 66.72/64.60，20k(18k) 65.25/63.68（R7/R11′）。三个点重合在 0.4 以内，"低 1.6"几乎全来自 R7 的 17k 尖峰（前后点 65.20、65.25）；平台期均值 R7 65.62（去尖峰 65.25）对 R11′ 64.71，系统性差距 0.5–0.9，低于单 seed 分辨率（R7 相邻点波动 1.5），且两边都在 val_unseen 上挑最优点。起点一致：iter 200 student_ce 3.121（R7）/ 3.025（R11′）。

机制：460000 的地图 transformer 与 fusion 是在"100 个常数空间 token + 元数据"上预训练的，R7 原样继承，故栅格盲而元数据 +1.47；R11′ 把空间 token 换成随机投影的 LLM 栅格，对预训练 fusion 是分布外输入，元数据通路先被扰动再恢复；学 W′ 的唯一信号是对使用 GT 栅格的教师做 KL，而 LLM 栅格与 GT 的 100×100 物体 mIoU 仅约 4%，上限由 R5 量出（+2.6，且训完仍用不上 GT 栅格）；lr 1e-5、20k iter 的预算也不足。R11′ ≈ R7 − 元数据扰动 + 接近 0 的栅格增益 ≈ R7 ± 1。待做测量：两条 train.log 的 distill_loss 对齐（R11′ 8k 0.290、11k 0.235）、R11′ 13k 的 metadata_only / raster_only 消融、配对 CI。结论：DAgger 阶段训不出栅格通路且会打扰元数据路径；R7 的 66.72 是尖峰点；栅格只能在预训练阶段训好（R16）。
