## 问题

使用 R2R 与部分英文 RxR 数据微调的 LLM-Grid 在 epoch 10 的部分训练样本上接近完全匹配，但在 R2R `val_unseen` 上明显较差。需要区分：

1. 仅根据指令和起始元数据预测精确布局是否本来就不可解；
2. 当前模型、目标定义或训练过程是否存在问题；
3. 是否继续正在运行的 `llm-grid-try5-pt`。

## 为什么 `val_unseen` 困难

实际输入只有：

- 四舍五入后的 level-local 起点坐标；
- 起始方向；
- 导航指令。

输入不包含 scene ID、全景观测、场景几何或语义地图，但目标要求预测 unseen house 中大量精确网格，包括指令未提及的实体及五个轨迹方向向量。指令可以支持类别、路线拓扑和粗略相对位置推测，却通常无法决定真实 MP3D 场景中的精确 cell。

R2R train 使用 61 个 scene；`val_seen` 的 53 个 scene 均在 train 中出现；`val_unseen` 的 11 个 scene 与 train 完全不重合。train → `val_seen` → `val_unseen` 的性能梯度与场景/指令记忆一致。

因此当前证据同时支持两个判断：

1. 当前精确 full-grid target 对 unseen scene 部分不可辨识，多种合理布局都可能与唯一 GT 不一致；
2. 当前模型也存在明显过拟合，不能把全部差距都归因于任务不可解。

## 评价协议核查与提示词混淆因素

### GT namespace 名称不同，但有效 target 一致

`prior.analyze.batch_vis` 默认使用 `gt.legacy.r1p5.direction5.blurred.v1`，而 LLM-Grid 训练和 predictor evaluation 从 `gt.legacy.r1p5.direction5.v1` 读取数据。两者的 namespace 名称虽然不同，但这不是本次比较的混淆因素：训练数据集会用 `GRID_SCALE=2` 对 non-blurred 100×100 grid 做 2×2 max pooling；blurred cache 则预先执行相同的 max pooling，再 nearest-neighbor upsample 回 100×100。因而再次按 scale 2 下采样 blurred cache 所得的 50×50 target，与直接下采样 non-blurred cache 相同。

在本次 epoch 10 `val_unseen` 样本上，两个 100×100 cache 的原始平均 IoU 仅约 0.662；该数值反映的是 non-blurred cache 中被 scale-2 target 主动丢弃的细粒度差异，不能用来证明训练与可视化 GT 不一致。后续仍应记录 namespace、scale 和最终 target shape，避免只根据 namespace 名称判断评价协议；本次人工可视化不能替代固定样本上的定量评价，但其 GT 表示与训练 target 是等价的。

### 坐标与方向语义不一致

当前 system prompt 声明：

- grid columns 对应 x，rows 对应 z；
- direction vectors 为 `[dx,dz]`。

实际项目约定为：

- grid rows 随 world x 增加，columns 随 world z 增加；
- direction vectors 使用项目的 `(sin, cos) = (-dz, -dx)` 可视化约定。

训练 target 与 parser 在数组层面保持一致，因此这不是简单的评价错位；模型可以通过监督记住输出约定。但错误的自然语言定义可能妨碍从 pretrained model 迁移和 unseen 泛化，下一次正式训练前应先修正并验证。

## 当前结论

不能简单归因于“任务不可解”或“模型太差”。较准确的表述是：当前 target 包含大量无法从输入唯一恢复的 unseen-scene 精确几何，同时 epoch 10 明显强化了训练集记忆而没有改善 unseen 空间泛化。GT namespace 名称差异不是混淆因素；下一步应修正 prompt contract、固定采样与评价协议，再用 target ablation 和下游导航反事实确认哪些可预测信息真正有用。
