## Checkpoint pruner 的 GRPO metric contract

Login node 的 `release_r2r_llm_grid_try5_grpo` 训练输出确认 checkpoint 与
TensorBoard scalar 使用同一步数：例如 `ckpt.iter10.pth`、`ckpt.iter20.pth`
分别对应 event step 10、20。GRPO event 同时记录 `grpo/spl_reward`、
`grpo/success_reward`、`grpo/NE`、训练 shaping reward 与各项 loss。

独立清理工具改为只接受一个完整 tfevents 路径，并从其 parent 推导待清理的
checkpoint 目录，避免 base path 与 event filename 组合不一致。调用者必须显式
指定 stage：

- `--stage dagger` 默认最小化 `loss/IL_loss`；
- `--stage grpo` 默认最大化 `grpo/spl_reward`；
- 自定义 `--metric` 时必须同时给出 `--mode min|max`。例如 success 使用
  `--metric grpo/success_reward --mode max`，NE 使用
  `--metric grpo/NE --mode min`。

GRPO 默认选择 SPL，因为它与最终 navigation success/path-efficiency 目标直接
一致；训练用 composite reward 额外加入独立 success 和连续
distance-to-goal shaping，不作为默认 checkpoint 排名依据。`store/` 仍完全
排除在自动扫描之外。回归测试覆盖 DAgger lower-is-better、GRPO SPL
higher-is-better、custom metric 显式方向、partial event、partial archive 与
人工 `store/` 保护。

工具固定读取调用时给出的单个 event 文件，不通过 glob 猜测多个 event 的合并
顺序。若训练 restart 生成新的 tfevents 文件，需要用新路径重启 pruner；旧文件
缺少的新 checkpoint metric 会按既有安全规则保留，而不会被误删。

## LLM-Grid 起点中心四向注册诊断

### 假设与固定协议

检验 LLM-Grid 绝对坐标上的低 Raster IoU 是否主要来自以已知起点为中心的
逐 episode 基数方向误差。仅回放本地 cache，保持 GT、起点和起始朝向不变；在 scale-2
`37x50x50` 栅格（`1 m/cell`）围绕连续起点 pivot，对 37 通道共享地搜索
`0/90/180/270°`。越出 `50x50` 框的 support 保留为 false positive，无效预测以空栅格留在分母。

不确定性使用 11 个 scene 为 cluster、seed `42`、10,000 次重采样的 paired
scene-cluster bootstrap。四个 GT-选择角度仅是 oracle 上界诊断，不是可部署的选择器，也未传入 navigation。
