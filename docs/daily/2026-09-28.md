## R13：历史 try5 训练是否加载了预训练 map encoder（CLI 只读审计，`reports/R13_try5_map_loading_audit.md`）

**结论：否。** 约 65 SR 的 `release_r2r_llm_grid_try5_dagger`（2026-08-19 启动，代码近似 658b8eb）当时：

- `policy.py` 只构造 `EmbeddingGridMapEncoder`，没有对 `self.map_encoder` 的任何 `load_state_dict`；
- `vlnbert_init.py` 只有通用 `from_pretrained(..., state_dict=...)`，没有 `bert.global_encoder.graph_map_attention.*` → 导航模型键名的重映射；导航模型本身没有 `map_encoder` 子模块，通用路径无法触及它；
- `default.py` 没有 `load_pretrained_map_modules`。

这些加载逻辑全部来自 2026-09-24 的 patch 0001（ec5fde0）。CLI 之前"会成功加载"的回答描述的是当前代码，不适用于那次训练。

两点保留：该目录只留了日志、没有 checkpoint，无法用权重范数复核；该日志里也没有 HF 的 "weights not used" 报告（此前引用的 43 个张量的 not-used 列表来自 R5 蒸馏训练的日志，不是这份）。结论完全建立在代码证据上，代码证据本身是充分的。

推论不变：R7 之前所有 DAgger 的 map encoder 与 fusion 都从初始化训练；R7 是第一次真正加载预训练 map 模块，而加载进来的是死 encoder。

## R12：学生通道消融（CLI 执行，`reports/R12_no_new_training_summary.md`）

**修正与判读。**

1. **R5 的 LLM 栅格是有用的**：去掉它 SR 掉 2.6 pp、OSR 掉 4.3 pp，作用集中在到达率。此前基于"gt_full ≈ p0"和探针小翻转率得出的"LLM 栅格无可测增益"是错的：GT 栅格替换 LLM 栅格不再提升，不等于 LLM 栅格没有贡献。R5 的 encoder 只见过 LLM 栅格，可能只学会读两者共有的粗粒度信息（房间范围、大致布局），GT 的细节它读不出来。
2. **R7 的增益结构与 R5 互补**：R7 完全不用栅格（死 encoder），但从 metadata token（起点方向与位置，非方向向量）拿到 +1.5 pp；R5 用栅格拿 +2.6 pp，metadata 为 0。两条通道在两个模型里各活一条。
3. **对 R7 的重新评价**：R7 比 R5 高 1–1.6 pp 是在"少了一条值 2.6 pp 的通道"的情况下达到的，460000 骨干本身的贡献比配对分析显示的还要大。
4. 教师那边 GT 栅格值约 17 pp，学生的 LLM 栅格值 2.6 pp；差距既有地图质量（IoU 0.13）也有读图器只在 LLM 栅格上训练的因素。

**推论**：把活的栅格通道（R5 式从初始化训 encoder）与 460000 骨干组合，即 R11 的设计，现在有了正面预期（两项增益若可加约 +2 pp）。是否重启由用户决定；本日志只记录证据。
