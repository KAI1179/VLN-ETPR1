**结论：否。** 约 65 SR 的 `release_r2r_llm_grid_try5_dagger`（2026-08-19 启动，代码近似 658b8eb）当时：

这些加载逻辑全部来自 2026-09-24 的 patch 0001（ec5fde0）。CLI 之前"会成功加载"的回答描述的是当前代码，不适用于那次训练。

**修正与判读。**

1. **R5 的 LLM 栅格是有用的**：去掉它 SR 掉 2.6 pp、OSR 掉 4.3 pp，作用集中在到达率。此前基于"gt_full ≈ p0"和探针小翻转率得出的"LLM 栅格无可测增益"是错的：GT 栅格替换 LLM 栅格不再提升，不等于 LLM 栅格没有贡献。R5 的 encoder 只见过 LLM 栅格，可能只学会读两者共有的粗粒度信息（房间范围、大致布局），GT 的细节它读不出来。
2. **R7 的增益结构与 R5 互补**：R7 完全不用栅格（死 encoder），但从 metadata token（起点方向与位置，非方向向量）拿到 +1.5 pp；R5 用栅格拿 +2.6 pp，metadata 为 0。两条通道在两个模型里各活一条。
3. **对 R7 的重新评价**：R7 比 R5 高 1–1.6 pp 是在"少了一条值 2.6 pp 的通道"的情况下达到的，460000 骨干本身的贡献比配对分析显示的还要大。

**推论**：把活的栅格通道（R5 式从初始化训 encoder）与 460000 骨干组合，即 R11 的设计，现在有了正面预期（两项增益若可加约 +2 pp）。是否重启由用户决定；本日志只记录证据。

## R12 其余部分（R10 扫描、预训练侧事实、学生 vs 教师）

**R10 扫描**：460000 及 R7 所有采样 checkpoint 的 `spatial_tokenizer.weight` 精确为 0，R5 的始终非零。预训练目录里没有中间 checkpoint，"何时归零"在本机无法回答。

**预训练侧事实**（只读代码）：`optim/misc.py` 把 `spatial_tokenizer.weight` 放在 weight_decay 组、`.bias` 放在 0 衰减组；`train_r2r.py` 没有冻结 map 参数；仓库里唯一带优化器参数的配置是 `run_pt/mix_pretrain_server.json`（AdamW，lr 5e-5，wd 0.01，grad_norm 5，500k 步，warmup 20k），但不能确认 460000 那次实际用的就是它。训练集缓存统计（各 200 个）：LLM 栅格活跃格 2.1%、GT 1.7%，全零地图 3%，float32 取值 0–1。**"预训练输入全零所以权重不收梯度"的假设被否定。** 权重精确为 0 无法由 AdamW 的乘性衰减产生（460k 步只衰到 0.79 倍），偏置的爆炸也与 AdamW 每步至多 lr 的步长不符。机制仍未解。下一个便宜的线索是预训练目录里若保存了优化器状态，`spatial_tokenizer.weight` 的 Adam 二阶矩能直接说明它是否收到过梯度。

## R15 收口：预训练 spatial_tokenizer 死亡的根因已定位并复现

CLI 的 R15 报告本身没能定位（登录节点 DNS 不通、本机无优化器状态、GPU 探针未跑），但它补上了一个数据点：try5 线的 `dagger.iter28000.pth` 的 `spatial_tokenizer.weight` 范数 19.1、偏置 0.083，即从初始化训出，R13"未加载"的结论有了权重证据。

**根因**：`train_r2r.py` 用 `GlocalTextPathCMTPreTraining.from_pretrained(None, config=..., state_dict=checkpoint)` 建模型。transformers ≥ 4.31（仓库锁定 4.43.4）的 `from_pretrained` 在构造模型期间用 `no_init_weights()` 把 `torch.nn.init.*` 全部替换成空操作，之后只对 BERT `_init_weights` 认识的模块（Linear、Embedding、LayerNorm）重新初始化。`nn.Conv2d` 不在其列，所以起始 state_dict 里没有的 `spatial_tokenizer` 保持 `torch.empty` 的原始内存：157 MB 的权重是新分配页，全为精确 0；3 KB 的偏置是分配器复用的垃圾值，一次 55、一次 1e19。同一 encoder 里 `category_projection` 因为 `__init__` 里用 `copy_` 显式写入 CLIP 嵌入而幸免，`metadata_encoder` 的 Linear 拿到 BERT 的 N(0, 0.02)（范数 2.07，与 387500/460000 的实测一致；DAgger 里同一层是 kaiming 的 16，因为 policy 在 HF 之外构造 encoder）。fusion 的 `MultiheadAttention` 也幸免，因为 PyTorch 在模块加载时就把 `xavier_uniform_` 绑定成了本地名字，不受运行时替换影响，这解释了 387500 里 in_proj_weight 的 xavier 范数 33.9。

**复现**（`scripts/distill/repro_hf_no_init_conv.py`，transformers 4.43.4 + torch，CPU，10 秒）：同一个含 Conv2d/Linear/MHA 的 `PreTrainedModel`，直接构造时 conv 权重范数 16.0、偏置 0.07；经 `from_pretrained(None, config, state_dict={})` 构造时 conv 权重全零（零比例 1.000），偏置一次全零、一次范数 3.9e20（最大 3.7e19），Linear 为 2.06，MHA 为 33.9。与两个预训练 checkpoint 的形态逐项吻合。

**为何训练中没有恢复**：460000 里偏置 ~1e19 使 LayerNorm 的 1/std 把回传到权重的梯度压到 Adam eps 以下，权重停在 0；387500 的 map 路径在那次预训练里根本没有梯度（所有偏置精确为 0、category_projection 与 CLIP 完全一致），权重同样停在 0。两条线一个起因、两种停留方式。

**修复（patch 0017，未应用到生产）**：`EmbeddingGridMapEncoder` 用张量方法 `uniform_` 显式初始化 spatial_tokenizer（不受 `no_init_weights` 影响）；新增 `assert_initialised()`，`train_r2r.py` 在 `from_pretrained` 之后对全模型的卷积参数做全零/非有限检查，不通过就拒绝训练；回归测试在 `no_init_weights()` 上下文里构造 encoder 并断言。同样的缺陷会影响任何在 HF 模型内构造、且不在起始 checkpoint 里的卷积（imagined 线的 `map_decoder`/`map_predictor` 若含卷积同样中招），guard 覆盖了它们。

**对研究结论的影响**：两条"带认知地图的预训练"从未训练过栅格路径。所有以 460000/387500 为起点、依赖预训练 map encoder 的结论都要重新看；此前"预训练 map 路径无效"实际是"预训练 map 路径从未存在"。

## 更正：根因结论降级为"版本相关的候选机制"

用户在 `etpr1-py38` 上运行 `repro_hf_no_init_conv.py`，环境是 **transformers 4.28.1 + torch 1.13.1**，不是 pyproject 锁定的 4.43.4。4.28.1 的 `no_init_weights()` 只跳过 `init_weights()`，不替换 `torch.nn.init`，所以 `from_pretrained(None, config, state_dict={})` 之后 Conv2d 仍是 kaiming（权重范数 16.0、偏置 0.07），**上面的机制在本机环境不复现**。

因此：上一节"根因已定位并复现"过早。准确表述是：该机制在 transformers ≥ 4.31 成立并已复现；是否是 387500/460000 的成因，取决于两次预训练实际运行环境（登录节点）的 transformers 版本。本机 WZ 服务器解析不到登录节点，需要用户从开发容器查：找到预训练的 sbatch 脚本所用 conda 环境，在其中打印 `transformers.__version__`。≥ 4.31 则机制成立；4.28.1 则被否定，回到未知。

顺带：patch 0017 的 guard 把 LayerNorm/MultiheadAttention 合法的零偏置也判成未初始化，回归测试因此失败。patch 0018 改为只检查二维以上张量的全零与所有参数的非有限。

## 根因确认：登录节点预训练环境 `etpr1-uv` = transformers 4.43.4 + torch 2.1.2

用户在 ln01 上核实：预训练用的 conda 环境 `etpr1-uv` 安装的是 transformers **4.43.4**（与 pyproject 锁定一致），不是本机 WZ 的 4.28.1。4.43.4 正是本节上文在沙箱里复现的版本：`from_pretrained()` 构造期间 `no_init_weights()` 把 `torch.nn.init.*` 全部替换为空操作，事后只对 Linear/Embedding/LayerNorm 重初始化，`nn.Conv2d` 被跳过。起始 checkpoint（ETP-R1 原版权重）里没有 map 模块，于是 `spatial_tokenizer` 保持 `torch.empty` 原始内存：权重全零、偏置垃圾值。两条预训练线（387500、460000）同一环境、同一代码路径、同一死法。

**根因定案。** "版本相关的候选机制"升级为已确认：环境版本、沙箱复现、checkpoint 形态三者闭合。

**波及范围**：同一预训练模型里所有"不是 Linear/Embedding/LayerNorm、且不在起始 checkpoint 里"的参数都受同样影响。`nn.MultiheadAttention` 幸免（PyTorch 在模块导入时绑定了 `xavier_uniform_` 本地名，复现里 in_proj 保持 xavier）；卷积层与裸 `nn.Parameter` 不幸免。imagined 线的 `map_decoder`/`map_predictor` 若含卷积或裸参数，其预训练权重同样可疑，重用前需用 `map_encoder_weight_sweep.py` 同样的方式核查。

**修复状态**：patch 0017（显式张量级初始化 + 构造后卷积全零/非有限检查）+ 0018（guard 只查二维以上张量）已在 exp/refiner，登录节点的 `ETP-R1-refiner` worktree 已含。任何新预训练必须从该 worktree 起。待办可选项：0020，训练中每 1000 步记录 tokenizer 权重/偏置范数，并把启动 guard 扩展到所有二维以上参数。
