### Typed mask seam 修正

adapter audit 发现原 runner 虽然保留了 per-instance device masks，却把
same-category union 放到了 D2H 后执行。这既让 D2H bytes 随 detection count
变化，也把冻结的 device postprocess 工作错误地移到 host。typed seam 已改为
只接受 contiguous device tensors：

- category unions：`bool[12,23,256,256]`；
- retained instance counts：`int64[12,23]`；
- 两者必须在同一 inference device，且 `(count > 0)` 与 union nonempty
  逐项完全一致，每个 view 的 count 总和不得超过 300。

因此 official postprocessor 后的 same-category union 必须在 GPU 内完成；D2H
固定复制 masks 与 counts，host 只进行 frozen dtype/schema construction。
empty、nonempty copy、count/mask mismatch、float mask 与 exact two-pass schedule
测试均通过。

candidate interpreter 要 import runner 还需要 benchmark contract 的轻量依赖
`jsonlines==3.0.0` 与 `typed-argument-parser==1.10.1`，均已 exact pin。继续 import
时暴露出 dense contract 顶层导入 Habitat trainer stack，而 mask candidate 只需要
camera geometry；同时 candidate 的 OpenCV 5 与旧 Habitat visualization API
不兼容。dense-only Habitat projector 改为函数内 optional import，mask projection
则使用独立的 pure NumPy frozen geometry。新增 parity test 覆盖非对称尺寸、
旋转 pose、非默认 HFOV 与 saturated depth，其 world points/pixel order/saturation
与原 Habitat authority byte-for-byte 相同。candidate `.venv` 现可直接 import
typed mask runner，不再安装 Habitat/gym 或增加 compatibility shim。

### YOLOE typed adapter 与 nonempty gate

adapter 直接实现 frozen six-stage seam，不调用聚合式 `model.predict`：

1. host preprocess 用 pinned `LetterBox(auto=False)` 把 RGB
   `uint8[12,256,256,3]` 转为 contiguous FP16
   `[12,3,640,640] / 255`；
2. runner 单独执行 H2D；
3. `SegmentationPredictor.inference` 消费完整 12-view FP16 batch；
4. pinned `SegmentationPredictor.postprocess` 执行 confidence filter、
   class-aware NMS、native mask restore；
5. adapter 在 GPU 验证 class/mask schema，并按 frozen 23 prompts 做
   same-category union；
6. runner 执行固定形状 D2H 与 projection。

RGB 不能直接交给 upstream NumPy API，因为该 API 声明输入为 BGR 并无条件翻转
channel。新增 channel-coded parity gate：adapter 的 RGB path 与“同一 RGB 先转
BGR，再交给 pinned upstream preprocess”逐元素完全相等，避免全零 smoke 隐藏
R/B swap。

nonempty synthetic raw prediction 经 official postprocessor 验证了两个同类、
一个重叠异类 detection：class-aware NMS 保留 3 个实例，同类 count 为 2 并在
device union，异类 overlap 仍保留。此处也修正了 zero-result smoke 无法暴露的
upstream schema 事实：pinned `process_mask_native()` 的 in-place `gt_` 把
binary 0/1 写回 FP32 buffer，所以 `Results.masks.data` 是 finite binary
FP32，而非 `torch.bool`。adapter 严格接受 exact FP32 `{0,1}` 后在 device
转 bool；final typed seam 仍只接受 bool unions。

另外，upstream `stream_inference` 原本在 `smart_inference_mode` 内 construct
并 fuse predictor。split adapter 若在普通 context 中 fuse，会产生 normal 与
inference-only tensor 混合，首个 YOLOE head conv 抛出
`Inference tensors do not track version counter`。cold setup 现与 upstream
lifecycle 一致，在 `torch.inference_mode()` 内完成；timed infer 仍由 runner
单独包围。最终 adapter smoke 同时通过：

- RGB parity；
- synthetic official nonempty/class-aware mask schema；
- real model infer + official postprocess（本次 synthetic color ramp 合法返回
  0 retained instances）；
- Ruff、ty（以 candidate `.venv` 解析）、`uv lock --check`。

### P8.5：YOLOE sealed visualization

在 commit `08631d0c64ebbc20c3082aa44f22771db7a9107c` 新增独立 mask-aware
visualizer；它只 strict-load accepted YOLOE package 与 sealed raw package，重新
验证 50 个 stored projected grids 与纯 projector 输出 byte-exact，不 load model、
不运行 inference，也不重新选择样本。selection 完全沿用 ESANet P7.3：lexical
scene ranks `0,2,5,8,10`，对应 ordinals `0,9,28,41,45`；每个 observation
保留 12-view contact、固定 views `0,3,6,9` 的 detail sheet，以及
GT/prediction/TP/FP/FN grid，共 15 张 PNG。

YOLOE 是 multi-label masks，不能复用 ESANet 的 single-label argmax disagreement。
detail sheet 因此使用六列：RGB、固定 `[0,10] m` depth、GT canonical overlay、
YOLOE multi-label mask overlay、active predicted-category count、category-wise
primary disagreement。多类别重叠不做 argmax：overlay 使用 active canonical colors
平均；disagreement 中 TP/FN/FP 为绿/蓝/红，`FN+FP` substitution 为紫，正确类别
同时带额外 FP 的 `TP+FP` 为黄。pixel count 色域固定 `[0,3]`，grid count 为与 P7
相同的 `[0,23]`，全部写入 render contract。

五组 detail/grid 人工复核结论：

- observation 09 中 YOLOE 在 view 3 明确分割出大床，证明它不像 ESANet 那样几乎
  完全无法识别 bed；view 6 的局部床仍漏检。ceiling 没有 YOLOE mask，且它属于
  primary endpoint 排除的 region/environmental channel，因此不是 clothes confusion，
  也没有因未预测 ceiling 直接拉低 primary IoU；
- observation 28 的 sofa 与 television mask 边界较完整，显示模型在大而清晰的
  常见物体上可以工作；门/局部 furniture 仍出现漏检与类别替代；
- observation 41 的四个 detail views 全部没有 retained mask，而 GT support 很大，
  disagreement 几乎全蓝，是 conservative/recall-limited failure 的最直观例子；
- observation 45 的 bed、door、picture/cabinet 有明显 TP，但 cabinet 内部与边缘有
  FP/FN；这与 pooled precision 约 `0.50`、recall 仅 `0.1415` 一致；
- observation 00 输出很稀疏，并出现把室内 bench-like surface 归到 bathtub 等
  category-boundary failure，支持 prompt/taxonomy mismatch，而不是 projector 或
  region-score mismatch。

因此定性图与 quantitative artifact 相互一致：YOLOE 并非完全不会分割 bed/sofa/
television 等对象，但跨场景输出极不均匀，主要失败是大量漏检，另有开放词表类别
边界导致的替代与 FP。visualization 不改变 P8 NO-GO，也不提供在 sealed cohort 上
调整 prompt/confidence/mapping 的许可。
