## YOLOE-t0 × Oracle predictor 推测性并行 cache 预注册

### 目的与解释边界

为避免本地 8×RTX 3090 空闲期间等待远端 Oracle cache，本轮按用户决定并行准备
YOLOE `pretrain/mixed` evidence 与 navigation cache。该运行明确标记为
**YOLOE evidence × Oracle-conditioned predictor 的 distribution-shift、cache-only
ablation**，不是已通过 P8 quality gate 的 deployable candidate，也不是
YOLOE-conditioned predictor。P8 的正式结论仍为 NO-GO；本轮结果不能单独推翻该
结论，也不能归因区分 perception noise 与 predictor distribution shift。

### 本地执行链与失败语义

新增本地 launcher：
`scripts/local/llm-grid-yoloe-t0-pretrain-cache.sh`。链路固定为：

1. `etpr1-uv` 中启动 8 个 deterministic shards，分别限制到一个 GPU UUID，渲染
   t=0 RGB/depth/pose raw artifacts；YOLOE inference 不得读取 oracle semantic、
   instruction、goal 或 trajectory；
2. 前一阶段全成功后，在 pinned YOLOE `.venv` 中启动 8 个 single-UUID workers，
   使用冻结的 text prompts/mask protocol 生成并投影 YOLOE object evidence；
3. 所有 inference shards 成功后，由 `etpr1-uv` finalizer 验证 exact population、
   shard commitments 与 artifacts，再原子发布 evidence index/manifest；
4. 只有 finalizer 成功，才使用上述 Oracle-conditioned predictor 启动 batch-4
   LLM navigation cache generation。

render 与 inference artifacts 均按确定性 shard 可恢复：重跑时必须 hash/schema
验证已有文件后跳过，不能静默覆盖不一致 artifact。Launcher 使用单实例 file lock、
逐阶段独立时间戳日志和 `wait -n`；任一 child 非零退出会立即终止同阶段其余 children，
且不会进入下一阶段。YOLOE frozen environment 不含 Habitat，因此 render 与 inference
必须保持进程/环境隔离，禁止把主环境 site-packages 注入 YOLOE `.venv`。

## 改为 YOLOE-conditioned predictor 全匹配链路

用户确认主实验不再采用 YOLOE evidence × Oracle-conditioned predictor 的
distribution-shift cache，而改为完整匹配链路：YOLOE t=0 evidence → 从同一 base model
独立训练的 YOLOE-conditioned predictor → `pretrain/mixed` navigation cache → navigation
pretraining。Oracle-conditioned adapter 不作为新 predictor 的初始化，以免把 Oracle
conditioning 混入主实验；原 speculative cache 只保留为可选诊断，不占用当前关键路径。

现有 predictor trainer 固定读取 `R2R/train` 与 English `RxR/train` evidence index，不能
直接读取 `pretrain/mixed` index。Oracle predictor 的 production run 保留 30,511 个
examples、训练约 8 小时 46 分。检查还发现，当前 13,964 个 pretraining observations 与
原始 VLN-CE train observations 的 exact observation IDs 没有交集，因此不能未经明确
pose-equivalence 验证就把 artifacts 静默重索引。下一步应为两个 train namespaces 生成
冻结 YOLOE evidence，然后按 Oracle run 的相同 corpus、target namespace、seed、LoRA 与
两轮训练设置，从同一 base model 训练 fresh adapter。

为避免 launcher 自动进入预计 35–50 小时的错误 cache，`2026-08-06 04:02 UTC` 向旧
supervisor PID `932818` 发送 TERM；其 trap 正常结束 8 个 workers，保留并可严格恢复
4,221/13,964 个 raw observations。随后移除 launcher 的 Oracle predictor/cache stage，
保留 render → frozen YOLOE inference → strict finalization，并以 detached screen session
`yoloe-pretrain-evidence` 于 `2026-08-06 04:03:10 UTC` 恢复执行。screen 主日志为

因此 count 暂时不增长；`/proc/<pid>/io` 显示所有 workers 持续读取，并非停滞。
