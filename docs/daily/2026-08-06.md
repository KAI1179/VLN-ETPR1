## YOLOE-t0 × Oracle predictor 推测性并行 cache 预注册

### 目的与解释边界

YOLOE `pretrain/mixed` evidence 与 navigation cache。该运行明确标记为
**YOLOE evidence × Oracle-conditioned predictor 的 distribution-shift、cache-only
ablation**，不是已通过 P8 quality gate 的 deployable candidate，也不是
YOLOE-conditioned predictor。P8 的正式结论仍为 NO-GO；本轮结果不能单独推翻该
结论，也不能归因区分 perception noise 与 predictor distribution shift。

### 本地执行链与失败语义

新增本地 launcher：
`scripts/local/llm-grid-yoloe-t0-pretrain-cache.sh`。链路固定为：

1. `etpr1-uv` 中启动 8 个 deterministic shards，分别限制到一个 GPU UUID，渲染
   t=0 RGB/depth/pose raw artifacts；YOLOE inference 不得读取 oracle semantic、
   instruction、goal 或 trajectory；
2. 前一阶段全成功后，在 pinned YOLOE `.venv` 中启动 8 个 single-UUID workers，
   使用冻结的 text prompts/mask protocol 生成并投影 YOLOE object evidence；
3. 所有 inference shards 成功后，由 `etpr1-uv` finalizer 验证 exact population、
   shard commitments 与 artifacts，再原子发布 evidence index/manifest；
4. 只有 finalizer 成功，才使用上述 Oracle-conditioned predictor 启动 batch-4
   LLM navigation cache generation。

render 与 inference artifacts 均按确定性 shard 可恢复：重跑时必须 hash/schema
验证已有文件后跳过，不能静默覆盖不一致 artifact。Launcher 使用单实例 file lock、
逐阶段独立时间戳日志和 `wait -n`；任一 child 非零退出会立即终止同阶段其余 children，
且不会进入下一阶段。YOLOE frozen environment 不含 Habitat，因此 render 与 inference
必须保持进程/环境隔离，禁止把主环境 site-packages 注入 YOLOE `.venv`。

## 改为 YOLOE-conditioned predictor 全匹配链路

用户确认主实验不再采用 YOLOE evidence × Oracle-conditioned predictor 的
distribution-shift cache，而改为完整匹配链路：YOLOE t=0 evidence → 从同一 base model
独立训练的 YOLOE-conditioned predictor → `pretrain/mixed` navigation cache → navigation
pretraining。Oracle-conditioned adapter 不作为新 predictor 的初始化，以免把 Oracle
conditioning 混入主实验；原 speculative cache 只保留为可选诊断，不占用当前关键路径。

现有 predictor trainer 固定读取 `R2R/train` 与 English `RxR/train` evidence index，不能
直接读取 `pretrain/mixed` index。Oracle predictor 的 production run 保留 30,511 个
examples、训练约 8 小时 46 分。检查还发现，当前 13,964 个 pretraining observations 与
原始 VLN-CE train observations 的 exact observation IDs 没有交集，因此不能未经明确
pose-equivalence 验证就把 artifacts 静默重索引。下一步应为两个 train namespaces 生成
冻结 YOLOE evidence，然后按 Oracle run 的相同 corpus、target namespace、seed、LoRA 与
两轮训练设置，从同一 base model 训练 fresh adapter。

为避免 launcher 自动进入预计 35–50 小时的错误 cache，`2026-08-06 04:02 UTC` 向旧

### 全匹配 continuation queue

为使本地长链在无人值守时按依赖顺序继续，新增 fail-fast continuation launcher：
`scripts/local/llm-grid-yoloe-matched-chain.sh`。它等待上述 `pretrain/mixed`
evidence manifest 原子发布；若 screen 提前退出且 manifest 不存在则立即失败，不会无限
等待。后续固定顺序为：

1. 生成 `yoloe-t0-train-v1` 的 English `R2R/train` 与 `RxR/train` evidence；
2. 从相同 base model 独立训练两轮 YOLOE-conditioned LoRA，输出
   `outputs/llm_grid/r2r-rxr-yoloe-t0-v1-s2-e2-seed42`；
3. 用该 adapter 与 `yoloe-t0-pretrain-mixed-v1` evidence 生成 matched navigation cache
   `llm-grid-yoloe-t0-v1-yoloepred-e2-pseed42-matched-r1p5-d5-s2-pretrain-v1`；
4. 与 ordinary cache 冻结 navigation-ready common intersection，并固定 artifact SHA-256；
5. 用 4 GPUs、相同 baseline checkpoint 启动 Try5 + LLM-Grid navigation pretraining。

## 暂停 YOLOE 下游链并扩大 MP3D segmenter 搜索空间

### 搜索偏差与当前决策

此前候选发现主要从通用 RGB-D / open-vocabulary segmenter 出发，再检查其能否用于
Matterport3D；只针对 ESANet 单独检索过 Matterport3D 证据，没有系统地从“已在 MP3D
训练或测试的 segmenter”反向搜索。这构成真实的 search-space bias。结合 YOLOE P8
已预注册为 NO-GO，本轮决定先暂停 matched LoRA、navigation cache 与 navigation
pretraining，不再让完整链路自动消耗数日 GPU 时间；但保留 YOLOE artifacts 作为
open-vocabulary baseline，不能因搜索偏差直接断言 MP3D-specific 模型一定更好。

### MP3D-tested 候选

以下数值来自论文/官方仓库，只描述其原任务，尚未验证能迁移到本项目的 t=0 evidence
contract：

1. **SFSS-MMSI** — Guttikonda 与 Rambach，WACV 2024，
   [论文实现与 checkpoint](https://github.com/sguttikon/SFSS-MMSI)。提供
   Matterport3D-trained 1024×512 spherical segmentation 模型；RGB-D checkpoint 的
   validation/test mIoU 为 39.191/35.921。它最适合先做 bounded pilot，因为同时使用
   RGB 与 depth、代码和权重已发布，且仍输出 image-space semantics。主要风险是固定
   MP3D label vocabulary 与本项目 channel 的映射、equirectangular 输入几何，以及旧
   PyTorch 1.13.1/mmseg 0.30.0 依赖。
2. **360BEV / 360Mapper** — Teng 等，WACV 2024，
   [官方实现与权重](https://github.com/InSAI-Lab/360BEV)。其 MP3D RGB panoramic
   segmentation checkpoint 为 46.35 mIoU；直接 RGB-D panorama→BEV 的 MP3D 模型中，
   MiT-B2/MSCA-B 为 44.32/46.31 mIoU。后者与最终 evidence 形状更接近，但同时替换
   segmentation 与几何投影，label space、坐标系、范围及 observed/unknown 语义都需
   重新验证，因此不作为第一轮最小可比 candidate。
3. **Geometric Exploitation for Indoor Panoramic Semantic Segmentation** — Dinh、Kim
   与 Cho，NeurIPS 2024，在 Matterport3D 等数据集上报告结果；但
   [官方仓库](https://github.com/caodinhduc/vertical_relative_distance) 当前只有
   README，并仍写明 code/data/checkpoints 将来更新，暂不可执行。
4. **Open Panoramic Segmentation (OOOPS)** — Zheng 等，ECCV 2024，包含 MP3D
   open-vocabulary panoramic evaluation；类别灵活性值得保留，但当前优先级低于已有
   MP3D RGB-D checkpoint 的 SFSS。
5. **SAI3D / OV3D** 等 MP3D 3D segmentation 方法依赖多视图、点云或更完整的 scene
   context。除非能证明只读取同一 t=0 observation，否则不进入当前 observation-bounded
   candidate set。

论文 mIoU 不能作为本项目 go/no-go。第一轮应在同一批 observation 上比较 YOLOE 与
SFSS 的映射后 category macro F1/IoU、投影后 semantic evidence 指标、coverage 与吞吐，
并以 oracle t=0 evidence 为固定参照；只有 bounded pilot 通过预先固定的门槛，才生成
完整 evidence 并训练 matched predictor。

### 观测表示与分支边界（尚未实现）

不应把现有 12-view 路径静默替换为 equirectangular，也不应维护两套下游 evidence
pipeline。首选边界是保留带 intrinsics/extrinsics 的 12 个 pinhole RGB-D views 作为
canonical raw observation，再由显式 adapter 生成候选模型所需的 equirectangular RGB-D
与 validity mask；segmenter 之后继续输出同一个 semantic evidence contract。派生 panorama
只在性能需要时缓存，并记录 source artifact/projection provenance。

带，不能拉伸或静默填充成“完整 360×180 observation”。第一轮可在现有可见带上验证
projection 与 seam；若 SFSS 明显受 polar coverage 限制，再把 Habitat equirectangular
sensor、cubemap 或增加 pitch views 作为独立 acquisition ablation，并显式记录它扩大了
输入观测范围，避免与“同一输入只换 segmenter”的结果混淆。
