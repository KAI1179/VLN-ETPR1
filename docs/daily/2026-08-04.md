### 目的与边界

为汇报补充可复现的样本级证据，直观检查 `0/90/180/270°` 中由 GT 选择角度后 IoU
提高的几何机制。本工作只新增 `prior/analyze/d2026_08_04/` 下的实验脚本和 focused
tests；未修改 core code、prediction cache、训练或 navigation。角度由 GT raster cells
打分后选择，因此这些图只回答诊断问题，不能代表运行时可部署性能。

### 冻结选样协议

四个 all-channel 样本均要求 schema valid、prediction/target support 为正且最佳角度为
strict winner。非零角度在该角度组内选择最接近 episode `delta IoU` 中位数的样本；
`0°` control 选择最接近 identity IoU 中位数的样本；距离相同时按 scene/example
字典序决定。

两项 cross-family 图要求 true-start、strict selector winner、selector 与 held-out
分数均为正且 held-out `delta IoU > 0`，再选择最接近该 positive-transfer 子集
`delta IoU` 中位数的样本。因此这两项只能说明“同一旋转有时会跨 object/region
迁移”，不能估计总体成功率。运行前记录的 region→object 候选
`EU6Fwq7SyZv/R2R_val_unseen_1490` 不符合上述中位数代表规则；sealed replay 拒绝后，
按冻结规则纠正为 `x8F5xyUWy9e/R2R_val_unseen_1594`，其 `delta IoU=0.095338`，
对应子集的中位数为 `0.095165`。

all-channel 图在共同 padded bounds 中同时显示 GT、原预测、旋转预测、category-aware
error 与四角 IoU；黑框是实际 `50×50` scoring frame，橙色叉是旋转 pivot。每个角度的
prediction support 总数严格守恒，非零角样本的 intersection 分别从 `35/31/15`

相对位置更接近，而不是增删预测 cell。与此同时，180°/270° 样本有 `21/91` 个预测
cell 落到 scoring frame 外；若先裁剪再画图，会隐藏旋转的边界代价，本实现保留并显式
报告这些 cell。

cross-family 两例中，由 objects 选出的 90° 同时使 held-out regions IoU 从 `0.02825`
升到 `0.10976`；由 regions 选出的 180° 同时使 held-out objects IoU 从 `0.06516`
升到 `0.16049`。这比“同一语义 mask 自拟合”更支持共享空间朝向误差，但由于样本从
positive-transfer 子集条件选择，仍不是因果证明，也不能替代总体 cross-fit 统计。

### 验证与结论

- focused tests：`6 passed`；
- Ruff format/check：通过；
- `ty check`：通过；
- 六张 PNG 均完成目视检查；renderer 对输入 SHA、固定 episode identity、分数 replay、
  support conservation、out-of-frame embedding 和 no-overwrite publication 均 fail closed。

结论：样本可视化与总体 oracle/cross-fit 结果一致，能清楚展示“绕真实起点修正相对
朝向”这一机制；但它也同样清楚地表明当前增益依赖 GT angle selection。该证据不改变
P3 target-free 实验的 **NO GO**，也不授权 P4 navigation ablation。
