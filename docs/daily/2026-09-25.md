## 决策

- 放弃基于 387500 的 `z_loader`/`loader` 变体（加载的是未训练权重）。
- R7（460000 初始化，`load_pretrained_map_modules True`）是第一个带预训练地图通路进入 DAgger 的学生；
  与历史 LLM-Grid 2 DAgger（65.42，地图通路从零）对比即可回答"地图预训练是否有用"。
  判据：前 1400 iter `student_ce` 均值明显低于原 run 的 1.09（如 < 0.95）说明地图通路在第 0 步就起作用。
- 待验证假设：随机残差投影在第 0 步注入与图嵌入同量级的扰动，促使策略学会压制地图；可用"`from_pretrained`
  之后再清零"的 flag 做对照。

## 补记：R7 首次启动即 NaN（patch 0009）

**现象**：`CUDA_VISIBLE_DEVICES=0,1,2,3` 启动 R7（学生从 `model_step_460000.pt` 初始化，`load_pretrained_map_modules True`），第一个 iter 的 rollout 里 `torch.distributions.Categorical(nav_probs)` 报 Simplex 约束失败，4 个 env 的 6 个候选概率全为 NaN（cuda:1）。

**诊断**：

- 失败发生在 GradScaler 做任何一次 step 之前（tqdm 仍是 0/200），且所有 env 同时 NaN，说明不是某个 episode 的地图输入坏了，而是权重/精度层面的问题。
- 上一轮 R5 与这次唯一的差别是 map_encoder 和 fusion 的权重：R5 里 map_encoder 停在 CLIP 初始化、fusion 被 HF `_fast_init` 重置成 N(0, 0.02)，激活值都很小；R7 第一次把预训练好的权重真正送进 DAgger。
- 预训练代码（`pretrain_src`）没有 autocast，整条 map 路径在 fp32 训练；DAgger 的 rollout 在 `autocast()`（fp16）下跑。spatial_tokenizer 每个 token 累加 512×10×10 = 51200 个乘积，fp16 上限 65504，溢出成 inf 后经过 LayerNorm 变 NaN，与"全体 NaN"一致。这是最可能的原因，但尚未被直接证实。

**处理（patch 0009，需在 exp/refiner 上 `git am`）**：

1. `EmbeddingGridMapEncoder`、`GraphMapCrossAttention`、`BidirectionalMapTokenFusion` 的 forward 关闭 autocast，用 fp32 计算，与预训练精度一致。
2. 新增 `nan_guard.assert_finite_parameters`：权重加载完立即检查学生和 teacher 全部参数是否有限，不是则报错并点名张量。
3. 新增 `nan_guard.NonFiniteOutputGuard`：给学生 policy 每个子模块挂 forward hook，前 `ETP_NAN_DEBUG_STEPS` 次 forward 内一旦某模块输出 NaN/+inf，直接报错并点名该模块（-inf 允许，mask 会用）。两个蒸馏 launcher 默认 1000 次，之后 hook 自动摘除，`launch_info.txt` 记录该值。

**判定**：若 0009 后 R7 正常起步，则 fp16 溢出假设成立；若再次失败，报错信息会直接给出第一个产生 NaN 的模块名，不再需要猜。

**补记 2（patch 0010）**：0009 的 NonFiniteOutputGuard 在第一次 waypoint forward 就崩了：waypoint 模式的输出 dict 混有 GPU 和 CPU 张量，`torch.stack` 跨设备报错。0010 改为每个浮点张量单独记 flag、按设备分组回读（每个设备每次 root forward 同步一次）。学生参数的有限性检查在那次运行里已通过，即 460000 的权重本身没有 NaN/inf；fp16 溢出假设仍待 0010 之后的启动验证。

**R7 已起跑（0010 之后，4 卡 × 4 env）**：guard 在前 1000 次 forward 内没有捕获任何非有限输出并自动摘除，训练正常推进，说明 fp32 map 路径就是修复点（这是 0009 中唯一改动模型计算的部分），fp16 溢出假设成立。
