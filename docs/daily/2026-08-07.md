### 冻结的渲染语义

- 每个有语义的单元格被完全划分为近似方形的矩形块；类别按 canonical category ID 排序，因此输入枚举顺序不会改变图像。

- 七月普通样例原本已调用共享地图渲染器；Oracle 图中的重复 `_semantic_layers` 现复用同一个马赛克绘制原语，只保留其展示专用图例布局。

## LLM-Grid 相对布局指标

目标是在不从 category-first prediction grid 伪造 instances 的前提下，补充 raster IoU 对整体平移和相对布局
不敏感的问题。主指标使用 level-local map axes；基于 start orientation 的前后左右只作为 secondary view。

### 当前边界

- merged category grids 无法识别 `table#1`；connected components、GT-assisted partition 或 Hungarian matching
  都不能作为 headline instance metric。
- MP3D level-local axes 不是地理方向，不能把 `-x/+x/-z/+z` 命名为 west/east/north/south。
- 真正的 instance graph evaluation 需要 LLM-Boxes 或新的 instance-native prediction contract。

### Corpus 与 contract audit

- fixed train corpus 共 `30,740` 个 boxes artifacts（R2R `10,786`，RxR `19,954`）。object category-example
  中 `67.71%` 含多个 GT instances，region 为 `44.12%`；多实例组的最大中心间距中位数分别为
  `7.80 m` 与 `7.07 m`，P90 为 `16.15 m` 与 `14.44 m`。因此 category centroid 会频繁抵消多峰布局，
  不能作为主指标。
- `gt.legacy.r1p5.direction5.v1` 的 boxes sidecar 与 raster 不是相同几何支持：100 条抽样中
  `boxes.to_cognitive_map().grid` 与 raster 为 `0/100` exact match。原因是 legacy raster 只复制 trajectory
  neighborhood 内的 full-level cells，而 sidecar 保存 relevance-filtered complete boxes。实现因此只比较
  prediction/target rasters；boxes 仅用于证明 instance ambiguity，不能混作 metric target。
- scale-2 evaluator 的 raster cell 为 `1.0 m`，但 offset-distribution similarity 直接比较离散相对位移分布，
  不需要把 axes 命名为地理方位或设置人为 distance dead zone。

### 冻结指标

- 对每个 GT 中同时存在的 category pair，分别计算 prediction 与 target 的 normalized cross-correlation，也就是
  从第一类 occupancy 到第二类 occupancy 的所有相对 offsets 分布。共同平移两个类别不改变分布；多实例、
  多峰与 object-region containment 都保留在分布中。
- 使用 Parseval identity 直接在 Fourier domain 计算两个 offset distributions 的 Sørensen similarity，避免逐 pair
  inverse FFT。missing predicted categories 只降低 pair coverage；conditional similarity 不伪填零。object-object、
  object-region、region-region 与 overall 分开报告；environmental object channels 和 `other` 不进入支持集。
- 200 条现有 mixed epoch-2 `val_unseen` caches 的初步 sanity 为 pair coverage `0.3618`、conditional offset
  similarity `0.2847`、raster IoU `0.1109`；offset similarity 与 IoU Pearson 仅 `0.2626`，说明它提供互补信号，
  但该已暴露 sample 不是 model-selection endpoint。
- 50 条 perfect-target benchmark 的 metric core 用时约 `0.40 s`；预计 full `1,839` episodes 约十几秒，而不是
  reconstruct 每个 pair distribution 的数分钟路径。

### 验证与剩余边界

- synthetic controls 覆盖共同平移、多峰共同平移、反向相对位移、missing category、diffuse full-grid、
  object/region strata、环境类别排除与无效输入；focused evaluator tests 共 `78 passed`。
- Ruff format/check 与 ty 均通过。真实 instance IDs、同类别 instance-to-instance edges 及语言中的动态 left/right
  仍不可识别；start-frame sector view 暂缓，避免给当前 scalar similarity 添加重复信息。
- 实现与 focused tests 为 commit `3d51f40`；本记录完成后单独提交并推送实验分支。

### 问题与证据边界

本轮回答两个相关但不同的问题：第一，原始 ETP-R1 的 GRPO 为什么冻结大部分
policy、只更新导航相关模块，以及认知地图候选是否改变该契约；第二，现有结果中
GRPO 相对 DAgger 增益较小的原因。这里没有可运行的 GPU 反馈环，因此不把“训练复现”
伪装成诊断条件；反馈环改为可重复的静态契约清单、checkpoint/trainable-profile 测试
与既有同 population 结果核对。代码和配置能证明“实现了什么”，不能单独证明设计动机
或某个性能原因。后者只会标为假设，除非已有 matched 对照支持。

### 竞争解释（测试前排序）

以下排序在运行静态测试和核对完整结果前固定，避免看到单个数字后倒推故事：

1. **GRPO replay 的梯度边界阻断 map adaptation。** 当前 cognitive-map GRPO
   rollout 把 map tokens `detach()` 后存入 CPU buffer，update 只重放这些 tokens；
   `nav4` profile 又只更新四个 navigation modules。因此若这是主因，允许
   `graph_map_attention` 更新应出现正向信号；若还不足，则必须在 replay 中带梯度重算
   map tokens，才可能检验 `map_encoder`/predictor adaptation。
2. **强 DAgger anchor 与组内轨迹同质导致 GRPO advantage 信号偏弱。** 同一 episode
   的八条轨迹若 reward 方差接近零，代码会给全部 step 接近零的 normalized advantage。
   若这是主因，训练日志中的 group reward variance/zero-advantage rate 应与参数更新和
   held-out 增益相关，增加有效而非任意的探索应增强信号。
3. **episode outcome reward 与地图使用位置不对齐。** 全轨迹 reward 被广播给每个
   high-level action，没有 map-quality 或 map-dependent-decision credit。若这是主因，
   总体指标增量会小，但明确需要地图区分的 episode/decision 子集可能改善；直接加入
   raster reward 则可能优化 predictor proxy 而非导航，不能作为默认修复。
4. **DAgger 已经学习主要地图收益，GRPO 只剩效率/停止策略余量。** DAgger 对访问到的
   每个 state 都有 global-planner teacher label，并广泛更新 policy 与 map path；GRPO
   只能从最终 outcome 区分 sampled trajectories。若这是主因，GRPO 的变化应主要体现为
   steps/path length/stop behavior，而不是 SR 或 map representation 的明显跃升。
5. **cohort、checkpoint selection 或非 matched control 造成表观小增益。** DAgger 与
   GRPO 使用不相交的 `_90`/`_10` online splits，LLM cache 还可能限制 population；若这是
   主因，只有同 anchor、seed、schedule、selection rule、evaluator 和 denominator 的
   paired control 才能稳定复现差异。

### 原始 ETP-R1 的冻结范围：能证明与不能证明的部分

[原论文](https://arxiv.org/html/2512.20940)明确写明：online SFT 除 frozen visual
backbones 外训练全部模型参数，而 online RFT 只微调 DPFT 与 SAP head；它把 closed-loop
GRPO 的作用描述为在完整轨迹 outcome reward 下优化 high-level waypoint decisions。
本地原始 `GRPO-R1` 实现与论文描述一致：先冻结整个 policy，再启用
`global_encoder`、`graph_query_text`、`graph_attentioned_txt_embeds_transform`、
`global_sap_head`。前三者覆盖 navigation-time DPFT 的 graph/text interaction，最后一个
是 action-scoring SAP head；language encoder、panorama path、RGB/depth backbone、
waypoint predictor 均不更新。

因此可验证的回答是：**作者把 RFT 参数面限定在直接产生 high-level navigation logits
的 DPFT + SAP head，而把 perception、waypoint proposal 与前置 representation 当作已经
由 pretraining/DAgger 学好的固定基础。** 论文还报告这种范围下，开启 frozen-layer
dropout、sampling dropout 与单次 on-policy update 最好；这些 ablation 支持“冻结不等于
完全 deterministic，仍用 dropout 制造 group diversity”。但论文和官方 README 都没有
给出“为什么不 full-finetune”的独立 ablation，也没有比较全量参数、语言 encoder 或
panorama encoder 的 RFT。因此显存、稳定性、防遗忘等常见理由只能视为合理推测，不能
归因给作者。

### DAgger / GRPO 契约矩阵

| 维度 | DAgger（online SFT） | GRPO（online RFT） | Cognitive-map 差异 |
|---|---|---|---|
| environment observation | 每 step 的 12-view RGB-D、instruction、当前 pose 与在线 evolving topological graph | 同一 observation contract；每条 sampled trajectory 都闭环接收新 observation | cognitive map 是额外 episode-level input，不替换 RGB-D/graph；本轮候选在 DAgger→GRPO 不换 map source/key |
| model input / replay | language、panorama、graph、map encoding 在 rollout 中以当前模型计算并保留梯度 | sampling 时计算相同 forward；update 重算 navigation forward，但复用 detached instruction embeddings、graph/panorama-derived inputs 与 detached map tokens | 因而 `map_encoder`、Imagined predictor 和 upstream encoders 即使解冻也没有现成的 update 梯度路径；Try5 fusion 位于 replayed tokens 之后，可单独训练 |
| rollout distribution | `_90` split；每 step 以衰减概率 `p` 执行 global-planner teacher action，否则 sampled policy action；访问到的 state 始终用 teacher label 监督 | `_10` split；同一 episode reset 后 categorical sample `G=8` 条纯 policy trajectories；maintained launcher 在 sampling 时启用 dropout | PriorGT/LLM cache 只允许有完整 map artifact 的 episode；Imagined 不受 cache population 限制 |
| trainable parameters | 原始 ETP-R1：除 policy 内已冻结 visual backbones 外几乎全量；PriorGT/LLM 正常模式也训练 map encoder/fusion；Imagined 还训练 predictor | `nav4`：仅四个 DPFT/SAP navigation modules；maintained LLM-Grid Try5 launcher 使用 `nav4-fusion`，额外更新 `graph_map_attention`；map encoder/predictor 仍冻结 | current architecture 的 fusion 在 `nav4` 下冻结；Try5 的 `nav4-fusion` 是唯一已维护的 map-specific GRPO 扩展 |
| initialization / checkpoint | 从 architecture/source-matched pretrained checkpoint 开始；普通非 requeue run 不继承 optimizer | 从相同 candidate 的 DAgger checkpoint 加载 policy；KL reference policy 在加载后复制并冻结；普通新 GRPO run 新建 optimizer，requeue 才恢复 optimizer/scheduler | `require_complete_checkpoint=True` 目前由 LLM-Grid Try5 launcher 显式开启，防止新 map module 静默随机初始化 |
| objective | 每个 visited state 的 teacher-action cross entropy；Imagined 在 step 0 另有 GT grid BCE 与 trajectory-keypoint Smooth-L1；PriorGT/LLM 没有 finetuning map reconstruction loss | 同 episode 内 normalized outcome advantage；clipped probability-ratio policy loss + `beta=0.04` reference KL；一个 update epoch | R2R code reward 为 `SPL + success + (1-d_final/6)`；论文写 `SPL + success - d_final/6`，多出的常数 1 会被 group centering 消掉，不改变 advantage；没有 map-specific reward |
| action / credit | teacher label 对每个 step 提供局部 dense supervision；实际 rollout 逐渐转为 on-policy | 一个 trajectory reward 作为该 trajectory 全部 high-level steps 的相同 advantage | map 是否在某一步有用没有显式 credit，只能通过整条轨迹相对组内结果间接学习 |

不同 cognitive-map source 的 GRPO caller 也没有另起一套 optimizer：PriorGT 是基类；
Imagined 只 override map preparation，从 instruction 与 start metadata 在线预测 map；LLM-Boxes/
LLM-Grid 只 override cache population 和 map loading。三者最后都进入同一个 detached-token
replay 与 trainable profile。换言之，“GRPO 输入是否变化”的答案是：**相对该候选自己的
DAgger，语义输入契约不变；变化的是 dataset partition、rollout policy、supervision 与
update 的梯度边界。**

### Matched control 前的证据更新

`exp/grpo-map-adaptation-ablation` 的 `c3046b7` 提供目前唯一机制审计完整的
cognitive-map GRPO 结果。普通 LLM-Grid Try5 的 `nav4-fusion` 从同一个 DAgger
`iter28000` anchor 运行 500 iterations：240 个预期 tensor（`nav4` 234、fusion 6）
发生变化，map encoder 与其余 frozen tensors 均不变；optimizer state、scheduler、
fusion gradient 与 checkpoint delta 审计都通过。现有 TensorBoard artifact 进一步确认
10 个 50-iteration aggregate 点的 fusion gradient norm、overall gradient norm、policy
loss 与 KL 均非零。因此“训练完全没有 GRPO 信号”已被排除；但没有记录 episode-group
reward std 或 zero-advantage fraction，不能排除部分 episode 无有效相对信号。

在同一 1,839-episode denominator 上，固定 `iter500` 相对 DAgger 为 SR 不变、SPL
`+0.001299`、nDTW `+0.011953`、steps `-15.413268`、path length `-2.111228`。
training-SPL selected `iter450` 相对 DAgger 为 SR `-0.002719`、SPL `+0.002433`，
steps/path length 仍明显缩短。这最符合解释 4：当前 GRPO 主要改变效率/停止行为，
没有产生新的 success headroom。它也与解释 1 相容，因为 fusion 可适应而 map encoder
不能适应；但不能证明后者是瓶颈。

历史 `nav4` selected checkpoint 的 SPL 比本轮 `nav4-fusion` 低约 0.96 percentage
points，但 SR 高约 0.11 points；它不是同 hardware/commit/seed/schedule 的 matched
control。故当前结果只能证明 fusion profile **可训练且稳定**，不能证明“训练 fusion
优于冻结 fusion”，也不能用这次对比决定 map encoder replay。解释 3（reward credit）
尚无 map-dependent decision slice，解释 5（control confound）仍明确存在。

### Matched 实验后的竞争解释结论

后续 `nav4` matched control、rollout diagnostics 与 failure audit 已完成；完整数值和
artifact 见 [2026-08-08](2026-08-08.md#grpo-matched-navigation-配对分析)。
这里按原测试前排序逐项闭环：

| 测试前解释 | 后验状态 | 结论与边界 |
|---|---|---|
| 1. detached replay 阻断 map adaptation | 部分排除，upstream 未识别 | 训练 downstream `graph_map_attention` 未带来有效收益，反而使 SR/OSR 下降；因此“只需解冻 fusion”被排除。`map_encoder`/predictor 仍没有可微 replay，本实验没有直接测试它们，但 negative fusion gate 不支持继续扩展。 |
| 2. 强 DAgger 导致组内同质、zero advantage | 强烈排除为主因 | 10 个 aggregate 的 zero-reward-variance fraction 均为 `0`；每个 8-rollout group 平均有 `7.970–7.992` 个不同 reward 与 `7.969–7.991` 条不同 graph-node trajectory。四个 `nav4` block 也都有非零梯度和 checkpoint delta。 |
| 3. outcome reward 与 map-dependent decision credit 不对齐 | 相容但未验证 | 训练确实把同一个 trajectory advantage 广播到全部 high-level actions；fusion 出现更短轨迹、较高 nDTW，但 reachability、NE 与 collisions 变差。没有 alternative credit/reward 或预注册 map-dependent decision slice，不能把相关现象写成因果证明。 |
| 4. DAgger 已吸收主要地图收益，GRPO 只剩效率/停止余量 | 当前最受支持，但仍是描述性解释 | 原始 pipeline 的历史 DAgger→GRPO 为 `+2.23 pp SR/+2.99 pp OSR/+1.59 pp SPL`；LLM-Grid DAgger→matched `nav4` 约为 `+1.09/+2.72/+0.06 pp`。standard GRPO 仍提高 reachability/success，但几乎没有 SPL 增益；fusion 的 retained-success efficiency 又被 success loss 抵消。没有弱/强 DAgger anchor intervention，因此“DAgger saturation 是主因”尚未被单独操纵证明。 |
| 5. cohort/checkpoint/unmatched control 造成表观小增益 | 对 fusion 结论已基本排除；对跨 pipeline 比较仍未完全排除 | fixed `500−500` 与 training-SPL-selected `450−500` 都失败；全部 11 个 leave-one-scene-out 的 SR/OSR delta 仍为负。原始 pipeline 数值仍是历史 selected/unpaired 对比，当前 DAgger 也缺完整 per-episode artifact 和多 training seed。 |

因此目前回答是**部分因果闭环**：GRPO 有充分 optimization signal，当前 one-way
fusion 也不是缺失的增益来源；它在 matched 对比中以 reachability 换取轨迹紧凑性。
领先但未最终区分的解释是“强 DAgger 后剩余 headroom 小”与“trajectory-level credit
过粗”。最小判别实验应是冻结两个 DAgger anchor、在同一 episode cohort 各采样
`G=8` 而不更新参数，比较 best-of-eight reward headroom、greedy failure rescue rate
与 divergent action 的 teacher regret：若 LLM-Grid headroom 明显更小，支持 saturation；
若 headroom 相近但实际 GRPO 增益仍小，则优先指向 credit/optimization mismatch。

### 测试前建议与 no-go（保留为预注册）

按信息量/成本排序：

1. **下一次任何 GRPO run 都先补零成本 instrumentation**：每个 episode group 的
   reward std、distinct reward/trajectory count、zero-advantage episode fraction、action
   entropy，以及各 trainable block gradient norm。它不需要增加训练 arm，可直接检验
   解释 2；旧 TensorBoard 不能事后恢复这些量。
2. **只有 ordinary LLM-Grid 仍影响架构决策时，补一个 matched `nav4` control。** 必须
   使用 `c3046b7` run 的同一 DAgger SHA、seed 100、500-iteration schedule、dropout、
   population、checkpoint selection 和 evaluator；对 `nav4-fusion - nav4` 做 paired
   episode/scene-bootstrap 与 stop-error comparison。这个单 arm 是目前唯一仍有明确因果
   信息的 GRPO ablation，但不在 GPU 全满时排队，也不应扩展到多个 source。
3. **只在 matched fusion control 显示正向且仍存在 DAgger recovery gap 后**，才实现
   differentiable map-encoder replay：buffer 保存每条 trajectory 一份 raw map inputs；
   current/reference policy 分别重算 map tokens，reference 保持 `no_grad()`。这只适用于
   PriorGT/LLM 的 map encoder；要训练 Imagined predictor，还必须同时重算而非 detach
   instruction path，是另一个更大的 contract。
4. **先做既有 DAgger/GRPO 的 map-dependent episode slicing，再设计 reward。** 例如按
   map category/space ambiguity、instruction relational content、DAgger stop error 分层；
   如果没有预注册的可观测 subgroup signal，就停止“GRPO 与认知地图冲突”方向。

以下方向当前为 **NO-GO**：

- 不做盲目的 full-policy GRPO；论文没有该 ablation，现有 replay 对 upstream inputs
  已 detach，单纯 `requires_grad=True` 既不能实现目标又无法归因。
- 不把 raster IoU/map reconstruction 直接加到 GRPO reward；对预计算 LLM map 它是常数，
  对可训练 predictor 则改变为 predictor-quality 多目标，并可能引入 rollout 时不可用的 GT。
- 不为每个 PriorGT/Imagined/LLM source 重跑完整 GRPO。先由 source-matched DAgger 判断
  cognitive-map source 是否有 navigation value，再由一个 matched GRPO mechanism arm
  判断是否值得扩展。
- 不把 `c3046b7` 的历史 `nav4` comparison 写成因果结论，也不因固定 `iter500` 和
  selected `iter450` 得到不同 SR/SPL trade-off 而选择性报告单一 endpoint。

## 数据流与可识别的算子

- 审计对象是 cache key `llm-grid-r2r-rxr-r1p5-direction5-s2-tagfree-contract-v2-epoch-2`，目标 namespace 为 `gt.legacy.r1p5.direction5.v1`、scale 2。开发集只使用全部 778 个 R2R `val_seen` episode；4 个 schema-invalid 输出按 evaluator 既有 contract 计为空栅格，没有从 denominator 删除。
- `parse_grid_text` 严格校验固定顶层键、canonical category 与 50×50 cell 坐标。重复 category 名直接 validation error；同 category、同坐标的重复 cell record 只增加 `duplicate_record_count`，最终仍写同一 binary cell。不同 category 占据同一空间位置是合法的 category-aware overlap，不能去重。
- 778 个输出共有 185,082 条可解析 cell record，其中仅 7 条是同 category、同坐标重复（0.00378%）；因此所谓 exact-dedup 已经是 frozen no-op，不构成新的后处理基线。
- 当前输出没有 category confidence 或 cell confidence；`mentioned` 只有 boolean 自报值，而且正式指标故意用 instruction-derived mention partition。故无法定义可校准的 confidence threshold，凭空把 cell 数量当 confidence 会改变问题而非校准预测。
- evaluator 把所有正值二值化后评分；invalid prediction 变为空栅格。因而本轮可离线识别的候选只剩 instruction-mentioned category mask、按预测 category cell count 去除 singleton、以及按同 category 8-neighborhood support 去除孤立/弱支持 cell。

## 冻结的开发比较

在查看这些候选的 `val_unseen` 结果前，固定以下 operator：

1. `no-op`：保持 parser 输出不变；
2. `mentioned-only`：只保留由原 instruction extractor 命中的 object/region channels；
3. `category-ge-2`：只保留预测 cell 数至少为 2 的 channel；
4. `neighbor-ge-1/2`：一个预测 cell 的同 channel 8 邻域至少另有 1/2 个预测 cell 才保留。

接受门槛为：相对 no-op 同时不降低 episode-macro IoU、不降低 pooled recall，并提高 pooled F1。这个门槛避免用少量 precision 换 recall 后只挑 pooled IoU。开发结果如下；`P-IoU/P-F1/P-R` 均为 pooled，`M-IoU` 为 episode-macro：

| operator | P-IoU | P-F1 | P-R | M-IoU | 决策 |
|---|---:|---:|---:|---:|---|
| no-op | 0.161914 | 0.278702 | 0.303124 | 0.185729 | frozen baseline |
| mentioned-only | 0.069525 | 0.130011 | 0.087022 | 0.073052 | NO-GO：大量 route-relevant context 被删 |
| category-ge-2 | 0.161999 | 0.278829 | 0.302298 | 0.185660 | NO-GO：recall 与 macro IoU 均下降 |
| neighbor-ge-1 | 0.162282 | 0.279248 | 0.301092 | 0.185723 | NO-GO：recall 与 macro IoU 均下降 |
| neighbor-ge-2 | 0.163079 | 0.280426 | 0.292379 | 0.185446 | NO-GO：precision 换 recall，macro IoU 下降 |

最大 pooled IoU 变化只有 +0.001165，且违反门槛。继续搜索 neighborhood size、component size 或形态学 kernel 会变成对 `val_seen` 的高自由度调参；没有可信信号，停止 sweep，也不读取这些候选的 `val_unseen` 分数。

## `prediction ∪ evidence` 的既有结果

从四条件 common-population `episodes.csv` 重新按 cell counts 汇总，确保 prediction 与 union 在完全相同 cohort 上比较。对于真正 matched、instruction-conditioned oracle-evidence predictor，直接 union 明显提高 recall，但 precision 损失更大：

| split | prediction IoU/F1/P/R | prediction∪evidence IoU/F1/P/R |
|---|---|---|
| `val_seen`（769） | 0.3317 / 0.4982 / 0.4797 / 0.5182 | 0.2296 / 0.3734 / 0.2710 / 0.6002 |
| `val_unseen`（1,839） | 0.1796 / 0.3045 / 0.2716 / 0.3466 | 0.1579 / 0.2727 / 0.1885 / 0.4927 |

Within-scene/global 错配条件下 union 有时会改善很差的 prediction，但那只是把同一份低精度 oracle evidence 加回去，不能推导成通用 deployable operator。直接 union 也违背此前“必须由 instruction-conditioned predictor 筛选”的 observation-bounded evidence 结论。故保留现有 union 指标作诊断，不把它接入 prediction 或 navigation cache。

## 结论

- 本轮明确为 **no-code/no-go**：parser/evaluator 已覆盖唯一确定的 exact-dedup/no-op；其余可识别过滤器没有通过冻结门槛，confidence 又不存在。新增通用 postprocessor 或 evaluation harness 只会扩大 API 和调参面，没有证据收益。
- 若未来输出 contract 显式训练/calibrate category 或 cell confidence，才重新开放 train/`val_seen` calibration，并用 untouched `val_unseen` 做一次最终验证；在此之前不把 occupancy/support heuristic 命名为 confidence。

### 泄漏与推理协议

- 训练 cohort 只能由 `scene_id`、原始输入可见的 start height 和确定性 seed 选择；不能读取 target `level_idx`、grid support、轨迹相似度或 category overlap 来挑 context。当前 token/union 审计使用 cache boxes sidecar `level_idx` 保证共享 level-local frame，因此**不是可部署 selection**。start-height cohort 只在 train 上用该 sidecar 检查了纯度；真正的数据加载器及其他 split 仍需单独验证。
- 同一轨迹的三条英文标注会直接复述同一目标路线。它们可以作为 paraphrase control，但不能进入“不同轨迹带来环境信息”的 treatment。
- `K=3→2→1` 且最终按现有单指令输入评价，仍是标准 episode-independent predictor；它检验的是课程/正则化作用，不表示模型在 unseen scene 推理时获得了更多该房屋的信息。
- 若在评价时也读取同场景其他 episode 的指令，这属于 transductive scene-batched inference。它没有读取 target label，但使用了其他任务输入和目标描述，改变了 benchmark/deployment contract，必须单独命名和报告，不能与现有 LLM-Grid checkpoint 曲线直接混为一谈。

### 建议实验与停止条件

1. 最小主实验：matched `K=1` baseline 对比 `K=3→2→1` PRIMARY curriculum；先测试用户原始的 scene-only、不同轨迹 context，再将 start-height 分组作为预注册的 floor-aware 变体。最后阶段和评价保持 `K=1`，其 user prompt 与当前 inference contract 逐字一致，不带 `PRIMARY`/context header。
2. 必要控制：同轨迹 paraphrase、跨场景但长度匹配的随机 context、真实同场景不同轨迹。只有真实同场景显著优于两个控制，才支持“环境信息”解释。
3. 更稳健的替代方案：训练全程随机 context dropout（`K∈{1,2,3}`），再做短 `K=1` 收尾；它避免模型只适应固定三段输入，可与硬课程做等 token/step 对照。
4. 无 `PRIMARY` 仍只作为 `union-grid auxiliary pretraining → PRIMARY finetuning`；
   旧 K3 explicit-cell proxy 因 `66.51%` retention 停止，后续 U2 row-run
   representation 通过 `97.9176%` feasibility gate 后只重新开放最小 matched 实验。
5. PRIMARY 停止条件：在 `val_unseen` predictor-quality 的 category、raster 和 direction 指标上不优于跨场景 context control，或 input/context shuffle 不改变结果。
6. Union 停止条件：completion/sequence 大量超预算、union support 过密而接近完整楼层 inventory、单轨迹 finetuning 后没有超过等算力 PRIMARY，或方向元数据必须靠隐式/任意合并才能进入现有 candidate。

### 文献结论与候选排序

1. **DVEFormer（IROS 2025）**：dense 512-D text-aligned RGB-D embeddings 最自然支持 exact
   23 prompts，且报告 embedded real-time inference；科学优先级最高，但官方 checkpoint 没有明确
   reuse terms，当前不能加载。
2. **SFSS-MMSI（WACV 2024）**：Matterport spherical RGB-D domain match 最强；但既有审计已经
   证明官方 MP3D checkpoint、label order、depth convention 与 permission 无法闭合，只能作为从源码
   训练的结构参考。
3. **EMSAFormer（IJCNN 2023）**：维护活跃、Apache-2.0、支持 ScanNet，适合作为 exact-23 supervised
   pinhole baseline；released weights 仍需单独确认 permission。
4. **DFormerv2（CVPR 2025）**：现代 per-view RGB-D encoder 与 custom-dataset path 很匹配；但没有
   MP3D model，且 README 的 non-commercial 声明与 MIT LICENSE 冲突，artifact readiness 低于前两者。
5. **OpenScene（CVPR 2023）**：最有价值的是 teacher→observation-local sparse student 的训练范式，
   不是复用其 full-scene MP3D checkpoint。每个样本只构造当前 12 views 的 depth shell，推理后立即丢弃。

PixelCLIP、Trident 与 Open-Fusion 类方法更适合作为离线 pseudo-label teacher；OV3D、NeRF、3DGS 与
persistent mapping 方法通常假设 translated cameras 或长 trajectory。canonical 12 views 共用单一光心，
缺少其主要 parallax 信号，因此不作为首轮 deployable candidate。360BEV 仍仅是 task-level reference：
它替换 sealed geometric projection，且 conservative mapping 只有 11/23。

### 预提议的独立开发协议（尚未实现）

- supervision 可来自 train-split semantic pixels 或获准的 offline teacher，但禁止完整 scene reconstruction、
  instruction、goal、trajectory、persistent map 与 held-out labels。

- 首轮 ablation 固定为 RGB-only vs RGB-D、independent per-view vs local-shell fusion、supervised vs legal
  teacher distillation；先看 image-space、projected evidence、latency，再决定是否运行 navigation。

### HM3DSem audit 结论

- **Training/development supervision GO**：HM3DSem v0.2 的 216 个 annotated scenes 按官方
  `145 train / 36 val / 35 test` scene split 使用；Habitat-Sim 可在同一 pose/render config 下输出
  aligned RGB、metric depth 与 semantic instance IDs，因此能严格生成 canonical t=0 12-view samples。
- **Exact-23 object coverage GO**：用官方 raw string→MP40 mapping 做 exact join 后，
  `136,739/142,646` instances 可映射，剩余 `5,907` 保持 `ignore`；本项目 23 个 object channels
  全部有非零支持，共 `40,436` conservatively exact-mapped instances。mapping 必须在实验前冻结，
  不因 val output 增加 lexical alias。
- **Region supervision NO-GO**：HM3DSem region ID 只是空间 grouping；room types 是从所含 object
  推导的 heuristic proposals，不是 authoritative room annotations。它们既不能监督本项目 region channels，
  也不能进入 observation-only input，因为会暴露 off-camera contents。
- **Reusable checkpoint source NO-GO**：conference-first search 没有找到在 HM3DSem 上训练并发布的
  standalone semantic segmenter。CVPR 2023 baselines 与 IEVE 使用的是 SUN RGB-D/MP3D/COCO perception；
  HM3D 训练发生在 navigation/exploration/verifier 部分。MVPd 是 class-agnostic video-instance data/model
  precedent，也不是 exact-23 observation segmenter。
- **Compute/terms**：本地 RTX 3090 适合 bounded canonical rendering 与 small RGB/RGB-D model probe，
  不适合直接复现 6M-frame MVPd 或 eight-V100 video baselines。HM3D/HM3DSem 受 Matterport academic
  non-commercial EULA 约束；derived checkpoint 的 distribution 需另行 terms review，不能由 Habitat code
  的 MIT license 推断。
- **冻结 proposal（尚未实现）**：只用 HM3D train scenes 的 visible object pixels 学习，以 HM3D val
  scene-disjoint development；不需要用 HM3D test 做 MP3D model selection。之后只在 permitted MP3D/R2R
  train data adaptation，冻结 model/mapping/threshold 后创建 fresh sealed MP3D val-unseen cohort；先通过
  exact-23 projected-evidence gate，再决定 navigation integration。

`data/reference/hm3d-semantic-research-2026-08-07/README.md`。本轮保存 3 篇论文、5 个官方仓库；没有下载

### 诊断语义

- sampled action trajectory 使用 replay 中每步 action 对应的
  `gmap_vp_ids`，而非会随 graph 长度变化的 action index。
- sampling action entropy 直接由 replay 中已保存的 `probs` 计算；不再次
  forward、不采样、不改变 RNG。
- reward group 只纳入至少两个有效 reward 的 episode slot，与 advantage
  标准化的有效 group 定义一致。
- rollout 统计先在每个 rank、每个 update 内求均值，再沿用 trainer 现有
  `sum/count + all_reduce` 在 `log_every` cadence 求全局 rank-update mean；
  因固定为每 rank 4 env groups，reward/group 指标等价于完整 group 的等权
  平均。entropy 是 rank-update mean，不宣称为跨全 run 的逐 action 加权值。
- DDP 在最后一次 backward 已同步 gradient，随后记录每个 module 的 clipping
  前 norm；因此各 rank 数值应相同，现有全局 reduce 只做一致值平均。
- population identity 先以 `train_10` JSON source order 将 cache eligibility
  与该 suffix dataset 相交；传给
  `construct_envs(..., episodes_allowed=...)` 的就是生成 fingerprint 的同一
  1,068-episode 有序 list。environment construction 后另以
  `sum(number_of_episodes)` 做 count gate，不相等即显式失败。此 preflight
  直接读取 JSON，不调用 dataset constructor，因而不会消耗 Python RNG。
