## R8：p0 / gt_full 逐字节一致的原因（本地 CLI 执行，报告 `reports/R8_gt_full_swap_diagnosis.md`）

**结论：模型侧，而且是 encoder 层面的栅格盲。** 评测管线没有问题。

证据链：

1. 管线正常。gt_full 评测耗时 43 min，p0 为 12 min（R7 5000 与 R5 10k 均如此），说明 semantic 传感器和 refiner 路径确实在跑；dry-run 落盘的配置里 `eval_map_source: gt_full`；8-episode 追踪里 `swap changed=True active_before=100 active_after=201`，GT 栅格确实替换进了 `cognitive_map["grid"]`。
2. R7 iter 5000 的离线探针（patch 0011）：LLM 栅格、GT 栅格、全零栅格得到的 map tokens **完全相同**（tok_rel = 0.0000，d_gt = d_zero = 0.0000），而去掉地图后 logits 变化 d_none ≈ 1.22、argmax 翻转率 9%。即 fusion 有贡献，但贡献全部来自 metadata token（起点方向、起点位置、方向向量）和常量，栅格内容进不去。
3. R5 iter 10k 对照：tok_rel 0.47–0.81，d_gt 0.15–0.28，argmax 翻转率 3–6%；两次全量评测的逐 episode 文件 MD5 不同。R5 的栅格通道是"弱但活着"，R6 里写的"通道死了"应改为"弱"。

**对 R7 的影响。** R7 的前提是"学生带着预训练好的 map 路径进 DAgger"。现在看到 iter 5000 的 encoder 已经栅格盲，最可能的解释是 460000 预训练本身已经把栅格路径压死（LLM 栅格 IoU 只有 0.13，预训练学会忽略它是合理的收敛结果），R7 从第 0 步起就没有栅格通道可用。因此 R7 无法检验"map 通道活着"这一假设；它剩下的价值是 460000 骨干 + metadata token 与 R5 的 SR 对比。训练已近尾声，不必中止。

待验证：栅格盲是预训练带来的还是 DAgger 5000 步造成的。patch 0012 的 `map_encoder_stage_probe.py` 对 460000、387500、R7 5000、R5 10k、GT teacher 五个 checkpoint 逐层比较 GT/LLM/全零栅格的相对差异，并报告 spatial_tokenizer 的 ||W·x|| / ||b||；若 460000 已经 ≈ 0，则结论落在预训练。

工具修正：`map_sensitivity_probe.py` 的 `underscores_to_dashes` 改为构造参数（与仓库其他脚本一致），CLI 报告的 `--run-name` 不识别问题由此而来。

## R9：栅格信号在 encoder 哪一层消失（报告 `reports/R9_map_encoder_stage_probe.md`）

| checkpoint | spatial_tokenizer.weight 范数 | bias 范数 | ‖W·x‖/‖b‖ | output_norm rel(gt) |
|---|---:|---:|---:|---:|
| LLM-Grid 预训练 460000（R7 起点） | 0.0000 | inf | 0 | 0 |
| Prior-GT 预训练 387500（R5 起点） | 0.0000 | 55.18 | 0 | 0 |
| R7 DAgger 5000 | 0.0000 | inf | 0 | 0 |
| R5 DAgger 10000 | 17.16 | 0.072 | 39.6 | 0.64 |
| GT teacher DAgger 16000 | 17.85 | 0.075 | 84.7 | 0.78 |

**结论。** 栅格盲来自预训练，而且两条预训练线都一样：`spatial_tokenizer.weight` 为 0，偏置巨大（460000 的偏置大到 float32 范数溢出）。`category_projection` 一层 rel(gt) 仍是 0.97，到 `spatial_tokenizer` 一层就变成 0，信号在 10×10 卷积处消失。

三件事由此得到统一解释：

1. **R7 首次启动的 NaN**：巨大的 spatial_tokenizer 偏置在 fp16 下溢出成 inf，LayerNorm 再变 NaN。fp32 修复让它"能跑"，但跑的是一个栅格盲的 encoder。之前写的"51200 项累加溢出"是错的猜测，真正的溢出源是偏置。
2. **R7 的栅格通道训不活**：偏置巨大使 LayerNorm 的 1/std 把反传梯度压到 Adam 的 eps 以下，权重在 DAgger 5000 步后仍是 0。R7 从头到尾只是"460000 骨干 + metadata token"。
3. **以前所有 DAgger 都是从 CLIP 初始化训 encoder 的**：loader 缺陷让预训练的 map 张量被丢弃，反而躲开了这个死 encoder。R5 和 GT teacher 的权重范数 17–18、偏置 0.07，正是 kaiming 初始化加训练的样子。这也是 R5 的栅格通道"弱但活着"、teacher 的 map ablation 有 12–17 pp 效应的原因。

**对结论的修订。** "预训练训过 map 路径"（步 0 取证）只对 fusion 和 metadata 路径成立，栅格路径在预训练里从未起作用。R7 无法检验它的假设；它跑完后的 SR 只能解读为 460000 骨干 + metadata 的效果。

**未解之处**：预训练用的是同一个 `EmbeddingGridMapEncoder`（kaiming 初始化），默认 AdamW（lr 5e-5、wd 0.01）既不能把权重精确压到 0，也不能把偏置推到 1e18 量级。要看预训练中间 checkpoint 的轨迹才能定位（patch 0013 `map_encoder_weight_sweep.py`，任务书 R10）。在此之前不猜机制。
