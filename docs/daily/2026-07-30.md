# 2026-07-30

## P5.6：ESANet official CUDA publication 续

承接 `docs/daily/2026-07-29.md` 中已冻结的 P5.6 publisher、双 environment
authority、private runtime loader 与 fatal OOM 路径。commit `bed1a52` 后的
正式命令已通过 P5.3 replay、runtime loader、model construction 与 strict
checkpoint load，随后在 warmup 前的 official CUDA preflight 安全停止；
final/staging path 均未创建。

最小复现显示 container 内 `os.getpid()`/`NSpid` 为同一 local PID，但
`nvidia-smi --query-compute-apps` 在 CUDA context 存活时返回另一个 ancestor-
namespace PID，该 PID 随 child 退出而消失。frozen backend 正确要求 evidence
中的 self PID 等于 `os.getpid()`，因此不能直接接受 driver PID。

experiment runner 增加 strict stateful inspector：

- candidate CUDA context 创建前连续两次 raw snapshot 均必须没有 compute PID；
- backend begin/finish 各连续采样两次，均必须只有同一个 raw PID；
- begin 私下绑定该 ancestor-namespace PID，finish 必须保持同一 singleton；
- fork、pre-existing/empty/extra/drifted PID、GPU policy drift 或第三次调用均
  fail closed；
- 只有经 empty → stable-singleton transition 证明属于当前 process 的 raw PID
  被规范化为 constructor `os.getpid()`；GPU policy、UUID 与温度仍来自原始
  snapshot。

真实 dedicated-venv lifecycle smoke 已通过：CUDA context 创建前 GPU 4 idle，
begin/finish 均返回当前 local PID 与固定 GPU UUID；child 退出后 driver PID
消失。focused tests 为 23 passed，Ruff、ty、diff check 均通过；独立 review
为 ACCEPT。P5.3/P5.4 core、sealed inputs 与 upstream source 均未修改。

首次正式重跑仍在 inspector idle gate 停止。分阶段 probe 随后定位了精确边界：
imports、venv/assets/environment/Git、`torch.cuda.device_count()` 与 fresh P5.3
结束后，`torch.cuda.is_initialized()` 均为 false 且 GPU 4 raw PID set 为空；
`iter_validated_raw_observations` 返回后 PyTorch 仍未初始化，但出现一个
ancestor-namespace raw PID，并稳定贯穿 source/preprocessing/commitment。
因此这是 validated raw reader 创建的当前 process 非 PyTorch CUDA context，
不是外部占用。idle inspector 现固定在 P5.3 之后、raw reader 之前，恰好封住
实际 empty → singleton ownership transition。

修复后的正式 GPU run 已完成 20 次 warmup 与两轮各 50 个 observation 的
measured inference；全程 GPU 4 只有已绑定的 current-process context，显存约
1.14 GiB。artifact 构造完成后、publication 之前，post-run source
re-attestation 错误拒绝了合法的 `src.models` namespace，因而 final/staging
path 均未创建，也未输出或检查 semantic endpoint。根因是 verifier 将所有
`src.*` namespace 都错误地与 `source/ESANet/src` 根目录比较；而 upstream
刻意没有 `src/models/__init__.py`，Python 的正确 origin 是
`source/ESANet/src/models`。修复保持 single-origin fail-closed 约束，并按完整
module name 推导唯一允许目录；同时新增合法 nested namespace 与 competing
nested namespace regression。

commit `d330f9c` 后的正式重跑再次完成全部 inference，post-run source 与 asset
re-attestation 均通过，并创建了 owned staging tree。随后 isolated
fresh-process publication validator 运行约 90 秒后返回 nonzero；hardened parent
按设计只报告 generic failure，自动删除 staging，final path 仍未创建。该失败
发生在 atomic rename 之前；没有 semantic endpoint 被输出或检查。下一步先在
不放宽 validator、不中断 no-overwrite 语义的前提下，取得 child failure 的
非 semantic 诊断，再决定是否重跑。

最小 held-FD probe 已确认根因：publication child 以
`/proc/self/fd/<interpreter>` 启动时，CPython 无法从 executable path 发现
相邻 `pyvenv.cfg`，因此错误落到 base environment（244 distributions，
environment hash `1133c110…`），而不是 pinned candidate overlay（247
distributions，hash `a0342fd…`）。`BenchmarkEnvironmentAttestation` 因而正确
fail closed。修复没有改弱 environment gate：runtime authority 现在额外绑定
精确 `lib/pythonX.Y/site-packages` directory 的 fingerprint，通过
`O_NOFOLLOW` held descriptor 传入 child，并为 nested P5.3 subprocess 重写成
`/proc/<child-pid>/fd/<site-fd>`；child 结束后同时复核 held 与 fresh path
identity。regression 证明 copied venv 的 normal-path 与 held-FD environment
hash 完全一致，并覆盖 nested child、symlink escape、JSON tamper 与 final
directory drift。package/publisher 全量 234 tests、Ruff、ty、diff check 均通过；
独立 security review 为 ACCEPT。

commit `fb61f8a` 后重跑仍在 fresh child 内 fail closed。direct environment
probe 定位到第二层隔离问题：publication child 的 candidate overlay
`PYTHONPATH` 被 nested P5.3 base-interpreter validator 继承，使其 environment
hash 变为 `2a02828d…`，而不是 pinned P5.3 hash `35be66f5…`。这两个 validator
本来就有不同 environment authority。修复策略是只用 held site-packages 完成
publication module import；import 后保留当前 process 已解析的 `sys.path`，
但将 environment 中 `PYTHONPATH` 还原为 repository-only，再启动 nested P5.3。
因此 outer candidate validation 继续使用 pinned overlay，P5.3 则恢复 sealed
base environment，二者都不放宽 hash gate。

commit `c50d614` 后的正式 no-overwrite run 成功完成 atomic publication 与第二次
byte-identical fresh validation。endpoint-free record 为 validation `PASS`、
candidate `FAIL`，50 observations、53 files、157,592,831 bytes；manifest
SHA-256 为 `030c2723…`，tree SHA-256 为 `62a567c5…`，producer commit
`c50d6144543f54b25404a0eaad2494def85374c0`。final path 已发布，staging
不存在。

object/domain/mapping coverage 失败，而非整体几何完全失配。P5.7 independent
audit 尚在运行。
