## P5.6：ESANet official CUDA publication 续

承接 `docs/daily/2026-07-29.md` 中已冻结的 P5.6 publisher、双 environment
authority、private runtime loader 与 fatal OOM 路径。commit `bed1a52` 后的
正式命令已通过 P5.3 replay、runtime loader、model construction 与 strict
checkpoint load，随后在 warmup 前的 official CUDA preflight 安全停止；
final/staging path 均未创建。

最小复现显示 container 内 `os.getpid()`/`NSpid` 为同一 local PID，但
`nvidia-smi --query-compute-apps` 在 CUDA context 存活时返回另一个 ancestor-
namespace PID，该 PID 随 child 退出而消失。frozen backend 正确要求 evidence
中的 self PID 等于 `os.getpid()`，因此不能直接接受 driver PID。

experiment runner 增加 strict stateful inspector：

- candidate CUDA context 创建前连续两次 raw snapshot 均必须没有 compute PID；
- backend begin/finish 各连续采样两次，均必须只有同一个 raw PID；
- begin 私下绑定该 ancestor-namespace PID，finish 必须保持同一 singleton；
- fork、pre-existing/empty/extra/drifted PID、GPU policy drift 或第三次调用均
  fail closed；
- 只有经 empty → stable-singleton transition 证明属于当前 process 的 raw PID
  被规范化为 constructor `os.getpid()`；GPU policy、UUID 与温度仍来自原始
  snapshot。

真实 dedicated-venv lifecycle smoke 已通过：CUDA context 创建前 GPU 4 idle，
begin/finish 均返回当前 local PID 与固定 GPU UUID；child 退出后 driver PID
消失。focused tests 为 23 passed，Ruff、ty、diff check 均通过；独立 review
为 ACCEPT。P5.3/P5.4 core、sealed inputs 与 upstream source 均未修改。

### DFormerv2-S asset 与 depth static audit

用户已明确授权 exact DFormerv2-S NYUv2 checkpoint 的内部分析使用。官方
checkpoint 实际为 107,037,174 bytes（约 102.08 MiB），SHA-256 为
`2efc0267…f47e2`；restricted CPU `weights_only=True` load 得到唯一顶层
`state_dict`，内含 802 tensors、26,692,392 elements、106,769,608 tensor
bytes，所有 floating tensors finite。官方 source 已 detached 到
`814799bb1f39eb380f72fdea1cd591f2cc27b6aa`；source + checkpoint 当前占约
117 MiB，均位于 ignored experiment storage。

weight permission blocker 已由 narrow risk exception 解除，但 depth adapter
blocker 仍成立。pinned source 的完整有效输入是：`.npy` depth 经
`plt.imsave(..., cmap="Greys_r")` 写为 uint8 PNG，OpenCV grayscale decode
后复制三通道，再算 `(g / 255 - 0.48) / 0.28`，backbone 只消费第 0 通道。
README 没有冻结 Matplotlib 版本、raw `.npy` units、invalid sentinel 或 paired
raw/PNG 样本；default `imsave` 还会逐图 min/max normalize，并经过非线性
colormap。因此不能用 `depth / 10` 冒充 official preprocessing。DFormerv2-S
保持 blocked，直到能用 official paired `.npy`/PNG 做 byte-level label-free
复核并冻结 invalid/degenerate-range 语义。

进一步检查 upstream 95 个 commit trees，未发现隐藏的 NYUv2 converter、
preparation script 或 raw/PNG pair；历史中也从未 pin Matplotlib。官方发布的
DFormer prepared `NYUDepthv2.zip` 为 275,116,140 bytes（262.37 MiB），
SHA-256 `42bc22c2…502a`，但只含 prepared PNG/RGB/labels，不含原 `.npy`。
NYUv2 官方 `nyu_depth_v2_labeled.mat` 为 2,972,037,809 bytes
（2.768 GiB），同时含 inpainted metric `depths` 与 projected/corrected
`rawDepths`；DFormer 未说明其 `.npy` 来自哪一个。prepared archive + official
MAT 共约 3.03 GiB，理论上可通过 RGB/index label-free matching 同时测试两个
depth variables，但即使成功仍不能恢复未记录的 producer Matplotlib version
或证明原 `.npy` invalid semantics。

因此当前不下载 dataset：262 MiB archive 单独不能解除 blocker，约 3.03 GiB
重建路径也不是确定性解。最小充分证据其实只需 author-provided 一组 raw
depth array + matching prepared PNG + RGB/index + Matplotlib version，预计
小于 3 MiB。下一优先级应是取得这组 provenance；在此之前不编写 DFormerv2
adapter、不运行 checkpoint inference，也不接触 sealed semantic endpoints。
