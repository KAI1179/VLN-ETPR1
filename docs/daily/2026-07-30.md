最小复现显示 container 内 `os.getpid()`/`NSpid` 为同一 local PID，但
`nvidia-smi --query-compute-apps` 在 CUDA context 存活时返回另一个 ancestor-
namespace PID，该 PID 随 child 退出而消失。frozen backend 正确要求 evidence
中的 self PID 等于 `os.getpid()`，因此不能直接接受 driver PID。

experiment runner 增加 strict stateful inspector：

- candidate CUDA context 创建前连续两次 raw snapshot 均必须没有 compute PID；
- backend begin/finish 各连续采样两次，均必须只有同一个 raw PID；
- begin 私下绑定该 ancestor-namespace PID，finish 必须保持同一 singleton；
- fork、pre-existing/empty/extra/drifted PID、GPU policy drift 或第三次调用均
  fail closed；
- 只有经 empty → stable-singleton transition 证明属于当前 process 的 raw PID
  被规范化为 constructor `os.getpid()`；GPU policy、UUID 与温度仍来自原始
  snapshot。

真实 dedicated-venv lifecycle smoke 已通过：CUDA context 创建前 GPU 4 idle，
begin/finish 均返回当前 local PID 与固定 GPU UUID；child 退出后 driver PID
消失。focused tests 为 23 passed，Ruff、ty、diff check 均通过；独立 review
