## 双地图交互方案第二次收敛

### 目标

根据讨论修订
[`upload_files/05_基于现有编码器的双地图交互方案.md`](../../upload_files/05_基于现有编码器的双地图交互方案.md)，进一步去除不可靠的 graph-grid 绝对坐标假设，并明确视觉语义与偏航监督。

### 结论

- 新架构只借鉴 Try5 的 map-to-graph attention 形式，不继承 Try5 fusion 权重；Try5
  保留为静态单向融合消融。
- graph-to-map 使用无绝对坐标的全局 attention：全部 visited 节点提供历史上下文，
  新观测触发整张 map-token 状态更新。
- 未来地图允许随已访问证据改变；保留不可变 `Z0`，递归学习全图残差，并用无新
  证据恒等、写门预算及 token 多样性约束防止状态坍塌。
- 删除“未见想象/视觉支持/认知冲突/视觉新增”四分类 head。无坐标对应时无法可靠
  构造逐格来源标签，该任务也不是导航闭环必需项。
- `VisualEvidenceHead` 保留为当前 panorama 的 37 类语义辅助任务。训练标签需由
  Habitat/MP3D Semantic + Depth 离线生成；当前 `data/` 下未发现可直接使用的逐
  viewpoint cache。验证与推理仍只输入 RGB-D。
- 偏航时 phase/remaining target 设为 `None` 并 mask；另监督 `off-route` 状态和
  每个 ghost 的 recovery 标签。recovery 表示候选能使 agent 明显接近 GT reference
  path，不能直接等同于当前 SPL teacher action。

### 尚未验证

- 全局更新能否在不使用 graph-grid 硬对齐时学习稳定的未来地图修订；
- 逐-viewpoint 37 类语义监督的生成成本、类别覆盖率和标签噪声；
- `3 m` off-route 阈值与 `0.25 m` recovery 改善阈值是否适合 R2R DAgger。

## 双地图在线交互实现

### 实现

- 新增 `online_fusion` 架构：visited 图节点无坐标地全局更新 100 个空间地图
  token；更新状态跨 DAgger 时间步保存；所有 ghost 从更新地图读取长时程信息。
- 新增 37 类视觉证据、`(37,100,100)` 稠密地图、五段进程、
  on/off-route/finished、remaining、recovery 与 ghost 排序监督；未引入 JSON 或
  在线 LLM。
- 预训练对 expert prefix 按访问顺序展开同一递归更新；DAgger 为并行环境同步维护
  地图状态、已消费 viewpoint 和路径进度，并在环境 pause 时同步裁剪。
- 参数组按方案固定前端 encoder；新交互模块为 `1× LR`，既有后端为
  `0.1× LR`。DAgger 强制完整加载本方案预训练权重。
- 新增本地 GPU 6、7 的预训练和 DAgger 启动脚本，以及训练期 panorama 语义
  标签生成器。

## OnlineFusion 监督核对

- 新增 [`06_视觉语义缓存与损失监督核对.md`](../../upload_files/06_视觉语义缓存与损失监督核对.md)，按代码核对缓存生成、5 组辅助损失及进度标签。
- 默认全量缓存应覆盖 90 个 scan 的 10,567 个有效 viewpoint；它只为离线预训练提供 37 类 panorama 语义 GT，DAgger 改为 simulator 在线生成同类 target。
- `state` 是无 GT 正则；grid/visual 有训练 GT；progress 与 ghost 使用 GT/expert 派生标签。预训练没有 off-route/recovery 样本，相关监督只来自 DAgger。
- 当前 phase/remaining 是 GT path index 比例，只能解释为粗粒度路线进度；recovery 是离轨时的逐 ghost 候选标签，不能与 off-route 状态等同。

## VisualEvidenceHead 冻结与辅助损失复核

- 采纳预训练专用视觉语义监督：预训练以 `1× LR` 训练 `VisualEvidenceHead`；DAgger 严格加载后冻结该 head、设 `visual loss=0`，不再创建 Semantic sensors。固定语义输出仍进入地图更新，`visual_category_projection` 继续训练。
- `L_state` 是累计地图残差、平均写门和 token 多样性的无 GT 正则；“写门预算”更准确地说是写门惩罚。
- `phase` 只是 `remaining` 的五档量化，建议从 progress 中删除；`recovery` 属于候选动作监督，建议与 progress 拆开。该简化尚未实施。
- DAgger 的进度是连续位置投影到单调最近 GT 点后的索引比例；预训练使用拓扑 viewpoint 索引，两阶段存在轻微定义差异。详见 [`07_状态进度与Ghost损失说明.md`](../../upload_files/07_状态进度与Ghost损失说明.md)。
