# 2026-08-13

## 双地图交互方案第二次收敛

### 目标

根据讨论修订
[`upload_files/05_基于现有编码器的双地图交互方案.md`](../../upload_files/05_基于现有编码器的双地图交互方案.md)，进一步去除不可靠的 graph-grid 绝对坐标假设，并明确视觉语义与偏航监督。

### 结论

- 新架构只借鉴 Try5 的 map-to-graph attention 形式，不继承 Try5 fusion 权重；Try5
  保留为静态单向融合消融。
- graph-to-map 使用无绝对坐标的全局 attention：全部 visited 节点提供历史上下文，
  新观测触发整张 map-token 状态更新。
- 未来地图允许随已访问证据改变；保留不可变 `Z0`，递归学习全图残差，并用无新
  证据恒等、写门预算及 token 多样性约束防止状态坍塌。
- 删除“未见想象/视觉支持/认知冲突/视觉新增”四分类 head。无坐标对应时无法可靠
  构造逐格来源标签，该任务也不是导航闭环必需项。
- `VisualEvidenceHead` 保留为当前 panorama 的 37 类语义辅助任务。训练标签需由
  Habitat/MP3D Semantic + Depth 离线生成；当前 `data/` 下未发现可直接使用的逐
  viewpoint cache。验证与推理仍只输入 RGB-D。
- 偏航时 phase/remaining target 设为 `None` 并 mask；另监督 `off-route` 状态和
  每个 ghost 的 recovery 标签。recovery 表示候选能使 agent 明显接近 GT reference
  path，不能直接等同于当前 SPL teacher action。

### 尚未验证

- 全局更新能否在不使用 graph-grid 硬对齐时学习稳定的未来地图修订；
- 逐-viewpoint 37 类语义监督的生成成本、类别覆盖率和标签噪声；
- `3 m` off-route 阈值与 `0.25 m` recovery 改善阈值是否适合 R2R DAgger。
